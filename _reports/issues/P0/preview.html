Rewrite the Bun guide's instrumentation step around @sentry/bun/plugin

The Bun guide at guides/bun/index.mdx:94 and :106 tells the user to run bun --preload ./instrument.js app.js, and the alert at :96-100 states that Sentry's auto-instrumentation does not work with bundled code and that bundling requires manual instrumentation. @sentry/bun/plugin is not named anywhere on the page, and logs is used as an onboarding block at :182 but is missing from the options at :20-22.

What was observed on bun 1.4.0: a bundle built with Bun.build({ plugins: [sentryBunPlugin()] }) from @sentry/bun/plugin records library and framework spans, while running the same app unbundled with bun run records none. packages/bun/src/plugin.ts:14 states the plugin is build-only. The unbundled diagnostic message is printed only with debug: true.

What to change:

  • Keep the --preload step, described as what guarantees init order.
  • Add a "Build with the Sentry plugin" step showing Bun.build({ entrypoints: [...], plugins: [sentryBunPlugin()] }) imported from @sentry/bun/plugin.
  • Replace the alert at :96-100 with a plain statement: library and framework instrumentation requires a build with the plugin; bun run on unbundled source records manual spans plus Bun.serve, node:http and fetch spans.
  • Add logs to the onboarding options at :20-22, or remove the block at :182.

Stop recommending denoCronIntegration() on the Deno crons page

platform-includes/crons/setup/javascript.deno.mdx:1 heads its first section "Automatic Check-Ins (Recommended)" and :12 tells the reader to pass Sentry.denoCronIntegration() to Sentry.init.

That call crashes startup on current Deno. packages/deno/src/integrations/deno-cron.ts:23 assigns Deno.cron = new Proxy(Deno.cron, ...), but on Deno 2.9.0 Deno.cron is a getter-only property, so Sentry.init throws TypeError: Cannot set property cron of #<Object> which has only a getter. This reproduced in four separate audit runs. Line 18 returns silently when Deno.cron is missing, so without --unstable-cron the integration is a no-op. It is also not in the default set at packages/deno/src/sdk.ts:31-49, contrary to its JSDoc at deno-cron.ts:64.

What to change

  • Remove the "Recommended" framing and the denoCronIntegration() snippet, or label the integration as broken on Deno 2.9.
  • Lead with the Sentry.withMonitor / Sentry.captureCheckIn sections already on the page.
  • State that Deno.cron needs --unstable-cron.

Three Bun OpenTelemetry includes are written against a package and APIs that no longer exist. platform-includes/performance/opentelemetry-setup/javascript.bun.mdx:5 and :48 import SentryContextManager, validateOpenTelemetrySetup from @sentry/node-core; error-monitoring-only/javascript.bun.mdx:3 and with-custom-sampler/javascript.bun.mdx:3 do the same. javascript.bun.mdx:12 and :55 pass skipOpenTelemetrySetup: true, and error-monitoring-only/javascript.bun.mdx:30 calls provider.addSpanProcessor(...).
