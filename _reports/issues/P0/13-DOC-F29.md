`docs/platforms/javascript/guides/sveltekit/manual-setup__v10.7.0.mdx:21-35` holds the "Notes on SvelteKit adapter compatibility" section, whose "Currently not supported" bullet at `:30-31` says non-Node server runtimes are not yet supported, while `:28` lists adapter-node as fully supported. That reads as excluding Deno, and the current `manual-setup.mdx` has no adapter-and-runtime section at all. `grep -rni deno` over the SvelteKit guide returns nothing.

Verified on SvelteKit with adapter-node and `@sentry/sveltekit` 10.67.0 on Deno 2.9.0: build with `vite build` under Node, using `sentrySvelteKit()` imported from `@sentry/sveltekit/vite`, then start the adapter output with `HOST=<host> PORT=<port> deno run --allow-net --allow-env --allow-read --allow-sys --allow-ffi build/index.js`. For outgoing requests, register `fetchIntegration` from `@sentry/cloudflare`, already installed as a dependency of `@sentry/sveltekit`, in `src/hooks.server.js`, gated on Deno so Node builds are not double-instrumented.

Works today:

- Errors from `+server.js` handlers, mechanism `auto.function.sveltekit.handle_error`.
- `GET /users/[id]` with source `route`.
- Per-request isolation and incoming trace continuation.
- `http.client` spans plus `sentry-trace`/`baggage`, with `fetchIntegration()`.
- Database spans for the `mysql` driver, with no extra flags.
- Logs.

Known limits:

- Without `fetchIntegration()`, neither a global `fetch()` nor SvelteKit's `event.fetch` produces an `http.client` span or carries trace headers on Deno.
- `mysql2` cannot be loaded once the SDK is initialized: Deno compiles `require('*.json')` as JavaScript while a module hook is registered (denoland/deno#36240), and the route fails with `SyntaxError: Unexpected token ':'`.

What to change:

- Fix `manual-setup__v10.7.0.mdx:21-35` to name Deno with adapter-node as supported.
- Restore an adapter-and-runtime section in `manual-setup.mdx` and add a Deno framework page with the run command and the `fetchIntegration` snippet.
