Nothing covers this combination: `grep -rni express docs/platforms/javascript/guides/deno/` and `grep -rni deno docs/platforms/javascript/guides/express/` both return zero hits. `docs/platforms/javascript/guides/express/index.mdx:4-5` declares `sdk: sentry.javascript.node` with `fallbackGuide: javascript.node`, and `:12` is a bare `<PlatformContent includePath="getting-started-node" />`, so the whole guide assumes `@sentry/node` on Node. `docs/platforms/javascript/guides/deno/index.mdx:1-232` names no framework.

Verified on Express 5.2.1 and Deno 2.9.0: `npm install express` plus `@sentry/deno` into a real on-disk `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}`, an `instrument.ts` that calls `Sentry.init({ dsn, tracesSampleRate: 1.0 })` from `@sentry/deno` and is the first import of the app file, then `deno run --allow-net --allow-env --allow-read --allow-sys app.ts`.

Works today:

- Incoming requests produce `http.server` transactions.
- Per-request isolation across concurrent requests, with distinct trace ids.
- Incoming `sentry-trace`/`baggage` continuation.
- Logs.

Known limits:

- Transaction names stay unparameterized: `GET /users/42` with source `url`, and no handler spans.
- Errors thrown in route handlers are swallowed by Express and are not captured.
- Database spans are not produced.
- `import "@sentry/deno/import"`, which is what would add route names, handler spans, error capture and database spans, cannot be used with Express on Deno 2.9: registering any module load hook makes `require('*.json')` compile as JavaScript (denoland/deno#36240) and Express fails at import.
- Outgoing `fetch()` is not instrumented; `node:http`/`node:https` requests are.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/express.mdx` with the install, `deno.json`, init placement, run command and the limits above.
- Add a shared "Outgoing fetch requests" note to `guides/deno/index.mdx`.
