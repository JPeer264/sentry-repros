Following the "Apply Instrumentation to Your App" step at `guides/bun/index.mdx:82-105` as written, `bun --preload ./instrument.ts app.ts` (the command at `:100`) with `debug: true` prints `No available Node API to register diagnostics-channel injection hooks; skipping.` at startup and `[Sentry] No diagnostics-channel injection detected. Channel-based integrations will not record spans. Make sure the diagnostics channels are injected via the runtime --import hook or a bundler plugin before the instrumented modules load.` after the first request. Neither line is mentioned on the Bun guide or the troubleshooting pages, and the guide names no bundler plugin (DOC-B1).

Observed on `develop` with bun 1.4.2: the warnings are correct. The first comes from `packages/server-runtime-injection/src/register.ts:160` (`:201` at develop head), the second from `packages/server-utils/src/orchestrion/detect.ts:38-42`; both go through `debug.warn`, so they print only with `debug: true`. Runtime instrumentation (`Bun.serve`, fetch, errors, logs) works on the documented path, and library instrumentation needs the `Bun.build` with `sentryBunPlugin()`. A reader who sees the warning has no page that says which of the two it refers to.

The second line is not tied to the unbundled path. On a plugin build started with `--preload` (variant `graphql-bundle-preload`, 2026-09-10, `graphql` 16.14.2 as a channel-instrumented library that needs no server) it prints at `app-graphql-bundle-preload.log:101` while the bundled instrumentation records `GraphQL parse`, `GraphQL validate` and `GraphQL query` spans under the request: `detectOrchestrionSetup()` runs inside `init()`, and the bundle's entry banner sets the bundler marker only when the bundle evaluates, after the preload. With `import "./instrument"` as the first line of the bundled entry and no `--preload` (variant `graphql-bundle-inline`) the line does not print. On the documented unbundled path the warning stays correct: the same app under `--preload` without a build (variant `graphql-preload`) printed it and recorded no GraphQL span.

What to change:

- Quote both lines on the Bun guide next to the run command at `:100`, say that they print only with `debug: true` and that runtime instrumentation is unaffected, and link the plugin build step from DOC-B1 as the fix for library spans. Say nothing about the plugin-build case, where the second line is a false warning until the SDK defers the check.
