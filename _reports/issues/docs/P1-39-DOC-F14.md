Verified on React Router 8 framework mode with a custom Express server and `@sentry/react-router` 10.67.0 on Bun 1.4.0: rewrite `app/entry.server.tsx` to use `renderToReadableStream` with `Sentry.wrapSentryHandleRequest(handler)` and `export const handleError = Sentry.createSentryHandleError({ logErrors: true })`, because Bun resolves `react-dom/server` to a build that has no `renderToPipeableStream`. Install `@sentry/bun` at the same version and pass `integrations: [fetchIntegration(), bunHttpServerIntegration()]` from it to the `Sentry.init` in the instrumentation file imported as the very first line of `server.js`, and import the database driver at startup.

Works today:

- Unhandled loader and action errors
- `http.server` spans named `GET /users/:id` with source `route`
- Per-request isolation, one trace per request
- Incoming `sentry-trace`/`baggage` continuation
- Outgoing `fetch` spans with propagation headers
- `mysql2` database spans
- `Sentry.logger` log envelopes

Known limits:

- Without `bunHttpServerIntegration()` the server SDK is inert on Bun: only errors and logs arrive, every request shares one scope and one trace, and child spans are dropped.
- `Sentry.createSentryHandleRequest({ renderToPipeableStream, ... })`, the wiring the guide shows, cannot be used on Bun.
- Browser-side capture was not exercised.
