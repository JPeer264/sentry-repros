`platform-includes/performance/enable-tracing/javascript.bun.mdx:1`, `javascript.deno.mdx:1` and `javascript.cloudflare.mdx:1` each read "Tracing is enabled by default in the Sentry <Runtime> SDK." The guides for those runtimes, and `platform-includes/performance/enable-automatic-instrumentation/javascript.bun.mdx:1` and `javascript.cloudflare.mdx:1`, tell the user to set `tracesSampleRate` or `tracesSampler`.

What was observed: `hasSpansEnabled` in `packages/core/src/utils/hasSpansEnabled.ts:23-36` records spans only when `tracesSampleRate` or `tracesSampler` is set, on every runtime. On Bun there is a second gate on top of it: `getPerformanceIntegrations` in `packages/bun/src/sdk.ts:38-44` returns no performance integrations while `hasSpansEnabled` is false. The Deno and Cloudflare SDKs have no such gate and always install the tracing integrations, so the general reason the sentence is wrong is the sampling option, not the integration set.

What to change:

- Replace the first sentence in all three includes with a statement that tracing is enabled by setting `tracesSampleRate` or `tracesSampler` in `Sentry.init`, and that no spans are recorded when neither is set.
- Keep the wording consistent with the `enable-automatic-instrumentation` includes for Bun and Cloudflare, which already require the option. There is no Deno variant of that include, so Deno falls back to `javascript.mdx`.
