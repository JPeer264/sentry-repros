Oak is absent from the docs entirely. `grep -ril "oak" docs/platforms/javascript/ platform-includes/` returns nothing, there is no Oak guide on any runtime, `docs/platforms/javascript/guides/cloudflare/frameworks/` contains only astro, hono, the two hydrogen pages, index, nextjs, nuxt, remix, sveltekit and tanstack-start, and the framework list at `docs/platforms/javascript/guides/cloudflare/index.mdx:16-23` omits Oak.

Verified on the develop line: Oak 17.2.0 on workerd with `compatibility_date: "2026-05-01"` and `compatibility_flags: ["nodejs_compat"]`. Oak's current line ships only to JSR, so install it through the JSR npm bridge (`@jsr:registry=https://npm.jsr.io` in `.npmrc`, then `npm install '@oak/oak@npm:@jsr/oak__oak@17.2.0'`); the plain npm package, `@oakserver/oak`, stops at 14.1.0. Install `@sentry/server-utils` explicitly alongside `@sentry/cloudflare`, in the same install command: without it the wrangler build fails to resolve `@sentry/server-utils/no-diagnostic-channels`. Oak's `Application.fetch` is already a Workers fetch handler, so no adapter is needed and `withSentry` is the whole wiring: `export default Sentry.withSentry((env) => ({ dsn: env.SENTRY_DSN, tracesSampleRate: 1.0 }), { fetch: (request, env, ctx) => app.fetch(request, env, ctx) })`. Run with `npx wrangler dev`; no bundler plugin is required.

Works today:

- Unhandled errors (Oak rethrows rather than swallowing), per-request isolation, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans from a `mysql` query under plain `wrangler dev`, `Sentry.logger` logs.

Known limits:

- There is no Sentry Oak integration, so the request span is named from the raw URL under `traceLifecycle: 'static'` and from the HTTP method alone under the default `'stream'`, never from the matched route pattern. One Oak middleware, given below, restores parameterized names with source `route` in both lifecycles.
- The server span is reported with status `ok` even when the handler threw.
- `mysql` 2.x works with no configuration; `mysql2` emits spans but its query fails on workerd unless you pass `disableEval: true` in the connection options, which this cell did not exercise.

What to change:

- Add `docs/platforms/javascript/guides/cloudflare/frameworks/oak.mdx` with the JSR install, the wrangler config, the `withSentry` entry above, and a Works/limits summary matching the two bullet lists here.
- Add Oak to the framework list at `guides/cloudflare/index.mdx:16-23`.
- Show the route-name middleware on that page: registered before `router.routes()`, it reads `ctx.matched` inside a `try/finally` (so it also runs when a handler throws) and calls `Sentry.updateSpanName(root, routeName)`, `root.setAttribute(Sentry.SENTRY_SEGMENT_NAME_SOURCE, 'route')` and `root.setAttribute('http.route', pattern)` on `Sentry.getRootSpan(Sentry.getActiveSpan())`, plus `Sentry.getIsolationScope().setTransactionName(routeName)` so error events carry the route too, all exports of `@sentry/cloudflare`. Use the exported `SENTRY_SEGMENT_NAME_SOURCE` constant, not the legacy string `'sentry.source'`, which the SDK ignores; with the constant both trace lifecycles report source `route`.
