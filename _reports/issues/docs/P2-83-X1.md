`platform-includes/performance/enable-tracing/javascript.bun.mdx:1`, `javascript.deno.mdx:1` and `javascript.cloudflare.mdx:1` each read "Tracing is enabled by default in the Sentry <Runtime> SDK." The guides for those runtimes, and `platform-includes/performance/enable-automatic-instrumentation/javascript.bun.mdx` and `javascript.cloudflare.mdx`, tell the user to set `tracesSampleRate` or `tracesSampler`.

What was observed: `getPerformanceIntegrations` in `packages/bun/src/sdk.ts:38-44` returns no performance integrations when `hasSpansEnabled` is false, which is the case when neither `tracesSampleRate` nor `tracesSampler` is configured. So spans are produced only once one of the two options is set.

What to change:

- Replace the first sentence in all three includes with a statement that tracing is enabled by setting `tracesSampleRate` or `tracesSampler` in `Sentry.init`, and that no spans are recorded when neither is set.
- Keep the wording consistent with the `enable-automatic-instrumentation` includes for Bun and Cloudflare, which already require the option.
