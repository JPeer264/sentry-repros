`guides/wasm/index.mdx:65` says the integration provides Debug IDs, Debug Files, Code IDs, Code Files and memory addresses. With a module that has no `build_id` custom section (nothing in the guide's install or Rust steps adds one; `wasm-split` does) the event carries only `instruction_addr` and `platform: native` on the wasm frame, no `addr_mode` and no `debug_meta`: the registry skips modules without `build_id`. With the section present the full set arrives (`addr_mode: rel:0`, a `debug_meta.images` entry of type `wasm` with code_id, code_file, debug_file and debug_id). The page never mentions `wasm-split`, `build_id`, DWARF or the debug file upload.

Loading also matters and the page (`:160`, `:176-179`) is silent on it: a module loaded with `WebAssembly.instantiate(bytes)` after `fetch().arrayBuffer()` is named `wasm://wasm/<hash>` by Chrome, so even with `build_id` no image matches and no `addr_mode` or `debug_meta` is attached; `instantiateStreaming` and `compileStreaming` keep the URL and match.
