Verified on SolidStart 2 (`@solidjs/start` 2.0.2, Nitro 3) with `@sentry/solidstart` 10.67.0 on Bun 1.4.0: `sentrySolidStart()` in `vite.config.ts`, `Sentry.init` inside the Nitro plugin `server/plugins/sentry.ts`, `sentryBeforeResponseMiddleware()` in `src/middleware.ts`, `vite build`, then `bun .output/server/index.mjs`. Install `@sentry/bun` alongside `@sentry/solidstart` and add `bunHttpServerIntegration()` and `fetchIntegration()` to `integrations`, guarding the fetch one on `process.versions.bun` so a Node deployment of the same build does not get two spans. Add `import 'mysql2/promise';` as the first import of the Nitro plugin.

Works today:

- Per-request isolation, one scope and one trace per request
- Incoming `sentry-trace`/`baggage` continuation
- Outgoing `fetch` spans with propagation headers
- `mysql2` 3.20.0+ database spans, with the driver loaded at startup
- `Sentry.logger` log envelopes
- Errors from server functions wrapped in `withServerActionInstrumentation`

Known limits:

- Errors thrown in a file API route or during page render are not reported, on Bun and on Node alike.
- Server transactions are named from the raw URL (`GET /users/456`, source `url`), not the route pattern, on Bun and on Node alike.
- Drivers Sentry instruments by build-time code injection produce no spans on Bun.
