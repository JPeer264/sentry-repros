No page joins React Router and Bun. `docs/platforms/javascript/guides/react-router/index.mdx:5-9` declares `categories: [javascript, browser, server, server-node]`, the start commands at `react-router/manual-setup.mdx:400-401` are `NODE_OPTIONS='--import ./instrument.server.mjs'` only, and the "Incomplete Auto-instrumentation" alert at `manual-setup.mdx:434-438` warns at `:436` that the direct-import fallback leaves instrumentation incomplete.

Verified on React Router 8 framework mode with a custom Express server and `@sentry/react-router` 10.67.0 (develop, 6f2da7483d) on Bun 1.4.0 and re-run on 1.4.2: rewrite `app/entry.server.tsx` to use `renderToReadableStream` with `Sentry.wrapSentryHandleRequest(handler)` and `export const handleError = Sentry.createSentryHandleError({ logErrors: true })`, because Bun resolves `react-dom/server` to a build that has no `renderToPipeableStream`. Add `export const instrumentations = [Sentry.createSentryServerInstrumentation()];` to the same file: the docs already show it at `manual-setup.mdx:273` as an optional React Router 7.15+ feature, and on Bun it is required, because Bun has no diagnostics-channel injection for `node:http` and this export is the only source of server spans. Install `@sentry/bun` at the same version, deduped to a single `@sentry/core`, and pass `integrations: process.versions.bun ? [fetchIntegration(), bunHttpServerIntegration()] : []` to the `Sentry.init` in the instrumentation file imported as the very first line of `server.js`; the runtime gate matters because the same build under Node with an unconditional `fetchIntegration()` produces two client spans for one fetch. For database spans add `await import("mysql2/promise")` right after `Sentry.init()` as well — that import and `bunHttpServerIntegration()` are jointly necessary, either alone yields zero database spans — or pin the tracing channels instead. `ssr.noExternal: ['mysql2']` is not needed. Start with `bun server.js`.

Works today:

- Unhandled loader errors; the mechanism sharpens from `react-router` to `react_router.loader` once server spans exist
- `http.server` spans named `GET /users/:id` with source `route`, from the `instrumentations` export alone, in both lifecycles
- Per-request isolation, one trace per request
- Incoming `sentry-trace`/`baggage` continuation, plus request and IP data on events
- Outgoing `fetch` spans with propagation headers
- `mysql2` database spans
- `Sentry.logger` log envelopes

Known limits:

- Without the `instrumentations` export and `bunHttpServerIntegration()` the server SDK produces only errors and logs on Bun. The `instrumentations` export alone restores route-named `http.server` spans; `bunHttpServerIntegration()` additionally restores per-request isolation, incoming-trace continuation, outgoing-`fetch` spans and database spans.
- With `fetchIntegration()` but without `bunHttpServerIntegration()`, `traceLifecycle: 'static'` sends the propagation headers but delivers no span envelope at all, only a client report.
- `Sentry.createSentryHandleRequest({ renderToPipeableStream, ... })`, the wiring the guide shows, cannot be used on Bun. The customization escape hatch at `manual-setup.mdx:284-330` (`getMetaTagTransformer` plus `wrapSentryHandleRequest`) also builds on `renderToPipeableStream` and needs a Bun variant.
- The debug line "No diagnostics-channel injection detected. Channel-based integrations will not record spans" still fires after the fix and is misleading.
- `contexts.runtime.name` is `node` on Bun.
- Action errors and browser-side capture were not exercised; the error probe is a loader.
