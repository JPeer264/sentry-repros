Verified on Remix v2 (`@remix-run/dev` Vite plugin with the `@remix-run/express` adapter) and `@sentry/remix` 10.67.0 on Bun 1.4.0: `instrument.mjs` imported as the first line of `server.mjs`, `export const handleError = Sentry.sentryHandleError` in `app/entry.server.tsx`, `sentryRemixVitePlugin()` in `vite.config.ts`, the `mysql2` pool at module scope, then bundle the server entry with `Bun.build({ entrypoints: ['./server.mjs'], outdir: './dist', target: 'bun', plugins: [sentryBunPlugin()] })` from `@sentry/bun/plugin`, keeping `@sentry/*` and `express` external, and run `bun dist/server.js`. Hold the adapter handler in a variable and wrap it in `Sentry.withIsolationScope(() => Sentry.continueTrace({ sentryTrace, baggage }, () => remixHandler(req, res, next)))`, or add `bunHttpServerIntegration({ spans: false })` from `@sentry/bun` to `Sentry.init`.

Works today:

- Unhandled loader errors via the `handleError` hook
- Route names `GET users/:id` with source `route`, plus `LOADER routes/users.$id` children
- Per-request isolation and incoming trace continuation, with the wrapper above
- Outgoing `fetch` spans with propagation headers
- `mysql2` database spans
- `Sentry.logger` log envelopes

Known limits:

- Plain `bun server.mjs` sends errors and logs only, with no transactions or spans at all.
- The app's `package.json` must not carry `"sideEffects": false`, or the bundler drops side-effect-only imports and their libraries go uninstrumented.
- The bundle is emitted without sourcemaps unless you enable them, so events lose context lines.
