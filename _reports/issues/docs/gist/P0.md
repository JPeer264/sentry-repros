## 1. Rewrite the Bun guide's instrumentation step around @sentry/bun/plugin

**Audit item:** DOC-B1 · **Type:** docs-change · **Finding:** The guide states the instrumentation model backwards and never names the plugin

The Bun guide at `guides/bun/index.mdx:94` and `:106` tells the user to run `bun --preload ./instrument.js app.js`, and the alert at `:96-100` states that Sentry's auto-instrumentation does not work with bundled code and that bundling requires manual instrumentation. `@sentry/bun/plugin` is not named anywhere on the page, and `logs` is used as an onboarding block at `:182` but is missing from the options at `:20-22`.

What was observed on bun 1.4.0: a bundle built with `Bun.build({ plugins: [sentryBunPlugin()] })` from `@sentry/bun/plugin` records library and framework spans, while running the same app unbundled with `bun run` records none. `packages/bun/src/plugin.ts:14` states the plugin is build-only. The unbundled diagnostic message is printed only with `debug: true`.

What to change:

- Keep the `--preload` step, described as what guarantees init order.
- Add a "Build with the Sentry plugin" step showing `Bun.build({ entrypoints: [...], plugins: [sentryBunPlugin()] })` imported from `@sentry/bun/plugin`.
- Replace the alert at `:96-100` with a plain statement: library and framework instrumentation requires a build with the plugin; `bun run` on unbundled source records manual spans plus `Bun.serve`, `node:http` and `fetch` spans.
- Add `logs` to the onboarding options at `:20-22`, or remove the block at `:182`.

## 2. Fix inverted traceLifecycle default in the stream mode includes

**Audit item:** DOC-R1 · **Type:** docs-change · **Finding:** Stream-mode includes call `'static'` the default; develop defaults to `'stream'`

The three stream-mode includes present stream mode as opt-in. `platform-includes/performance/enable-stream-mode/javascript.bun.mdx:5` (and `javascript.deno.mdx:5`, `javascript.cloudflare.mdx:8`) say "Opt in by setting the `traceLifecycle` option to `'stream'`", and each closes with "set `traceLifecycle` to `'static'` (the default)" (`javascript.bun.mdx:25`, `javascript.deno.mdx:24`, `javascript.cloudflare.mdx:62`).

What to change:

- Reframe all three includes as opt-out: `'stream'` is the default, `'static'` is what a user sets.
- Replace the `traceLifecycle: "stream"` sample lines with `"static"` examples, or drop them.
- Add the missing comma after `tracesSampleRate: 0.2` at `javascript.cloudflare.mdx:19`.

## 6. Document the instrument.server file and the wranglerConfigPath requirement on the Cloudflare Vite plugin page

**Audit item:** DOC-Q2 · **Type:** docs-change · **Finding:** The Cloudflare Vite plugin reads its options from an undocumented file and is a silent no-op without the wrangler config path

`guides/cloudflare/features/vite-plugin.mdx` and the proposed quick start step 3 present `sentryCloudflareVitePlugin()` as a drop-in: add it next to `cloudflare()`, build, deploy. Neither says where the SDK options come from when the plugin wraps the entry, and neither says what happens when the wrangler config is not named `wrangler.jsonc` or `wrangler.toml` at the project root.

Observed on develop with a Worker whose source has no `withSentry` call: the plugin wraps the entry at build time (`const viteEntry = withSentry(__SENTRY_OPTIONS_CALLBACK__, __SENTRY_DEFAULT_EXPORT__)` in the built output), and the options callback is taken from an `instrument.server.{ts,js,mjs,cjs}` file next to the wrangler `main`. Without that file the callback falls back to `() => undefined` and the Worker runs with no DSN, silently. With the wrangler config under a non-default name and no `wranglerConfigPath`, the plugin instruments nothing: the run produced an empty sink, an uncaught error in the worker log and no trace headers, with no warning from the plugin. With `wranglerConfigPath` set and the options file present, the built Worker delivered the same errors, spans, headers and logs as a hand-written `withSentry`, with no experimental flag.

What to change:

- On the Vite plugin page, add the `instrument.server.ts` file as a required step when the source has no `withSentry`, with its shape: a default export of the options callback.
- State that `wranglerConfigPath` is required whenever the config is not at the default path, and that the plugin does nothing without it.
- Remove the `_experimental.useDiagnosticsChannelInjection` flag from the page and from `guides/cloudflare/index.mdx:77-92`; it is not needed on develop (also DOC-C4).
