The Remix guide names no runtime other than Node: `docs/platforms/javascript/guides/remix/index.mdx:4-9` scopes the guide with Node categories and `:11-17` carries only the Remix 3 alert, while `platform-includes/getting-started-prerequisites/javascript.remix.mdx:1-7` requires just Remix 2.0.0+. Greps for `deno`, `installGlobals`, `enableRuntimeChannelInjection` and `orchestrion` over `docs/` and `platform-includes/` all return zero.

Verified on Remix 2.17.x with the Remix Vite plugin and a custom `node:http` server on Deno 2.9.0: install with npm under Node using `--legacy-peer-deps`, set `deno.json` to `{"nodeModulesDir": "manual"}`, add `sentryRemixVitePlugin()` next to `remix()` in `vite.config.ts`, export `handleError = Sentry.sentryHandleError` from `app/entry.server.tsx`, and import `instrument.server.mjs` as the first line of the server entry with `Sentry.instrumentBuild(build)`. Call `installGlobals()` from `@remix-run/node` at the top of `app/entry.server.tsx`, which is what `remix reveal` generates: it replaces Deno's native `fetch` with the `node:http`-backed polyfill, and outgoing requests are then traced. For database spans, set `enableRuntimeChannelInjection: false` and bundle the server entry with `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild`, keeping `@sentry/*` external.

Works today:

- Loader errors, mechanism `auto.function.remix.server`.
- `GET users/:id` with source `route`, plus nested loader spans.
- Per-request isolation and incoming trace continuation.
- Outgoing `http.client` spans with trace headers, after `installGlobals()`.
- Database spans for `mysql2`, and logs.

Known limits:

- Without `installGlobals()`, outgoing `fetch()` produces no span and no `sentry-trace`/`baggage` headers.
- Express cannot be used as the Remix server on Deno; it fails at import.

What to change:

- Add `docs/platforms/javascript/guides/remix/install/deno.mdx`, name the supported runtimes in `index.mdx:4-9` and the prerequisites include, and document both SDK options above.
