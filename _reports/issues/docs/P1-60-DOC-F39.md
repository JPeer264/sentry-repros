Nothing documents Koa on Workers. `docs/platforms/javascript/guides/koa/index.mdx:1-12` is a 12-line stub declaring `sdk: sentry.javascript.node` with `fallbackGuide: javascript.node`, and grepping it for "cloudflare" or "workerd" returns nothing. `grep -rin koa docs/platforms/javascript/guides/cloudflare/` returns nothing, `guides/cloudflare/frameworks/` has no `koa.mdx`, the framework list at `guides/cloudflare/index.mdx:16-23` omits Koa, and `httpServerHandler` and `enable_nodejs_http_server_modules` appear nowhere in the docs.

Verified on the develop line: Koa 3 with `@koa/router` on workerd, `compatibility_date: "2026-05-01"`, `compatibility_flags: ["nodejs_compat", "enable_nodejs_http_server_modules"]`, served through `httpServerHandler` from `cloudflare:node` and wrapped with `Sentry.withSentry()` from `@sentry/cloudflare`. Build with Vite: `plugins: [cloudflare(), sentryCloudflareVitePlugin()]` from `@sentry/cloudflare/vite`, then `vite build` and run wrangler against the emitted config. `httpServerHandler({ port: 8080 })` stays at module scope; `new Koa()`, every `app.use()`, the router wiring and `app.listen()` must run inside `fetch`, behind a memoized promise.

Works today:

- Unhandled errors (mechanism `auto.middleware.koa`), parameterized route names with `http.route`, per-request isolation, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans from a `mysql` query, `Sentry.logger` logs.

Known limits:

- Without the Vite build there is no Koa instrumentation: errors are swallowed with no event and the transaction is named from the raw URL.
- Creating the Koa app at module scope makes the Worker fail to start with "Disallowed operation called within global scope".
- `mysql2` on workerd needs `disableEval: true` in the connection options.

- Add the module-scope rule as a shared note on `guides/cloudflare/features/vite-plugin.mdx`.
