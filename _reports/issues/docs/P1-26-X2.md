`common/migration/` ends at `v9-to-v10.mdx`, so there is no v10-to-v11 page. The SDK's `MIGRATION.md:289-295` says channel-based instrumentation now works on Cloudflare, Bun and Deno and that "For most users this requires no changes." It names none of `@sentry/bun/plugin`, `sentryBunPlugin` or `@sentry/deno/import`.

What was observed: on Bun, library and framework spans require a `Bun.build` with `sentryBunPlugin` from `@sentry/bun/plugin`, and are not produced under `bun run`. On Deno, they require a first-line `import '@sentry/deno/import';`. On Cloudflare, they require the Vite plugin from `@sentry/cloudflare/vite` with `buildTimeInstrumentation` left at its default. Each of these subpaths exists on `develop` and is exercised by the corresponding e2e apps and integration suites.

What to change:

- Add `common/migration/v10-to-v11.mdx` with a `PlatformSection` block per runtime, each stating the exact setup step above with a snippet.
- Make the Cloudflare section carry the entrypoint, option and API changes tracked as DOC-C1 through DOC-C5.
- State plainly which of the three runtimes needs a build step and which needs an import, so "requires no changes" is not the reader's takeaway.
