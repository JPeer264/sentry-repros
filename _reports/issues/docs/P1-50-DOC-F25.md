There is no Fresh page at all, and `docs/platforms/javascript/guides/deno/index.mdx:1-230` names no framework; the Deno guide directory holds only `index.mdx` and `configuration/integrations/{breadcrumbs,contextlines}.mdx`, so the Cloudflare-style `guides/*/frameworks/` layout has no Deno counterpart.

Verified on Fresh 2 and Deno 2.9.0: scaffold with `deno run -A jsr:@fresh/init@^2`, set `"nodeModulesDir": "manual"` in `deno.json`, install `@sentry/deno` into that same `node_modules`, keep `import "@sentry/deno/import";` as the first line of `instrument.ts` and `instrument.ts` as the first import of `main.ts`. Fresh catches route errors itself, so add `integrations: [Sentry.captureConsoleIntegration({ levels: ['error'], handled: false })]` to `Sentry.init` to report them; if the app registers its own `app.onError("*")` handler, call `Sentry.captureException` inside it instead. For database spans, use `mysql@2` and list each driver in both `ssr.external` and `environments.ssr.build.rollupOptions.external` in `vite.config.ts`. Both `deno task dev` and the `deno serve _fresh/server.js` build were exercised.

Works today:

- Errors, via `captureConsoleIntegration`, or an explicit capture in the app's error handler, or `setErrorInterceptor` from `jsr:@fresh/core/internal`.
- Incoming `sentry-trace`/`baggage` continuation.
- Database spans for `mysql@2`, with the driver externalized as above.
- Logs.

Known limits:

- Routes are not named automatically; a middleware that reads `ctx.route` and calls `Sentry.updateSpanName` on the root span is required, otherwise transactions carry the raw path with source `url`.
- Per-request isolation is not reliable on Deno: awaiting a dynamic `import()` inside a request restores that request's store into the root async context, so tags, users, contexts and breadcrumbs set during one request appear on every later request. Mitigate with a first middleware that strips tags, contexts, extra, user, breadcrumbs and attachments off `Sentry.getIsolationScope()`. Do not use `Sentry.withIsolationScope(new Sentry.Scope(), ...)` for this: it cleans events but attributes each request's tags to the next transaction.
- `mysql2` cannot be used: under the import hook Deno compiles its `require('*.json')` as JavaScript (denoland/deno#36240) and the route 500s.
- Outgoing `fetch()` is not instrumented.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/fresh.mdx` plus a `frameworks/index.mdx` listing the Deno frameworks.
