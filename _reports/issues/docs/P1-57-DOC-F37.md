Nothing documents Express on Workers. `docs/platforms/javascript/guides/express/index.mdx:4-9` pins `sdk: sentry.javascript.node` with `fallbackGuide: javascript.node`, and grepping the Express guide for "cloudflare" or "workerd" returns nothing. In the other direction, the Cloudflare framework list at `docs/platforms/javascript/guides/cloudflare/index.mdx:16-23` has no Express entry and `httpServerHandler`, `cloudflare:node` and `enable_nodejs_http_server_modules` appear nowhere under `docs/` or `platform-includes/`.

Verified on the develop line: Express 5 on workerd with `compatibility_date: "2026-05-01"` and `compatibility_flags: ["nodejs_compat", "enable_nodejs_http_server_modules"]`, served through `httpServerHandler` from `cloudflare:node` and wrapped with `Sentry.withSentry()` from `@sentry/cloudflare`. Build the Worker with Vite: `plugins: [cloudflare(), sentryCloudflareVitePlugin()]` from `@sentry/cloudflare/vite`, then `npx vite build && npx wrangler dev --config dist/<worker>/wrangler.json`. Keep `httpServerHandler({ port: 8080 })` at module scope but create the Express app and call `app.listen()` inside `fetch`, memoized on first request.

Works today:

- Unhandled route errors (mechanism `auto.http.express`), parameterized route names with `http.route`, per-request isolation across `await`, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans from `mysql2`, `Sentry.logger` logs.

Known limits:

- A Worker bundled by plain `wrangler dev`/`wrangler deploy` gets no route names, no handler spans and no database spans, and route errors are swallowed by Express with no event.
- `vite dev` cannot start Express on workerd; build first, then run wrangler against the build output.
- `mysql2` on workerd needs `disableEval: true` in the connection options.
