Neither guide covers the pair: `grep -rn -i hapi docs/platforms/javascript/guides/deno/` and `grep -rn -i deno docs/platforms/javascript/guides/hapi/` both return nothing. `docs/platforms/javascript/guides/hapi/index.mdx:4-5` declares `sdk: sentry.javascript.node` with `fallbackGuide: javascript.node` and `:12` is a bare `getting-started-node` include. `docs/platforms/javascript/guides/deno/index.mdx:1-230` covers error monitoring and tracing only, and never mentions `node_modules`, `nodeModulesDir` or the import hook.

Verified on `@hapi/hapi` 21.4.10 and Deno 2.9.0: `npm install @hapi/hapi` plus `@sentry/deno` into a real on-disk `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}` and an `imports` map, and `Sentry.init()` from `@sentry/deno` before the server is created. `hapiIntegration()` is already in the Deno SDK's default set, so no `integrations` entry is needed. Three shapes were verified. (A) Bundle the app with esbuild and `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild` (`bundle: true`, `platform: 'node'`, `format: 'esm'`, `external: ['@sentry/deno','@sentry/server-utils']`, `loader: {'.json': 'json'}`, `createRequire` banner) and run `deno run --allow-net --allow-env --allow-read --allow-sys dist/main.js`, which yields error capture, parameterized route names, hapi router spans and database spans with no runtime hook. (B) Keep `deno run main.ts` and call `attachHapiErrorHandler(server)` from `@sentry/server-utils`, which works before or after `server.start()`. (C) Keep `deno run main.ts` and put `import "@sentry/deno/import"` plus a twelve-line JSON load hook (`Module.registerHooks` returning `{ format: 'json', source: readFileSync(...) }` for `.json` URLs) ahead of the app; the two registrations may come in either order, but both must precede the app import.

Works today:

- Route errors, mechanism `auto.function.hapi`, in shapes A and C; in shape B, mechanism from `attachHapiErrorHandler`.
- `GET /users/{id}` with source `route`, in shapes A and C, plus a `router` child span.
- Route names without any build step or hook, through a six-line `server.ext('onPreHandler')` that calls `updateName` on the root span and then sets `Sentry.SENTRY_SEGMENT_NAME_SOURCE` to `route` and `http.route` to `request.route.path`. The attribute must be set after `updateName`, which otherwise leaves the source `custom`.
- Per-request isolation and incoming trace continuation, with or without a build step or hook.
- Database spans for `mysql`, in shapes A and C, and logs in every configuration.

Known limits:

- Running the entry directly with `Sentry.init()` alone loses Hapi errors, because Hapi turns the throw into a Boom 500 and the transaction is recorded with status `internal_error` while no event is sent, and it names transactions `GET /users/42` with source `url` (`http.server GET` under the stream lifecycle).
- `import "@sentry/deno/import"` on its own aborts the app at import: `@hapi/validate` does `require('../package.json')` and Deno compiles JSON as JavaScript while a module load hook is registered (denoland/deno#36240). Registering the hook through `--import` fails the same way; the JSON load hook is the escape.
- `@sentry/deno` does not export `setupHapiErrorHandler`, so the call the Hapi guide prescribes throws on Deno; the shipped equivalent is `attachHapiErrorHandler` from `@sentry/server-utils`.
- Outgoing `fetch()` is not instrumented: no `http.client` span and no `sentry-trace`/`baggage`, with and without the hook and in both trace lifecycles. `node:http`/`node:https` requests are traced and propagated.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/hapi.mdx` with the three setups side by side and the limits.
- `platform-includes/getting-started-use/javascript.hapi.mdx:17,42`: `await Sentry.setupHapiErrorHandler(server)` does not exist on `@sentry/deno`. Scope that step to the Node SDK, or give the Deno equivalent.
