No page mentions Elysia on Cloudflare Workers. `docs/platforms/javascript/guides/elysia/index.mdx:25` lists the prerequisites as "Bun or Node.js 18+ (with @elysiajs/node adapter)" and the install snippets at `:55-56` and `:82` are Bun and Node only. `platform-includes/performance/what-instrumentation-provides/javascript.elysia.mdx:9-12` has a "Runtime Behavior" section covering exactly two runtimes. The Cloudflare framework list at `docs/platforms/javascript/guides/cloudflare/index.mdx:16-23` has no Elysia entry and `guides/cloudflare/frameworks/` has no `elysia.mdx`.

Verified on the develop line: Elysia 1.4.30 on workerd with `compatibility_date: "2026-05-01"` and `compatibility_flags: ["nodejs_compat"]`. Install `@sentry/cloudflare @sentry/elysia elysia`. Construct the app as `withElysia(new Elysia({ aot: false }))` before any route is registered, and export `Sentry.withSentry((env) => ({ dsn: env.SENTRY_DSN, tracesSampleRate: 1.0 }), { fetch: request => app.fetch(request) })`. Ahead-of-time compilation must be off: with the default, workerd refuses to start the Worker because Elysia's generated handler runs `new Function` and touches randomness in global scope. For database spans, build with Vite: `plugins: [cloudflare(), sentryCloudflareVitePlugin()]` from `@sentry/cloudflare/vite`, then `vite build` and point wrangler at the emitted config.

Works today:

- Unhandled errors via Elysia's global error hook, parameterized route names, per-request isolation, incoming trace continuation, outgoing `fetch` spans with headers, `Sentry.logger` logs, and `db` spans through the Vite build.

Known limits:

- A `wrangler`-bundled Worker emits no database spans.
- `withElysia` must wrap the instance before routes are registered, or only the error path gets the route name.
- `mysql2` on workerd needs `disableEval: true` in the connection options.
