No page covers Koa on Deno. `docs/platforms/javascript/guides/koa/index.mdx:4` declares `sdk: sentry.javascript.node`, `:5` `fallbackGuide: javascript.node`, and `:12` is only `<PlatformContent includePath="getting-started-node" />`; `grep -rni deno docs/platforms/javascript/guides/koa/` returns nothing, and `docs/platforms/javascript/guides/deno/index.mdx:1-230` mentions no framework and no import hook.

Verified on Koa 3.2.1 with `@koa/router` 15.7.0 on Deno 2.9.0: `npm install` the app dependencies and `@sentry/deno` into a real `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}` and an `imports` map, an `instrument.ts` calling `Sentry.init()` from `@sentry/deno` that is evaluated before the Koa app module, and `deno run --allow-net --allow-env --allow-read --allow-sys main.ts`. Three shapes were exercised on top of that. (A) Bundle the server with esbuild and `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild` (`format: 'esm'`, `external: ['@sentry/deno', '@sentry/server-utils']`, plus a `createRequire` banner; both externals and the banner are load-bearing) and run the bundle. (B) Skip the bundler and start with `deno run --import=./preload.ts main.ts`, where `preload.ts` first registers a `node:module` load hook that returns `.json` URLs with `format: "json"` and then imports `"@sentry/deno/import"`. (C) For database spans without either, import the Koa app module first, then register the hook in the entry body with `await import("@sentry/deno/import")`, then `await import("mysql")` and create the client with `mysql.createConnection`.

Works today:

- Automatic route-error capture with mechanism `auto.middleware.koa`, in shapes A and B, with no `app.on('error')` of your own; in shape C, register `app.on('error', err => Sentry.captureException(err))` yourself.
- Parameterized names `GET /users/:id` with source `route`, `http.route` set and koa `router` spans, in shapes A and B, in both trace lifecycles.
- Per-request isolation and incoming trace continuation.
- Database spans for `mysql` in shape C, on the request transaction.
- Logs, carrying the request trace id.

Known limits:

- With no build step and no hook, nothing Koa-specific is instrumented: transactions are `GET /users/42` with source `url`, the streamed server span is `GET` with no `http.route`, there are no koa spans, and a thrown route error is not captured at all.
- `import "@sentry/deno/import"` must not be a static import of the entry file. Deno instantiates the entry's whole static module graph, Koa included, before the first statement runs, so the hook registers after Koa is already in the module cache and never transforms it, and the same import kills the process anyway: Koa's `statuses` dependency does `require('./codes.json')`, and Deno compiles JSON as JavaScript while any module load hook is registered (denoland/deno#36240), so it aborts with `SyntaxError: Unexpected token ':'`. The JSON load hook in shape B is what makes the flag form survive.
- Use `mysql.createConnection`, not `mysql.createPool`: pooled queries emit their db span as a root transaction of its own, on a different trace from the request.
- `@sentry/deno` exports no `setupKoaErrorHandler`, so the unbundled fallback is the hand-written `app.on('error')` listener, whose events carry a manual mechanism.
- `debug: true` prints "[instrumentation:koa] subscribing to channels" and "Integration installed: Koa" even when no hook is loaded and nothing is instrumented, so the debug log cannot be used to confirm the setup.
- Outgoing `fetch()` is not instrumented: no `http.client` span and no `sentry-trace`/`baggage`, in both trace lifecycles. `node:http`/`node:https` requests are traced and propagated.
