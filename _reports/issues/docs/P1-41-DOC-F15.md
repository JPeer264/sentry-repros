None of the 11 files under `docs/platforms/javascript/guides/tanstackstart-react/` contains the string "bun". `tanstackstart-react/index.mdx:5-9` declares `categories: [javascript, server, server-node, browser]`, the single documented start command is `node --import ./.output/server/instrument.server.mjs .output/server/index.mjs` (`manual-setup/index.mdx:372`), and the only non-Node runtime named anywhere is Cloudflare, as an exclusion (`manual-setup/index.mdx:391`).

Verified on TanStack Start (React) 1.168.35 with the Nitro node-server preset and `@sentry/tanstackstart-react` 10.67.0 on Bun 1.4.0: keep `@sentry/*` and `@opentelemetry/*` external in the server build via `build.rollupOptions.external` in `vite.config.ts`, wrap the server entry with `wrapFetchWithSentry`, install `@sentry/bun` at the same version and pass `integrations: [fetchIntegration(), bunHttpServerIntegration()]` to `Sentry.init` in `instrument.server.mjs`, guarded on `typeof globalThis.Bun !== 'undefined'`, then start with `bun --preload ./instrument.server.mjs .output/server/index.mjs`.

Works today:

- Unhandled errors from `server.handlers` routes, with `wrapFetchWithSentry` on the server entry
- Per-request isolation, one scope and one trace per request
- Incoming `sentry-trace`/`baggage` continuation
- Outgoing `fetch` spans with propagation headers
- `Sentry.logger` log envelopes

Known limits:

- Parameterized route names such as `GET /api/user/$id` are not produced on Bun.
- Database spans are not recorded on Bun.
- Without `bunHttpServerIntegration()` no transaction or span is recorded at all and every request shares one process-wide trace.
- Browser-side capture was not exercised.
