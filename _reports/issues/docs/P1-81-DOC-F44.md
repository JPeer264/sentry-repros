`docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx` is the only page for this combination and is 56 lines long. `:6` says the SDK supports Next.js on Workers "but requires additional configuration", `:14` points at OpenNext, `:15` at the plain Next.js install guide, `:28-38` sets `nodejs_compat`, `:40-54` sets a minimum `compatibility_date`, and `:56` closes with "You should start seeing error events, traces, and logs appear in Sentry." That is the entire body of advice. `disableEval` appears nowhere in the docs, and `@sentry/cloudflare` is never mentioned on the page.

Verified on the develop line: Next.js 15 App Router via `@opennextjs/cloudflare`, `compatibility_date: "2026-05-01"`, `compatibility_flags: ["nodejs_compat"]`, with `src/instrumentation.ts` exporting `register` and `onRequestError = Sentry.captureRequestError`, `sentry.server.config.ts` calling `Sentry.init`, and a CommonJS `next.config.js` wrapped with `withSentryConfig` from `@sentry/nextjs/config`. The config file has to be CommonJS: `import { withSentryConfig } from '@sentry/nextjs'` in an ESM `next.config.mjs` fails with "Named export 'withSentryConfig' not found", because the exports map puts the CJS `node` condition ahead of `import`. Outgoing HTTP needs one addition: install `@sentry/cloudflare` explicitly, it is not a transitive dependency, and add `fetchIntegration()` from it to the `integrations` array in `sentry.server.config.ts`; that one integration covers `node:http` calls as well as global `fetch`.

Works today:

- Unhandled route handler errors, parameterized route names (`GET /api/users/[id]`, source `route`), per-request isolation, incoming trace continuation, `Sentry.logger` logs.
- Outgoing `fetch` and `node:http` spans with `sentry-trace`/`baggage` propagation, once `fetchIntegration()` from `@sentry/cloudflare` is added.
- `db` spans from `mysql2`, with `disableEval: true` in the connection options.

Known limits:

- Only drivers that publish their own diagnostics channels produce database spans; `mysql` 2.x produces none on Workers. The visible symptom at init is the SDK logging "Failed to register diagnostics-channel injection hooks, so channel-based integrations will not record spans" with `TypeError: port1.on is not a function`. Listing the driver in `serverExternalPackages` is not an escape hatch: it produces spans but breaks the driver with `PROTOCOL_INCORRECT_PACKET_SEQUENCE`.
- `sendDefaultPii` is gone on the v11 line; leaving it in `sentry.server.config.ts` fails the `next build` type check.

What to change on `docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx`:

- Add an "Instrument Outgoing HTTP Requests" section after `:54` with the `@sentry/cloudflare` install and the `fetchIntegration()` snippet.
- Add a "Database Spans" section covering `disableEval: true` and the driver limit.
