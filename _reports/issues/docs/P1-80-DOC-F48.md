Verified on the develop line: React Router 7.18 in framework mode with SSR, `compatibility_date: "2026-05-01"`, `compatibility_flags: ["nodejs_compat"]`. Install `@sentry/react-router` and `@sentry/cloudflare` (a separate install), and pin `@react-router/node` to `^7` next to `react-router` 7: nothing on Workers uses it, but `@sentry/react-router`'s peer range otherwise makes npm hoist 8.3.1 and the install aborts with `ERESOLVE`. `react-router.config.ts` needs `ssr: true` and `future: { v8_viteEnvironmentApi: true }`, without which the build dies in `[commonjs--resolver]` with `id.endsWith is not a function`, a message that names neither plugin. `vite.config.ts` combines `cloudflare({ viteEnvironment: { name: 'ssr' } })`, `reactRouter()` and `sentryCloudflareVitePlugin()` from `@sentry/cloudflare/vite`. `app/entry.server.tsx` exports a `handleError` that calls `Sentry.captureException`, written by hand because `createSentryHandleError` lives only on the node entry: `@sentry/react-router/cloudflare` re-exports `../client`, `wrapSentryHandleRequest` and `injectTraceMetaTags` and nothing else. `wrapSentryHandleRequest` supplies the route names, and `injectTraceMetaTags` is what hands the browser its trace.

Works today:

- Loader errors, parameterized route names (`GET /users/:id`, source `route`), per-request isolation, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans from `mysql` through the Vite plugin's build-time instrumentation, `Sentry.logger` logs.

Known limits:

- Without the hand-written `handleError` export, React Router routes the throw into the ErrorBoundary and no event is sent; `createSentryHandleError` is not available on the Cloudflare entry.
- Building with `sentryCloudflareVitePlugin({ buildTimeInstrumentation: false })` removes all database spans.
- `mysql` 2.x is the driver this ran on; `mysql2` queries fail on workerd unless you pass `disableEval: true` in the connection options, which this cell did not exercise.
- Only the server runtime was exercised; the client half of `@sentry/react-router` was not part of this run.
