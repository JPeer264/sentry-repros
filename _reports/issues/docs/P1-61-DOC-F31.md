`docs/platforms/javascript/guides/react-router/` contains only `index.mdx`, `manual-setup.mdx` and `profiling/`, and `grep -rni deno` over it returns nothing; the reverse grep over `guides/deno/` also returns nothing. The guide is Node-shaped throughout: `index.mdx:9` categorises it `server-node`, `manual-setup.mdx:400-401` gives the only start commands and both are Node ones, and the "Limited Node support for OpenTelemetry auto-instrumentation" Expandable at `:186-197` is the closest the guide comes to a runtime statement.

Verified on React Router 7.18.3 in framework mode with `@sentry/react-router` 10.67.0 on Deno 2.9.0: `npm install` the app packages and the Sentry packages into a real `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}`. `app/entry.server.tsx` must use the web-stream renderer, `renderToReadableStream` from `react-dom/server`, because Deno resolves `react-dom/server` through the `deno` export condition and there is no `renderToPipeableStream`; wrap it with `wrapSentryHandleRequest` and export `handleError = createSentryHandleError({ logErrors: true })`. The server entry is a hand-written `node:http` adapter whose first line is `import './instrument.server.mjs';` and which serves `createRequestHandler(build, 'production')` over `http.createServer`; build with `npx react-router build` and start it with `PORT=<port> deno run --allow-net --allow-env --allow-read --allow-sys server.mjs`. Add the Vite plugin as `import { sentryReactRouter } from '@sentry/react-router/vite'`. Use `mysql@2`, not `mysql2`.

Works today:

- Loader errors, mechanism `react-router`, surfaced by the `handleError` export.
- `GET /users/:id` with op `http.server` and source `route`.
- Per-request isolation and incoming trace continuation.
- Database spans for `mysql@2` with no extra instrumentation path: the SDK subscribes to the driver's diagnostics channel eagerly on Deno. The connection must be created inside the loader.
- Outgoing `fetch()`, with `fetchIntegration` imported from `@sentry/cloudflare` and registered in `instrument.server.mjs` behind a Deno-only guard, so a Node build does not emit a duplicate `http.client` span.
- Logs.

Known limits:

- The two start paths the guide prescribes do not work on Deno: `react-router-serve` goes through the `renderToPipeableStream` path Deno cannot load, and `NODE_OPTIONS='--import ./instrument.server.mjs'` is ignored by Deno. A bare `Deno.serve` handler produces neither the `http.server` span nor the isolation scope, so the `node:http` server entry above is the load-bearing piece.
- `mysql2` cannot be loaded once Sentry is initialized: its `require('../package.json')` throws `SyntaxError: Unexpected token ':'` through the SDK's runtime require hook. Plain Deno imports it fine.
- With `mysql@2`, a module-scope pool detaches its query: the db span arrives as its own root transaction on a different trace while the request transaction has no children.
- Without the fetch integration above, an outgoing `fetch()` gets no `http.client` span and no `sentry-trace`/`baggage` headers, so the trace ends at the server. `node:http` requests are traced and propagated.
- Error events carry the raw path in their `transaction` field while the transaction itself carries the route pattern.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/react-router.mdx` and cross-link it from `guides/react-router/manual-setup.mdx` near `:400-401` and from the Node-support Expandable at `:186-197`.
