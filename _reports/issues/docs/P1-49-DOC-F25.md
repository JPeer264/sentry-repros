There is no Fresh page at all, and `docs/platforms/javascript/guides/deno/index.mdx:1-232` names no framework; the Deno guide directory holds only `index.mdx` and `configuration/integrations/{breadcrumbs,contextlines}.mdx`, so the Cloudflare-style `guides/*/frameworks/` layout has no Deno counterpart.

Verified on Fresh 2 and Deno 2.9.0: scaffold with `deno run -A jsr:@fresh/init@^2`, set `"nodeModulesDir": "manual"` in `deno.json`, install `@sentry/deno` into that same `node_modules`, keep `import "@sentry/deno/import";` as the first line of `instrument.ts` and `instrument.ts` as the first import of `main.ts`. Fresh catches route errors itself, so add `integrations: [Sentry.captureConsoleIntegration({ levels: ['error'], handled: false })]` to `Sentry.init` to report them; if the app registers its own error handler, call `Sentry.captureException` there. For database spans, list each driver in both `ssr.external` and `environments.ssr.build.rollupOptions.external` in `vite.config.ts`. Both `deno task dev` and the `deno serve _fresh/server.js` build were exercised.

Works today:

- Errors, via `captureConsoleIntegration` or an explicit capture in the app's error handler.
- Incoming `sentry-trace`/`baggage` continuation.
- Database spans for `mysql`, with the driver externalized as above.
- Logs.

Known limits:

- Routes are not named automatically; a middleware that reads `ctx.route` and calls `Sentry.updateSpanName` on the root span is required, otherwise transactions carry the raw path with source `url`.
- Per-request isolation is not reliable on Deno: the runtime leaks the AsyncLocalStorage store out of a handler that awaits a dynamic `import()`, so tags, users, contexts and breadcrumbs set during one request appear on later requests.
- Outgoing `fetch()` is not instrumented.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/fresh.mdx` plus a `frameworks/index.mdx` listing the Deno frameworks.
