No page covers Koa on Deno. `docs/platforms/javascript/guides/koa/index.mdx:4` declares `sdk: sentry.javascript.node`, `:5` `fallbackGuide: javascript.node`, and `:12` is only `<PlatformContent includePath="getting-started-node" />`; `grep -rni deno docs/platforms/javascript/guides/koa/` returns nothing, and `docs/platforms/javascript/guides/deno/index.mdx:1-232` mentions no framework and no import hook.

Verified on Koa with `@koa/router` on Deno 2.9.0: `npm install` the app dependencies and `@sentry/deno` into a real `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}` and an `imports` map, an `instrument.ts` calling `Sentry.init()` from `@sentry/deno` that is evaluated before the Koa app module, and `deno run --allow-net --allow-env --allow-read --allow-sys main.ts`. For automatic Koa error capture, bundle the server with esbuild and `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild` (`format: 'esm'`, `external: ['@sentry/deno', '@sentry/server-utils']`, plus a `createRequire` banner) and run the bundle; without that build step, register `app.on('error', err => Sentry.captureException(err))` yourself. For database spans, keep `@sentry/deno/import` out of the static imports and register it in the entry body with `await import("@sentry/deno/import")` after Koa is imported, then load the driver with a dynamic import.

Works today:

- Error capture, through the bundled build or the `app.on('error')` handler.
- Per-request isolation and incoming trace continuation.
- Database spans for `mysql`, with the deferred hook registration.
- Logs, carrying the request trace id.

Known limits:

- Parameterized route names are not available: transactions are `GET /users/42` with source `url`, and the streamed server span is `GET` with no `http.route`.
- `import "@sentry/deno/import"` must not be the first static import: Koa's `statuses` dependency does `require('*.json')`, and Deno compiles JSON as JavaScript while any module load hook is registered (denoland/deno#36240), so the process dies at import.
- Outgoing `fetch()` is not instrumented; `node:http` requests are.
