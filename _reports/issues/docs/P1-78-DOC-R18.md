`docs/platforms/javascript/common/configuration/releases.mdx:30-43` markets Release Health and links to Session APIs, and `docs/platforms/javascript/common/configuration/apis.mdx:922-940` documents `startSession`, `endSession` and `captureSession`. Neither file has `supported` or `notSupported` frontmatter, so both render on the Cloudflare guide as if `Sentry.startSession()` were available there.

It is not. `packages/cloudflare/src/index.ts` exports none of the three, so importing them from `@sentry/cloudflare` yields `undefined`. Bun (`packages/bun/src/index.ts:33-35`) and Deno (`packages/deno/src/index.ts:87-89`) export all three, which is why the pages read correctly on those guides. The audit verified the same functions imported from `@sentry/core` work inside a `withSentry` handler on Workers.

**What to change**

- On the Cloudflare rendering, state that the session APIs come from `@sentry/core`, not `@sentry/cloudflare`.
- Alternatively gate the Sessions section and the Release Health block away from `javascript.cloudflare`.
