`docs/platforms/javascript/guides/cloudflare/features/workflows.mdx` is 56 lines and covers `trace_id` derivation from `instanceId` (`:11-15`), the sampling decision (`:17-23`) and a warning about creating spans outside `step.do()` (`:25-30`). It never says what happens to an error thrown inside a step, so a reader cannot tell whether a retried failure appears once or many times.

On develop, `packages/cloudflare/src/workflows.ts:150-153` calls `captureException` only when `isFinalAttempt`. That flag is computed at `:113-120` from the step context the Workflows engine passes: when `attempt` and `config.retries.limit` are both present, only `attempt > retryLimit` reports, so intermediate retries send nothing. When no step context is supplied, every attempt is captured.

What to change:

- Add a section on step error capture to `workflows.mdx`.
- State that a failing `step.do()` reports once, on the final attempt, where the engine supplies a step context.
- Note that engines without a step context report every attempt.
