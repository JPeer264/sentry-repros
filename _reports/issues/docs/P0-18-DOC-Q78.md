**Filed.** Must item of Linear [SDK-1517](https://linear.app/getsentry/issue/SDK-1517), "Nitro (Getting started / Manual setup)".

`guides/nitro/index.mdx:23` says a Nitro application 3.0.260415-beta or newer, and `:50` installs `@sentry/nitro`. `npm install` fails with `ERESOLVE` for every Nitro beta newer than 3.0.260415-beta, the registry's latest 3.0.260903-beta included, because the peer range accepts only 3.0.0, 3.0.260311-beta and 3.0.260415-beta; the exact 260415 beta installs.

`:86-99` wraps `defineNitroConfig({ ... })` with no `serverDir`, and `:208` adds `routes/debug-sentry.ts` at the project root. Nitro 3 defaults to `serverDir: false`, scans nothing, and every route including `/debug-sentry` answers 404 with no event; with `serverDir: "./server"` and the file at `server/routes/debug-sentry.ts` the route creates the issue.

What to change:

- State the exact Nitro versions the peer range accepts and that newer betas need `--legacy-peer-deps` until the range is widened; add `serverDir: "./server"` to the config snippet and name the verify file `server/routes/debug-sentry.ts`.

The same peer range blocks the SolidStart guide: plain `npm install @sentry/solidstart` fails with `ERESOLVE` because `@sentry/nitro` rejects the nitro beta SolidStart 2 needs, and `--legacy-peer-deps` is required (QS-solidstart).
