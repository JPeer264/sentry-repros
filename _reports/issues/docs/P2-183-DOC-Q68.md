**Note.** the gen_ai.system, gen_ai.tool.input and gen_ai.tool.output renames are Linear SDK-1480.

`common/agent-tracing/mastra.mdx:140-172` lists `gen_ai.system`, `gen_ai.request.messages`, `gen_ai.request.temperature`, `gen_ai.tool.type` `function`, `gen_ai.tool.input`, `gen_ai.tool.output` and `gen_ai.agent.instructions`. The renames of `gen_ai.system`, `gen_ai.tool.input` and `gen_ai.tool.output` are Linear SDK-1480. The rest is not in it: the build sends `gen_ai.input.messages` and `gen_ai.output.messages` instead of `gen_ai.request.messages`, `gen_ai.tool.type` `tool` instead of `function`, and `gen_ai.system_instructions` instead of `gen_ai.agent.instructions`; no temperature; and `gen_ai.request.stream` is `true` for non-streaming calls. `guides/mastra/index.mdx:83` and `agent-tracing/mastra.mdx:61` say the exporter reads `SENTRY_ENVIRONMENT` and `SENTRY_RELEASE`; when unset it passes environment `production` and release `''`, and the empty release makes the SDK discard every session with a warning.

Two things about the trace neither page says: the model's HTTP calls arrive as separate `http.client` root segments (`auto.http.node_fetch`) in the same trace, not as children of `gen_ai.chat`; and on the built-in route each tool call yields two `gen_ai.execute_tool` spans (one under the agent span from `client_tool_call`, one under the chat span), so tool counts double.

What to change:

- Replace the attribute list with the names the exporter emits, beyond the three renames in SDK-1480, name the defaults and tell users to set `SENTRY_RELEASE`, and describe the trace shape.
