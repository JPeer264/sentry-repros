`guides/elysia/index.mdx:139` says client errors (3xx and 4xx) are not captured by default. The default filter reads `context.set.status`, which is 200 for Elysia's `NotFoundError` (an unmatched route, 404 to the client) and 500 for anything thrown through `status(4xx, ...)`: both are captured, `Error: NOT_FOUND` once per process because Elysia reuses one instance, and a `status()` throw as `'ElysiaCustomStatusResponse' captured as exception with keys: code, response`. Only `set.status = 4xx` before a throw is skipped. The guide's own `shouldHandleError` snippet (`:146-151`) suppresses them.

What to change:

- State that unmatched routes and `status()`-thrown responses are captured by default, that `status()` throws arrive as non-Error objects, and point at `shouldHandleError` as the filter.
