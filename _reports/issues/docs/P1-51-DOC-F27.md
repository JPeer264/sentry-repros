`grep -rniE "deno" docs/platforms/javascript/guides/nextjs/` returns zero hits across every subtree, and the reverse grep over `guides/deno/` returns zero for Next.js. `docs/platforms/javascript/guides/nextjs/index.mdx:4-9` declares `sdk: sentry.javascript.nextjs` with category `server-node`. `grep -rn "enableRuntimeChannelInjection" docs/` returns nothing repo-wide, so the option that makes this combination work is undocumented; `docs/platforms/javascript/common/configuration/options.mdx:729` is where the neighbouring `traceLifecycle` option lives.

Verified on Next.js 15.5.4 App Router and Deno 2.9.0: `deno.json` with `{"nodeModulesDir": "manual"}`, build and start with `deno run -A node_modules/next/dist/bin/next build` and `... next start`, the standard root `instrumentation.js` and `sentry.server.config.js`. Two deviations are required: set `enableRuntimeChannelInjection: false` in `Sentry.init()`, and add `integrations: [winterCGFetchIntegration()]` from `@sentry/vercel-edge`, which is already installed with `@sentry/nextjs`.

Works today:

- Route handler errors, mechanism `auto.function.nextjs.route_handler`.
- `GET /users/[id]` with source `route`, plus nested Next.js spans.
- Per-request isolation and incoming trace continuation.
- Outgoing `http.client` spans with `sentry-trace`/`baggage`, via `winterCGFetchIntegration()`.
- Database spans for drivers that ship their own diagnostics channels (`mysql2` 3.11+, `ioredis` 5.11+).
- Logs.

Known limits:

- Without `enableRuntimeChannelInjection: false`, every request returns 500 with `SyntaxError: Unexpected token ':'`, because Deno cannot `require()` a `.json` file while the module hook is installed (denoland/deno#36240).
- With it set, drivers that depend on that runtime hook, such as `mysql` 2.x and `pg`, produce no spans.
- Error events carry no source context lines.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/nextjs.mdx`.
- Document `enableRuntimeChannelInjection` in `common/configuration/options.mdx` near `:729`.
