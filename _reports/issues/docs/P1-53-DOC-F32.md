`grep -rni deno docs/platforms/javascript/guides/tanstackstart-react/` returns nothing, and `grep -rni tanstack docs/platforms/javascript/guides/deno/` also returns nothing. The guide is Node-only by construction: `docs/platforms/javascript/guides/tanstackstart-react/manual-setup/index.mdx:9` tags it `server-node`, `:286` heads the recommended section "With `--import` Flag (e.g. Node.js Server)", and `:354-358` gives the start script as `node --import ./.output/server/instrument.server.mjs .output/server/index.mjs`.

Verified with `@sentry/tanstackstart-react` 10.67.0 on Deno 2.9.0, running the Nitro `node` output: keep the documented app shape (`sentryTanstackStart()` in `vite.config.ts`, `wrapFetchWithSentry` in `src/server.ts`, the Sentry request and function middleware in `src/start.ts`, and `instrument.server.mjs` calling `Sentry.init`). Deno has no `node --import`, so add a two-line `.output/server/deno-entry.mjs` that imports `./instrument.server.mjs` then `./index.mjs`, and start it with `PORT=<port> deno run --allow-net ... deno-entry.mjs`. For parameterized names, pass `nitro({ noExternals: ['@sentry/tanstackstart-react'] })` in `vite.config.ts`, so the plugin can inject route patterns into the bundled SDK. Build with vite 8.x and the pristine config: vite 7.3.2 with nitro 3.0.260903-beta crashes rollup with `Cannot read properties of null (reading 'getVariableForExportName')` whether or not Sentry is involved, and a pre-plugin that externalises every `@sentry/*` import gets past that crash but silently removes the route parametrization. Confirm the injection landed before deploying with `grep -l 'users/$userId' .output/server/_libs/sentry__tanstackstart-react.mjs`.

Works today:

- Server route errors, mechanism `auto.middleware.tanstackstart.request`.
- Parameterized server route names (`GET /users/$userId`, source `route`), with `noExternals` set, in both trace lifecycles. A Node control run of the same output produced the same names.
- Per-request isolation and incoming trace continuation.
- Database spans for `mysql`, injected at build time by the Sentry Vite plugin.
- Logs.

Known limits:

- If the build externalizes `@sentry/tanstackstart-react`, transaction names stay raw, for example `GET /users/123` with source `url`. This is a build-config effect, not a Deno one: the same build produces url-source names under Node, and the SDK emits no warning when the route-pattern substitution did not happen.
- The build is version-sensitive: vite 7.3.2 with nitro 3.0.260903-beta fails in rollup with or without Sentry, and the externalising pre-plugin that works around it costs the route names.
- Outgoing `fetch()` is not instrumented on Deno: no `http.client` span and no `sentry-trace`/`baggage` headers.
