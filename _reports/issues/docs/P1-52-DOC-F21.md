There is no page for Fastify on Deno. `docs/platforms/javascript/guides/fastify/index.mdx:4` declares `sdk: sentry.javascript.node`, `:5` `fallbackGuide: javascript.node`, and `:12-14` is only `<PlatformContent includePath="getting-started-primer" />` plus `getting-started-node`; `grep -rni deno docs/platforms/javascript/guides/fastify/` returns zero hits. `docs/platforms/javascript/guides/deno/index.mdx:1-230` never mentions Fastify, any framework, `nodeModulesDir`, or the `@sentry/deno/import` hook.

Verified on Fastify 5.12.3 and Deno 2.9.0 with `@sentry/deno` 10.67.0: a `package.json` with `{"type":"module"}`, `npm install @sentry/deno fastify mysql2` into a real `node_modules`, `deno.json` with `{"nodeModulesDir": "manual"}` and an `imports` map, an `instrument.ts` that only calls `Sentry.init({ dsn, tracesSampleRate: 1.0 })`, imported as the very first line of `main.ts`, and `deno run --allow-net --allow-env --allow-read --allow-sys main.ts`. No build step is needed and the Fastify integration is on by default; `setupFastifyErrorHandler(app)`, which the Fastify guide still prescribes, is a deprecated no-op on the develop line and errors are captured without it.

Works today:

- Route errors, mechanism `auto.function.fastify`, with the server span marked `internal_error`.
- `GET /users/:id` with source `route` and `http.route` set, in both trace lifecycles.
- Per-request isolation and incoming trace continuation.
- Database spans for `mysql2` 3.20+, which publishes its own diagnostics channels, with no import hook and no bundler plugin.
- Logs.
- Outgoing `fetch()`, with `integrations: [winterCGFetchIntegration()]` imported from `@sentry/vercel-edge`: the `http.client` span and the `sentry-trace`/`baggage` headers appear in both trace lifecycles, with the shipped integration running unmodified on Deno. It is an extra package to install next to `@sentry/deno`.

Known limits:

- Do not add `import "@sentry/deno/import"`: with it the process dies at import with `SyntaxError: Unexpected token ':'` from `ajv/dist/core.js:21`, which does `require("./refs/data.json")`, because Deno compiles JSON requires as JavaScript once a module load hook is registered (denoland/deno#36240).
- Outgoing `fetch()` is not instrumented by default: `@sentry/deno`'s default integrations trace only `node:http`/`node:https`, so without the integration above a `fetch()` gets no `http.client` span and no `sentry-trace`/`baggage` headers, in either trace lifecycle.

What to change:

- Add `docs/platforms/javascript/guides/deno/frameworks/fastify.mdx` with the setup above and an explicit warning against the import hook.
- Put the outgoing `fetch` note, with the `winterCGFetchIntegration()` remedy, in `guides/deno/index.mdx` as a shared runtime section.
