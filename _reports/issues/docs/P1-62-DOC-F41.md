Verified on the develop line: Oak 17.2.0 on workerd with `compatibility_date: "2026-05-01"` and `compatibility_flags: ["nodejs_compat"]`. Oak's current line ships only to JSR, so install it through the JSR npm bridge (`@jsr:registry=https://npm.jsr.io` in `.npmrc`, then `npm install '@oak/oak@npm:@jsr/oak__oak@17.2.0'`); the plain npm package stops at 14.1.0. Oak's `Application.fetch` is already a Workers fetch handler, so no adapter is needed and `withSentry` is the whole wiring: `export default Sentry.withSentry((env) => ({ dsn: env.SENTRY_DSN, tracesSampleRate: 1.0 }), { fetch: (request, env, ctx) => app.fetch(request, env, ctx) })`. Run with `npx wrangler dev`; no bundler plugin is required.

Works today:

- Unhandled errors (Oak rethrows rather than swallowing), per-request isolation, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans from a `mysql` query under plain `wrangler dev`, `Sentry.logger` logs.

Known limits:

- There is no Sentry Oak integration, so the request span is named from the raw URL under `traceLifecycle: 'static'` and from the HTTP method alone under the default `'stream'`, never from the matched route pattern.
- The server span is reported with status `ok` even when the handler threw.
- `mysql2` queries fail on workerd.
