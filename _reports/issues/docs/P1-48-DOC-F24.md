Oak appears nowhere in the docs: `grep -rin '\boak\b' docs/ platform-includes/` and `grep -rl '@oak/oak\|jsr:@oak' docs/` return nothing. `docs/platforms/javascript/guides/deno/index.mdx:1-230` names no framework and never mentions `Deno.serve`, only bare `deno run` at `:100` and `:119`; the Deno guide directory holds just `index.mdx` and two integration pages.

Verified on Oak 17.2.0 (`jsr:@oak/oak`) and Deno 2.9.0: `deno.json` with `{"nodeModulesDir": "manual"}` and imports for `@oak/oak` and `@sentry/deno`, `@sentry/deno` present in a real `node_modules`, plus `npm install path-to-regexp@6.3.0`, which Oak needs to boot under manual `nodeModulesDir`. Put `import "@sentry/deno/import";` as the first line of the instrument file, then `Sentry.init()`, and mount the app with `Deno.serve(app.fetch)`. Name routes with a middleware registered before `app.use(router.routes())` that reads `ctx.matched?.at(-1)?.path` and, inside `try { await next(); } finally { ... }`, calls `Sentry.updateSpanName(span, `${ctx.request.method} ${route}`)` and sets both `Sentry.SENTRY_SEGMENT_NAME_SOURCE` to `route` and `http.route` to the route. A `router.use((ctx, next) => { ...; return next(); })` registered before the routes is equivalent.

Works today:

- Route errors, mechanism `auto.http.deno`, on the `app.fetch` path.
- Per-request isolation and incoming trace continuation.
- `GET /users/:id` with source `route` and `http.route` set, via the naming middleware, on the success and the error path, in both trace lifecycles, and with prefixed routers (`GET /api/users/:id`).
- Database spans for `mysql` through the import hook, with the driver imported dynamically after init.
- Logs, correlated to the request trace.

Known limits:

- `app.listen()` runs handlers outside the request's async context: no active span, errors are never captured, and tags and trace ids leak between requests. Nothing in user code repairs it, so always mount with `Deno.serve(app.fetch)`.
- Naming code placed after `await next()` instead of in a `finally` block silently skips every request whose handler throws, so those keep the unparameterized name.
- Without the middleware, spans are named by HTTP method only (stream) or by the raw path with source `url` (static); there is no Oak integration in `@sentry/deno`.
- Oak types `app.fetch` as a Cloudflare handler, so `ctx.request.ip` is empty on Deno. The SDK still records the client address, which it takes from the `Deno.serve` connection info.
- Outgoing `fetch()` is not instrumented; `node:http` requests are.
