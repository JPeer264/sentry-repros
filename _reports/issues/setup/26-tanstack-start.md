- [ ] **P1** · DOC-F49 · TanStack Start on Workers: no Configure Vite step
  `docs/platforms/javascript/guides/cloudflare/frameworks/tanstack-start.mdx:1-281` covers this combination and is linked from `docs/platforms/javascript/guides/cloudflare/index.mdx:23`. `:10` scopes the page to Cloudflare Workers built with `@cloudflare/vite-plugin`, `:16-47` covers the install, `:50` states that the server entry must be wrapped with `Sentry.withSentry` from `@sentry/cloudflare`, `:59-100` shows the custom server entry with `wrapFetchWithSentry` from `@sentry/tanstackstart-react` inside `Sentry.withSentry(...)`, `:102-123` the `"main": "src/server.ts"` wrangler change, `:125` the client configuration, `:184` server-side error capture, `:221` source maps and `:232` verification. The page has no Vite configuration section at all: `sentryTanstackStart` appears nowhere on it, and the only two "vite" mentions are incidental, at `:10` and `:258`. It also never states which versions the setup was exercised against.
  Verified on the develop line: TanStack Start (React) v1.136 with file-based routing, React 19, `compatibility_date: "2026-05-01"`, `compatibility_flags: ["nodejs_compat"]`, wrangler 4.129.0. The page's wiring was exercised as shown, plus one step the page never mentions: `sentryTanstackStart()` from `@sentry/tanstackstart-react/vite` in `vite.config.ts`. Plugin order matters: `cloudflare({ viteEnvironment: { name: 'ssr' } })` first, `tanstackStart()`, then `sentryTanstackStart()`. `src/start.ts` registers `sentryGlobalRequestMiddleware` and `sentryGlobalFunctionMiddleware` first in their arrays, and `src/router.tsx` must export `getRouter`, not `createRouter`, or the client build fails. Run `vite build`, then `wrangler dev` against the emitted config.
  Works today:
  - Unhandled route handler errors, parameterized route names (`GET /users/$id`, source `route`, with `http.route`), per-request isolation, incoming trace continuation, outgoing `fetch` spans with propagation headers, `db` spans, `Sentry.logger` logs.
  Known limits:
  - Without `sentryTanstackStart()` in `vite.config.ts`, two capabilities disappear at once: route names fall back to the raw URL (`GET /users/123`, source `url`), because that plugin defines `__SENTRY_ROUTE_PATTERNS__`, which `wrapFetchWithSentry` reads, and database spans vanish, because the same plugin runs `sentryOrchestrionPlugin`.
- `vite dev` produces no database spans on this stack at all: the orchestrion plugin returns early when `NODE_ENV` is `development`. Use `vite build` plus `wrangler dev`.
- Only the server runtime was exercised; the client half of the SDK was not part of this run.
  **Change:** On `docs/platforms/javascript/guides/cloudflare/frameworks/tanstack-start.mdx`: Add a "Configure Vite" step to the Configure section showing the full plugin chain in order, `cloudflare({ viteEnvironment: { name: 'ssr' } })`, then `tanstackStart()`, then `sentryTanstackStart()`, and stating that without the last one route names fall back to source `url` and database spans are not recorded. Say in that step that `sentryCloudflareVitePlugin()` should not be added to a TanStack Start app, since the TanStack plugin chain plus the explicit `withSentry` in `src/server.ts` already covers it, and that database spans need `vite build`, not `vite dev`. Add a tested-versions note near `:10` recording the combination above.
