Docs changes for the Bun guide that a new user hits between install and the first event on v11, from the runtime docs audit (develop `03aaf42455` and `6f2da7483d`, docs `aebda0ee4`). Each item links to its issue draft in the secret gist (https://gist.github.com/JPeer264/6d973a8266700d0cecbca9ed27cf8b21); the reproductions are [`quickstarts/bun/`](<https://github.com/JPeer264/sentry-repros/tree/issue-linear-runtime-improvements/quickstarts/bun>) in the audit repository.

## Must land

- [ ] **P0** · DOC-B1 · The instrumentation step is backwards and never names the plugin
  The Bun guide at `guides/bun/index.mdx:88` and `:100` tells the user to run `bun --preload ./instrument.js app.js`, and the alert at `:90-94` states that Sentry's auto-instrumentation does not work with bundled code and that bundling requires manual instrumentation. `@sentry/bun/plugin` is not named anywhere on the page, and `logs` is used as an onboarding block at `:182` but is missing from the options at `:20-22`.
  What was observed on bun 1.4.0: a bundle built with `Bun.build({ plugins: [sentryBunPlugin()] })` from `@sentry/bun/plugin` records library and framework spans, while running the same app unbundled with `bun run` records none. `packages/bun/src/plugin.ts:14` states the plugin is build-only. The unbundled diagnostic message is printed only with `debug: true`.
  **Change:** Keep the `--preload` step, described as what guarantees init order. Add a "Build with the Sentry plugin" step showing `Bun.build({ entrypoints: [...], plugins: [sentryBunPlugin()] })` imported from `@sentry/bun/plugin`. Replace the alert at `:90-94` with a plain statement: library and framework instrumentation requires a build with the plugin; `bun run` on unbundled source records manual spans plus `Bun.serve`, `node:http` and `fetch` spans. Add `logs` to the onboarding options at `:20-22`, or remove the block at `:182`.
  Draft: [Rewrite the Bun guide's instrumentation step around @sentry/bun/plugin](<https://gist.github.com/JPeer264/6d973a8266700d0cecbca9ed27cf8b21#27-rewrite-the-bun-guides-instrumentation-step-around-sentrybunplugin>)

- [ ] **P2** · DOC-Q4 · Two warnings on the documented path that no page explains
  Following the "Apply Instrumentation to Your App" step at `guides/bun/index.mdx:82-105` as written, `bun --preload ./instrument.ts app.ts` (the command at `:100`) with `debug: true` prints `No available Node API to register diagnostics-channel injection hooks; skipping.` at startup and `[Sentry] No diagnostics-channel injection detected. Channel-based integrations will not record spans. Make sure the diagnostics channels are injected via the runtime --import hook or a bundler plugin before the instrumented modules load.` after the first request. Neither line is mentioned on the Bun guide or the troubleshooting pages, and the guide names no bundler plugin (DOC-B1).
  Observed on `develop` with bun 1.4.2: the warnings are correct. The first comes from `packages/server-runtime-injection/src/register.ts:160` (`:201` at develop head), the second from `packages/server-utils/src/orchestrion/detect.ts:38-42`; both go through `debug.warn`, so they print only with `debug: true`. Runtime instrumentation (`Bun.serve`, fetch, errors, logs) works on the documented path, and library instrumentation needs the `Bun.build` with `sentryBunPlugin()`. A reader who sees the warning has no page that says which of the two it refers to.
  **Change:** Quote both lines on the Bun guide next to the run command at `:100`, say that they print only with `debug: true` and that runtime instrumentation is unaffected, and link the plugin build step from DOC-B1 as the fix for library spans.
