- [ ] **P1** · DOC-Q85 · The Node install pages do not reflect the v11 install-method decision: --import main, bundler plus top-level import, @sentry/node/import with late init, no CommonJS option
  The SDK team settled the v11 install methods for Node on 2026-09-09 while aligning the in-product onboarding (Linear SDK-1446); the docs pages do not reflect the decision yet, and the getting-started runs show why it matters:
  - `node --import ./instrument.mjs` stays the main documented path, because it guarantees the runtime wrapping and instruments as early as possible. Every Node quick start delivered the full telemetry on that path.
  - An alternative page documents the bundler plugin plus a top-level import, and explains the difference: a plain first-line import is not enough on its own because ESM hoists the framework imports ahead of `Sentry.init`. The runs measured that nuance: Express, Fastify, Hapi and Hono still got their spans and errors from a first-line import (their instrumentation registers at runtime), Koa lost every router and middleware span and, without the deprecated handler, its error capture (DOC-Q28, DOC-Q45). The pattern `import "./instrument.mjs"; await import("./app.mjs");` makes a top-level import safe without a bundler.
  - An alternative page documents `--import @sentry/node/import` with a later `Sentry.init()`, replacing the late-initialization page that still rests on the removed `@sentry/node/preload` entry (DOC-Q26).
  - The CommonJS install option is dropped; the pages assume ESM.
  - Meta-frameworks are documented without `--import`, with an alternative that uses it and says when (for example when some packages are not bundled). Nuxt no longer emits the server config into the build, so it cannot be `--import`ed at all (DOC-F11).

  **Change:** Rework `common/install/index.mdx`, `esm.mdx`, `esm-without-import.mdx`, `commonjs.mdx` and `late-initialization.mdx` to the three methods above, record the decision on the pages rather than in a chat thread, and align the in-product onboarding snippets with it.
  Draft: [Restructure the Node install methods for v11: --import as the main path, bundler plus top-level import and --import @sentry/node/import as the alternatives, no CommonJS option](<https://gist.github.com/JPeer264/6d973a8266700d0cecbca9ed27cf8b21#107-restructure-the-node-install-methods-for-v11---import-as-the-main-path-bundler-plus-top-level-import-and---import-sentrynodeimport-as-the-alternatives-no-commonjs-option>)
