Add a TanStack Start on Deno page with the Deno entry and noExternals

Description

grep -rni deno docs/platforms/javascript/guides/tanstackstart-react/ returns nothing, and grep -rni tanstack docs/platforms/javascript/guides/deno/ also returns nothing. The guide is Node-only by construction: docs/platforms/javascript/guides/tanstackstart-react/manual-setup/index.mdx:9 tags it server-node, :300 heads the recommended section "With --import Flag (e.g. Node.js Server)", and :369-376 gives the start script as node --import ./.output/server/instrument.server.mjs .output/server/index.mjs.

Verified with @sentry/tanstackstart-react 10.67.0 on Deno 2.9.0, running the Nitro node output: keep the documented app shape (sentryTanstackStart() in vite.config.ts, wrapFetchWithSentry in src/server.ts, the Sentry request and function middleware in src/start.ts, and instrument.server.mjs calling Sentry.init). Deno has no node --import, so add a two-line .output/server/deno-entry.mjs that imports ./instrument.server.mjs then ./index.mjs, and start it with PORT=<port> deno run --allow-net ... deno-entry.mjs. For parameterized names, pass nitro({ noExternals: ['@sentry/tanstackstart-react'] }) in vite.config.ts with Vite 8, so the plugin can inject route patterns into the bundled SDK.

Works today:

  • Server route errors, mechanism auto.middleware.tanstackstart.request.
  • Parameterized server route names, with noExternals set.
  • Per-request isolation and incoming trace continuation.
  • Database spans for mysql, injected at build time by the Sentry Vite plugin.
  • Logs.

Known limits:

  • If the build externalizes @sentry/tanstackstart-react, transaction names stay raw, for example GET /users/123 with source url.
  • Outgoing fetch() is not instrumented on Deno: no http.client span and no sentry-trace/baggage headers.

What to change:

  • Add docs/platforms/javascript/guides/deno/frameworks/tanstack-start.mdx.
  • Add a Deno start-command variant in guides/tanstackstart-react/manual-setup/index.mdx near :369-376.

A TanStack Start on Deno page must exist. It must say the Nitro `node` output runs under Deno and that errors, per-request isolation, incoming trace continuation, database spans and logs all work, and it must replace the Node-only `node --import …` start command at :369-376 with the Deno equivalent. Two build-shape facts must be documented because neither is discoverable. (1) Server route parametrization (`GET /users/$userId` rather than `GET /users/123`) requires `@sentry/tanstackstart-react` to be bundled into the Nitro server build, because the Vite plugin injects the route patterns by transforming the SDK's own source; if the build externalizes the SDK the names stay raw. The verified fix is `nitro({ noExternals: ['@sentry/tanstackstart-react'] })` in `vite.config.ts` (with Vite 8), alongside `tanstackStart()` and `sentryTanstackStart()`. (2) On Deno the server SDK does not instrument outgoing `fetch()` — no `http.client` span and no `sentry-trace`/`baggage` headers — so the trace stops at the server boundary. The page must ship the global-fetch integration for `instrument.server.mjs`, built from primitives `@sentry/core` already exports (`addFetchInstrumentationHandler`, `defineIntegration`, `getClient`, `instrumentFetchRequest`, `isSentryRequestUrl`, `LRUMap`, `shouldPropagateTraceForUrl`) — the same body `@sentry/cloudflare` ships as its `fetchIntegration`. It should also note the install shape the run needed: a single `npm install` of all Sentry tarballs plus an explicit `npm install nitro@latest`.

Where the docs stand: `grep -rni deno docs/platforms/javascript/guides/tanstackstart-react/` returns nothing and `grep -rni tanstack docs/platforms/javascript/guides/deno/` returns nothing; the guide is Node-only by construction — docs/platforms/javascript/guides/tanstackstart-react/manual-setup/index.mdx:9 tags it `server-node`, :300 heads the recommended section "With `--import` Flag (e.g. Node.js Server)", and :369-376 gives the start script as `node --import ./.output/server/instrument.server.mjs .output/server/index.mjs`
