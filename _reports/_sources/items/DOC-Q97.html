DOC-Q97The Remix captureActionFormDataKeys claim describes data that never appears on errored actionsP1proven

Proposed issue docs-change

Correct the captureActionFormDataKeys description on the Remix page

Description

platform-includes/getting-started-complete/javascript.remix.mdx:189-194 says captureActionFormDataKeys captures the listed action form-data fields with errors and requires sendDefaultPii. With the snippet as printed and a form posting the listed keys, the throwing action produced no remix.action_form_data.* attribute on its span or its event: the instrumentation skips form data when the action errored. The successful action got the keys on its ACTION span with the values redacted to [Filtered]: the sample names key_x and key_y contain key, which is on the built-in sensitive-key denylist (packages/core/src/utils/data-collection/filtering-snippets.ts:11), so their values can never appear. sendDefaultPii does not exist on develop; captureActionFormDataKeys is an integration-level option that takes precedence over dataCollection.httpBodies (packages/remix/src/utils/formData.ts:16-18), and without it every field is captured when httpBodies includes incomingRequest, the default.

What to change:

  • State that the fields land on the action span of successful actions, drop the sendDefaultPii sentence, and use sample keys that are not on the built-in denylist, since key_x and key_y always report [Filtered].
