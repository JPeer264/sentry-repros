DOC-R19Cloudflare Pages middleware snippet does not say the root middleware also spans static asset requestsP2verified in source

Proposed issue docs-change

Note that the root Pages middleware also spans static asset requests

Description

The Cloudflare Pages setup at docs/platforms/javascript/guides/cloudflare/index.mdx:161-205 tells the reader to register sentryPagesPlugin as the first entry in onRequest inside functions/_middleware.js (snippet at :174). includes/cloudflare-pages-middleware-intro.mdx instructs creating that file in the functions directory at the project root. Neither says which requests the middleware then handles.

A root functions/_middleware.js runs on every Cloudflare Pages request, static asset requests included. Under the default stream lifecycle each asset fetch produces its own http.server span envelope alongside the app's function routes, which changes both the trace volume and what the reader sees in the performance view; the same requests become transactions only with traceLifecycle: "static". The naming is worth stating too: the root request span is named GET / and every other path is named bare GET, with the path carried in the url.path attribute.

What to change

  • Add a note to the Pages setup section stating that a root middleware runs on every request, static assets included.
  • Say what arrives per request under the default stream lifecycle: one http.server span envelope, named GET / for the root and GET for every other path, with url.path as an attribute.
  • Point readers at scoping the middleware to a subdirectory, for example functions/api/_middleware.js, when they want only their function routes instrumented.

Confirmed on 2026-09-09 with wrangler 4.130.0: the root functions/_middleware.js produced an http.server span envelope for GET / and for GET /style.css, requests with no function at all; moved to functions/api/_middleware.js it instrumented /api/* only and silently dropped the guide's own root functions/debug-sentry.js verify route, so the scoped remedy needs the note that the verify route must then live under that directory (QS-cloudflare-pages, variants base and scoped).

Source: runtime docs audit, item DOC-R19

Status quo. docs/platforms/javascript/guides/cloudflare/index.mdx:161-205 tells the reader to add `sentryPagesPlugin` as the first middleware in `functions/_middleware.js` (snippet at :174), and includes/cloudflare-pages-middleware-intro.mdx instructs creating that file in the `functions` directory at the project root. Neither says what requests the middleware then runs on.

On develop. probes/C10 drove a Pages project with a root `functions/_middleware.js` under the default stream lifecycle: every request produced an `http.server` span envelope, the static assets `/` and `/app.js` included. Under stream mode those are span envelopes, not transactions; transactions appear only with `traceLifecycle: "static"`. C10 also recorded the naming: `GET /` for the root and bare `GET` for every other path, with `url.path` as an attribute.

Work item. Add a note to the Pages setup section stating that a root middleware runs on every request including static assets, that each one arrives as its own span envelope under the default stream lifecycle, and that scoping the middleware to a subdirectory such as `functions/api/_middleware.js` limits instrumentation to function routes.
