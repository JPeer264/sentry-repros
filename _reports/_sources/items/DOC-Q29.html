Proposed issue docs-change

Drop the deprecated setup*ErrorHandler calls from the Express, Fastify, Koa and Hapi getting-started snippets

Description

platform-includes/getting-started-use/javascript.express.mdx:15 and :34 add Sentry.setupExpressErrorHandler(app) after all routes. On develop the export is marked @deprecated in the build (server-utils/build/types/integrations/express/error-handler.d.ts:17-20), takes only app, and prints no notice at runtime. The variants without the call captured the same events on express 4 and 5 (auto.http.express, handled: false, 5xx only), and expressIntegration({ shouldHandleError }) is what changes the filter, as common/migration/v10-to-v11/index.mdx:715-746 describes. The Fastify tab does the same at platform-includes/getting-started-use/javascript.fastify.mdx:11 and :28: setupFastifyErrorHandler(app) is a deprecated empty function on develop, the variants without it captured the same events on Fastify 4 and 5, and nothing is printed at runtime (QS-fastify, variants no-handler and fastify4-no-handler). The Koa tab at getting-started-use/javascript.koa.mdx:11 and :28 places setupKoaErrorHandler(app) before app.listen(): the deprecated call adds an app.on('error') listener that pre-empts Koa's default one, so Koa's stderr error logging silently disappears while capture is identical without the call under --import (QS-koa, variants import and no-handler; the direct-import exception is DOC-Q45). The Hapi tab at getting-started-use/javascript.hapi.mdx:17 and :42 tells readers to await Sentry.setupHapiErrorHandler(server) before server.start(); the export is deprecated and a no-op on develop, the listener is auto-registered on the start channel, and every no-handler variant captured the identical four events (QS-hapi, variants no-handler, self-import-no-handler and errors-only-no-handler).

What to change:

  • Remove the four calls from the getting-started snippets and point at expressIntegration({ shouldHandleError }) and fastifyIntegration({ shouldHandleError }) for filtering.
