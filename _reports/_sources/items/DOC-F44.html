Proposed issue docs-change

Document outgoing fetch and database spans for Next.js on Cloudflare Workers

Description

docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx is the only page for this combination and is 56 lines long. :6 says the SDK supports Next.js on Workers "but requires additional configuration", :14 points at OpenNext, :15 at the plain Next.js install guide, :28-38 sets nodejs_compat, :40-54 sets a minimum compatibility_date, and :56 closes with "You should start seeing error events, traces, and logs appear in Sentry." That is the entire body of advice. disableEval appears nowhere in the docs, and @sentry/cloudflare is never mentioned on the page.

Verified on the develop line: Next.js 15 App Router via @opennextjs/cloudflare, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"], with src/instrumentation.ts exporting register and onRequestError = Sentry.captureRequestError, sentry.server.config.ts calling Sentry.init, and next.config.js wrapped with withSentryConfig from @sentry/nextjs/config. Outgoing HTTP needs one addition: install @sentry/cloudflare explicitly, it is not a transitive dependency, and add fetchIntegration() from it to the integrations array in sentry.server.config.ts.

Works today:

  • Unhandled route handler errors, parameterized route names (GET /api/users/[id], source route), per-request isolation, incoming trace continuation, Sentry.logger logs.
  • Outgoing fetch spans and sentry-trace/baggage propagation, once fetchIntegration() from @sentry/cloudflare is added.
  • db spans from mysql2, with disableEval: true in the connection options.

Known limits:

  • Only drivers that publish their own diagnostics channels produce database spans; mysql 2.x produces none on Workers.

What to change on docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx:

  • Add an "Instrument Outgoing HTTP Requests" section after :54 with the @sentry/cloudflare install and the fetchIntegration() snippet.
  • Add a "Database Spans" section covering disableEval: true and the driver limit.

Page: docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx — add an "Instrument Outgoing HTTP Requests" section after the Wrangler section (after :54) with the `@sentry/cloudflare` install plus `fetchIntegration()` in `sentry.server.config.ts`, and a "Database Spans" section documenting `disableEval: true` for mysql2

The page's two wrangler settings are correct but incomplete: errors, route names, isolation, incoming trace continuation and logs worked, while two capabilities needed undocumented steps. (1) Outgoing fetch produced no spans and no trace propagation out of the box. The page must state that on Cloudflare Workers the Next.js SDK does not instrument outgoing HTTP automatically, because the Workers runtime provides a native `fetch` instead of the Node.js implementation the SDK patches, and must show the fix: install `@sentry/cloudflare` explicitly (it is not a transitive dependency of `@sentry/nextjs`) and add `fetchIntegration()` from `@sentry/cloudflare` to the `integrations` array in `sentry.server.config.ts`. (2) Database spans work, but only with `disableEval: true` passed to `mysql2`'s `createPool`/`createConnection`; without it the query throws `EvalError: Code generation from strings disallowed` because workerd forbids `new Function`, which mysql2 uses to compile row parsers. Nothing about the Sentry configuration changes for db spans, and `next.config.js` stays the plain `withSentryConfig` wrapper. The word `disableEval` appears nowhere in the docs today.

Where the docs stand: docs/platforms/javascript/guides/cloudflare/frameworks/nextjs.mdx:1-56 is the only page for this combination (56 lines total). :6 "supports Next.js applications deployed on Cloudflare Workers, but requires additional configuration"; :14 points at OpenNext; :15 at the plain Next.js install guide; :28-38 `nodejs_compat`; :40-54 `compatibility_date` `2025-08-16` or later; :56 "You should start seeing error events, traces, and logs appear in Sentry." That is the entire body of advice. Missing: `grep -rn disableEval docs/platforms/javascript platform-includes` returns zero hits anywhere in the docs. `@sentry/cloudflare` is never mentioned on nextjs.mdx (the only install instruction is the generic Next.js guide link at :15), and docs/platforms/javascript/common/configuration/integrations/fetchIntegration.mdx:14-22 documents `Sentry.fetchIntegration` only under the Cloudflare platform (platform-includes/configuration/integrations/javascript.cloudflare.mdx:6), with no cross-reference from the Next.js on Cloudflare page. docs/platforms/javascript/guides/cloudflare/index.mdx:19 links to this page from the framework list.
