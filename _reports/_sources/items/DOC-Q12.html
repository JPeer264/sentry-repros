Proposed issue docs-change

Fix the React Router v6 and v7 page snippets that fail on React 19

Description

Three snippets on the React Router pages fail when copied verbatim into a React 19 app. The declarative-mode snippet at guides/react/features/react-router/v7.mdx:71-108 renders with ReactDOM.render (:101), which react-dom 19 no longer exports: TypeError: import_react_dom.default.render is not a function at boot, nothing renders, and the SDK reports its own docs page crash. The same call sits at v6.mdx:94, v6.mdx:150 and v7.mdx:155.

The useRoutes snippet at v7.mdx:122-160 imports wrapUseRoutes (:131) but calls wrapUseRoutesV7 (:147), and uses Sentry, ReactDOM and BrowserRouter without importing them: ReferenceError: Sentry is not defined, the SDK never initializes and zero envelopes arrive. v6.mdx:117-155 has the same mismatch.

The custom errorElement snippet at v7.mdx:239-255 is a jsx block that contains the TypeScript cast useRouteError() as Error (:244) and imports from react-router-dom (:240) while the page installs react-router: esbuild stops with Expected ";" but found "as" and an unresolved import. The same cast is at v8.mdx:246 and v6.mdx:239.

With the three defects fixed, the page's wiring works: pageload and navigation segments named /users/:userId with source route, and the errorElement boundary captures the route render error.

What to change:

  • Render with ReactDOM.createRoot(document.getElementById("root")).render(...), as v8.mdx:104 already does, in all four places.
  • In the useRoutes snippets import * as Sentry from "@sentry/react", call Sentry.wrapUseRoutesV7 (or Sentry.wrapUseRoutes), and import BrowserRouter and ReactDOM.
  • Drop the cast or tag the block tsx, and import useRouteError from the package the page installs.
