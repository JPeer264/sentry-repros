Proposed issue docs-change

Rewrite the Connect guide and integration page for v11, whose SDK has no Connect instrumentation

Description

common/migration/v10-to-v11/index.mdx:1370 records that the Connect instrumentation was removed, and the develop build confirms it: @sentry/node exports neither setupConnectErrorHandler nor connectIntegration, installs no Connect integration (46 with tracing, 23 without), and carries no orchestrion config or diagnostics-channel subscriber for connect. The docs still describe it in six places.

platform-includes/getting-started-use/javascript.connect.mdx:11 and :28 call Sentry.setupConnectErrorHandler(app) after connect(): every app the guide prints crashes with TypeError: Sentry.setupConnectErrorHandler is not a function before it listens, under --import, CommonJS, a first-line import and NODE_OPTIONS; the orphaned getting-started-add-top-level-import/javascript.connect.mdx:9 and :24 do the same. common/configuration/integrations/connect.mdx:23-27 passes integrations: [Sentry.connectIntegration()], which throws inside the instrument file so the SDK never initializes; :3, :19 and :21 say the integration is enabled by default and captures spans with @opentelemetry/instrumentation-connect (and the sentence says "for the Hapi framework"). The integrations table row at platform-includes/configuration/integrations/javascript.connect.mdx:7, the request-handler row at v10-to-v11/index.mdx:436 and the Connect entry of common/install/late-initialization.mdx:113 repeat it.

With the handler line deleted the guide app runs and delivers the generic Node telemetry only: http.server segments named GET with source url and no http.route, no handler or middleware span, logs, and no automatic capture of a thrown handler error (DOC-Q53).

What to change:

  • Delete the setupConnectErrorHandler(app) line from both tabs and the orphaned include, and say that v11 has no Connect-specific instrumentation: requests appear as method-named http.server segments.
  • Replace the Connect integration page with a removal notice pointing at the migration entry, drop the table row, drop Connect from the request-handler row at :436 and from the late-initialization list.
