DOC-Q26The late-initialization page is built on the @sentry/node/preload entry that v11 removedP0proven

Proposed issue docs-change

Rewrite or remove the late-initialization install page for v11

Description

common/install/late-initialization.mdx (supported by the Node, Connect, Express, Fastify, Hapi, Hono and Koa guides) tells readers to run node --require @sentry/node/preload app.js (:37) or node --import @sentry/node/preload app.js (:68) and to select modules with SENTRY_PRELOAD_INTEGRATIONS (:106, :132).

Observed on develop: Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './preload' is not defined by "exports" in @sentry/node/package.json; the package exports ., ./import, ./vite, ./rollup, ./webpack and ./esbuild only. common/migration/v10-to-v11/index.mdx:1359 records that the init, preload and loader entry points were removed from every server SDK, and names the replacement: --import the SDK and call Sentry.init() later. The Fastify run hit the same error; the page lists Fastify at :9 and :114 (QS-fastify, variant late-init), as did the Koa run, with Koa listed at :116 (QS-koa, variant late-init).

What to change:

  • Rewrite the page around the v11 shape (--import the SDK, call Sentry.init() when the DSN is known) and drop @sentry/node/preload and SENTRY_PRELOAD_INTEGRATIONS, or remove the page from the v11 docs.
  • Check the v11 docs tickets for an existing owner before filing.
