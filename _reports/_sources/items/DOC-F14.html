DOC-F14React Router on Bun: documented noP1proven

Proposed issue new-page

Add a React Router on Bun page requiring bunHttpServerIntegration

Description

No page joins React Router and Bun. docs/platforms/javascript/guides/react-router/index.mdx:5-9 declares categories: [javascript, browser, server, server-node], the start commands at react-router/manual-setup.mdx:413-414 are NODE_OPTIONS='--import ./instrument.server.mjs' only, and manual-setup.mdx:449 warns that the direct-import fallback leaves instrumentation incomplete.

Verified on React Router 8 framework mode with a custom Express server and @sentry/react-router 10.67.0 on Bun 1.4.0: rewrite app/entry.server.tsx to use renderToReadableStream with Sentry.wrapSentryHandleRequest(handler) and export const handleError = Sentry.createSentryHandleError({ logErrors: true }), because Bun resolves react-dom/server to a build that has no renderToPipeableStream. Install @sentry/bun at the same version and pass integrations: [fetchIntegration(), bunHttpServerIntegration()] from it to the Sentry.init in the instrumentation file imported as the very first line of server.js, and import the database driver at startup.

Works today:

  • Unhandled loader and action errors
  • http.server spans named GET /users/:id with source route
  • Per-request isolation, one trace per request
  • Incoming sentry-trace/baggage continuation
  • Outgoing fetch spans with propagation headers
  • mysql2 database spans
  • Sentry.logger log envelopes

Known limits:

  • Without bunHttpServerIntegration() the server SDK is inert on Bun: only errors and logs arrive, every request shares one scope and one trace, and child spans are dropped.
  • Sentry.createSentryHandleRequest({ renderToPipeableStream, ... }), the wiring the guide shows, cannot be used on Bun.
  • Browser-side capture was not exercised.

What to change:

  • New page docs/platforms/javascript/guides/bun/frameworks/react-router.mdx with the server-entry rewrite, the two @sentry/bun integrations, the startup driver import, the bun server.js start command and the capability list.
  • react-router/manual-setup.mdx:413-414: add the Bun equivalent of the start commands.

Source: runtime docs audit, item DOC-F14, cell M-reactrouter-bun

Page: docs/platforms/javascript/guides/bun/frameworks/react-router.mdx (new)

A page must say React Router 8 framework mode with a custom Express/Node server runs on Bun 1.4.0 but that the stock `node-custom-server` template's `server.js` has to be rewritten for Bun, and must state plainly that `@sentry/react-router` is inert on Bun on its own: only errors and logs arrive; there are no route names, no per-request isolation, no incoming `sentry-trace`/`baggage` continuation, no outgoing `fetch` spans, and no database spans (child spans are additionally suppressed by `requiresParentSpan` once no request span exists). The cause and fix must both be documented: Bun's `node:http` does not emit the `http.server.request.start` diagnostics channel the Node SDK opens the request span from, so install `@sentry/bun` at the same version (deduped to one `@sentry/core`) and pass `integrations: [fetchIntegration(), bunHttpServerIntegration()]` from it to the `Sentry.init` in the instrumentation file imported as the very first line of `server.js`, and import your database driver at startup. The Node-only start commands at manual-setup.mdx:413-414 need a documented Bun equivalent.

Where the docs stand: ~/dev/sentry-docs/docs/platforms/javascript/guides/react-router/index.mdx:5-9 (`categories: [javascript, browser, server, server-node]`); ~/dev/sentry-docs/docs/platforms/javascript/guides/react-router/manual-setup.mdx:413-414 (`NODE_OPTIONS='--import ./instrument.server.mjs' react-router dev` / `... react-router-serve ./build/server/index.js`); manual-setup.mdx:449 ("automatic instrumentation will be incomplete" warning for the direct-import fallback). `grep -rin bun` over guides/react-router/ and `grep -rin react.router` over guides/bun/ both return nothing.

What ran: React Router 8 (framework mode, custom Express/Node server) with @sentry/react-router 10.67.0 (develop, v11 line) on bun 1.4.0 (cross-checked on the CI pin bun 1.3.14 at $SCRATCH/bun1314/bun-darwin-aarch64/bun). Cell record.
