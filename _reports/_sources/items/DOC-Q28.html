Proposed issue docs-change

Correct the first-line import limitation on the esm-without-import page for v11

Description

common/install/esm-without-import.mdx:28-30 says that with a direct first-line import only native Node.js APIs can be instrumented and the SDK will not capture framework-specific data. Observed on develop: import "./instrument.mjs" as the first line of the Express app produced exactly the --import output, with middleware and handler spans, route-named segments (GET /users/:id, source route) and auto.http.express error events; the Node run's Express check saw the same, and the Fastify run got the same hook and handler spans and auto.function.fastify events from a first-line import (QS-fastify, variant self-import). Koa is the counter-example: its first-line import produced url-named GET segments and no router or middleware span (QS-koa, variant self-import), so the page should name what is covered and what is not instead of a blanket warning.

What to change:

  • Replace the blanket warning with what is affected on v11 (packages imported before the instrument file), and say that Express and Fastify are covered while Koa is not.
