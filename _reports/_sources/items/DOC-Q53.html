Proposed issue docs-change

Say on the Connect guide that errors need an error-handling middleware, and show it

Description

platform-includes/getting-started-verify/javascript.connect.mdx:7 and :13-15 say that app.use("/debug-sentry", (req, res) => { throw new Error(...) }) creates an issue. On the app that starts (the handler line removed, DOC-Q52), the request answers 500 from Connect's finalhandler, Connect prints the stack, and no event reaches Sentry in any variant, with or without tracing; thrown and next(err) errors (404, 503, 500) are all swallowed. The guide also renders no capture-errors step, because getting-started-capture-errors has no Connect include (DOC-Q31). The only Connect error that arrived was the unhandled rejection of the async tracing snippet (DOC-Q27).

What to change:

  • Add an error-handling middleware (err, req, res, next) that calls Sentry.captureException(err) before next(err) as the prerequisite of the verify route, and state that v11 captures no Connect errors on its own.

Source: runtime docs audit, item DOC-Q53, quick start QS-connect, variants no-handler, cjs-no-handler and errors-only
