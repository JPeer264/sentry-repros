Proposed issue docs-change

Correct the SvelteKit adapter note: adapter-node runs on Deno

Description

docs/platforms/javascript/guides/sveltekit/manual-setup__v10.7.0.mdx:21-36 holds the "Notes on SvelteKit adapter compatibility" section, whose "Currently not supported" heading at :31 is followed at :32 by a bullet saying non-Node server runtimes are not yet supported, while :28 lists adapter-node as fully supported. That reads as excluding Deno, and the current manual-setup.mdx has no adapter-and-runtime section at all. grep -rni deno over the SvelteKit guide returns nothing.

Verified on SvelteKit with adapter-node and @sentry/sveltekit 10.67.0 on Deno 2.9.0: build with vite build under Node, using sentrySvelteKit() imported from @sentry/sveltekit/vite, then start the adapter output with HOST=<host> PORT=<port> deno run --allow-net --allow-env --allow-read --allow-sys --allow-ffi build/index.js. For outgoing requests, register fetchIntegration from @sentry/cloudflare, already installed as a dependency of @sentry/sveltekit, in src/hooks.server.js, gated on Deno so Node builds are not double-instrumented. For mysql2, prime its package.json in the CJS require cache before the SDK installs its module hooks, either with a preload file (createRequire(import.meta.url)('mysql2/package.json') started through deno run --preload ./prewarm-json.mjs) or with the same two lines at the very top of src/hooks.server.js.

Works today:

  • Errors from +server.js handlers, mechanism auto.function.sveltekit.handle_error.
  • GET /users/[id] with source route.
  • Per-request isolation and incoming trace continuation.
  • http.client spans plus sentry-trace/baggage, with fetchIntegration().
  • Database spans for mysql with no extra flags, and for mysql2 with the prewarm above, parented under the SvelteKit http.server span in both trace lifecycles.
  • Logs.

Known limits:

  • Without fetchIntegration(), neither a global fetch() nor SvelteKit's event.fetch produces an http.client span or carries trace headers on Deno.
  • mysql2 fails on first use unless its package.json is in the require cache before Sentry.init: Deno compiles require('*.json') as JavaScript while a module hook is registered (denoland/deno#36240), and the route throws SyntaxError: Unexpected token ':'. The prewarm above is the fix; mysql needs nothing.
  • The "@sentry/server-runtime-injection was bundled into your application" warning can fire on Deno while instrumentation is working, so it is no signal of a broken setup.

What to change:

  • Fix manual-setup__v10.7.0.mdx:21-36 to name Deno with adapter-node as supported.
  • Restore an adapter-and-runtime section in manual-setup.mdx and add a Deno framework page with the run command and the fetchIntegration snippet.
  • common/configuration/integrations/fetchIntegration.mdx:10: it says the integration "only works inside the Cloudflare Workers runtime", which this run disproves.

The adapter-compatibility note must be corrected to say that SvelteKit runs on Deno through adapter-node with no source changes: build with `vite build` under Node, then start the adapter output with `HOST=… PORT=… deno run --no-prompt --allow-net --allow-env --allow-read --allow-sys --allow-ffi build/index.js`. Errors, route names, per-request isolation, incoming trace continuation and logs all work unchanged. Two Deno-specific caveats must be added. (1) Outgoing HTTP: `@sentry/node`'s fetch instrumentation is inert on Deno because it listens on undici `diagnostics_channel` events and Deno's global `fetch` is native, so neither a global `fetch()` nor SvelteKit's `event.fetch` produces an `http.client` span or carries `sentry-trace`/`baggage`. The verified fix is to register `fetchIntegration` from `@sentry/cloudflare` (already installed as a dependency of `@sentry/sveltekit`, so no new install) in `src/hooks.server.js`, gated to Deno so Node builds are not double-instrumented. (2) Database spans: they work on Deno with adapter-node, for `mysql` with no flags at all and for `mysql2` with one preparatory line. Deno has an open bug (denoland/deno#36240) where registering any module hook makes `require('*.json')` compile as JavaScript, so a driver that reads its own `package.json` at runtime throws `SyntaxError: Unexpected token ':'` on first use; the verified fix is to put that JSON in the CJS require cache before `Sentry.init` runs — `createRequire(import.meta.url)('mysql2/package.json')` either in a preload file started with `deno run --preload ./prewarm-json.mjs`, or as the first two lines of `src/hooks.server.js` above the `@sentry/sveltekit` import. Both give a `db` span parented under the SvelteKit `http.server` span in both trace lifecycles, so mysql2 is usable, not blocked. The page should also say that the "@sentry/server-runtime-injection was bundled into your application" warning can appear on Deno while everything works. (3) The fetchIntegration reference page still states the integration only works inside Cloudflare Workers, which this run disproves, so it needs correcting too.

Where the docs stand: docs/platforms/javascript/guides/sveltekit/manual-setup__v10.7.0.mdx:21-36 ("Notes on SvelteKit adapter compatibility") has the "Currently not supported" heading at :31 and the bullet at :32 — "Non-Node.js server runtimes, such as Vercel's edge runtime, are not yet supported" — which reads as excluding Deno, while :28 lists Adapter-node as fully supported; the run contradicts the exclusion (the adapter-node production build ran under Deno with errors, route names, isolation, incoming trace, db spans and logs all working). The current docs/platforms/javascript/guides/sveltekit/manual-setup.mdx has no such expandable at all (its body is only `sentry-init/manual-setup-callout` + `getting-started-complete`, :1-9), so the v11 line now makes no runtime statement whatsoever; `grep -rni deno docs/platforms/javascript/guides/sveltekit/` returns 0 hits; common/configuration/integrations/fetchIntegration.mdx:10 still says the integration "only works inside the Cloudflare Workers runtime"
