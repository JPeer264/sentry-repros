Correct the SvelteKit adapter note: adapter-node runs on Deno

Description

docs/platforms/javascript/guides/sveltekit/manual-setup__v10.7.0.mdx:21-35 holds the "Notes on SvelteKit adapter compatibility" section, whose "Currently not supported" bullet at :30-31 says non-Node server runtimes are not yet supported, while :28 lists adapter-node as fully supported. That reads as excluding Deno, and the current manual-setup.mdx has no adapter-and-runtime section at all. grep -rni deno over the SvelteKit guide returns nothing.

Verified on SvelteKit with adapter-node and @sentry/sveltekit 10.67.0 on Deno 2.9.0: build with vite build under Node, using sentrySvelteKit() imported from @sentry/sveltekit/vite, then start the adapter output with HOST=<host> PORT=<port> deno run --allow-net --allow-env --allow-read --allow-sys --allow-ffi build/index.js. For outgoing requests, register fetchIntegration from @sentry/cloudflare, already installed as a dependency of @sentry/sveltekit, in src/hooks.server.js, gated on Deno so Node builds are not double-instrumented.

Works today:

  • Errors from +server.js handlers, mechanism auto.function.sveltekit.handle_error.
  • GET /users/[id] with source route.
  • Per-request isolation and incoming trace continuation.
  • http.client spans plus sentry-trace/baggage, with fetchIntegration().
  • Database spans for the mysql driver, with no extra flags.
  • Logs.

Known limits:

  • Without fetchIntegration(), neither a global fetch() nor SvelteKit's event.fetch produces an http.client span or carries trace headers on Deno.
  • mysql2 cannot be loaded once the SDK is initialized: Deno compiles require('*.json') as JavaScript while a module hook is registered (denoland/deno#36240), and the route fails with SyntaxError: Unexpected token ':'.

What to change:

  • Fix manual-setup__v10.7.0.mdx:21-35 to name Deno with adapter-node as supported.
  • Restore an adapter-and-runtime section in manual-setup.mdx and add a Deno framework page with the run command and the fetchIntegration snippet.

Page: guides/sveltekit/manual-setup__v10.7.0.mdx:21-35 — correct the "Currently not supported" bullet and add Deno/adapter-node; restore an adapter-and-runtime compatibility section in guides/sveltekit/manual-setup.mdx (which currently has none), and add guides/deno/frameworks/sveltekit.mdx with the run command, the `fetchIntegration` snippet and the mysql2 `createRequire` workaround

The adapter-compatibility note must be corrected to say that SvelteKit runs on Deno through adapter-node with no source changes: build with `vite build` under Node, then start the adapter output with `HOST=… PORT=… deno run --no-prompt --allow-net --allow-env --allow-read --allow-sys --allow-ffi build/index.js`. Errors, route names, per-request isolation, incoming trace continuation and logs all work unchanged. Two Deno-specific caveats must be added. (1) Outgoing HTTP: `@sentry/node`'s fetch instrumentation is inert on Deno because it listens on undici `diagnostics_channel` events and Deno's global `fetch` is native, so neither a global `fetch()` nor SvelteKit's `event.fetch` produces an `http.client` span or carries `sentry-trace`/`baggage`. The verified fix is to register `fetchIntegration` from `@sentry/cloudflare` (already installed as a dependency of `@sentry/sveltekit`, so no new install) in `src/hooks.server.js`, gated to Deno so Node builds are not double-instrumented. (2) Database spans: they work on Deno with adapter-node and no flags for drivers that do not read their own `package.json` at import time (`mysql` needs nothing). Deno has an open bug (denoland/deno#36240) where registering any module hook makes `require('*.json')` compile as JavaScript, which breaks drivers like `mysql2`; the verified workaround is to force the driver's `package.json` into the CJS cache before `Sentry.init` runs, i.e. `createRequire(import.meta.url)('mysql2/package.json')` at the top of `src/hooks.server.js` followed by a dynamic `await import('@sentry/sveltekit')`.

Where the docs stand: docs/platforms/javascript/guides/sveltekit/manual-setup__v10.7.0.mdx:21-35 ("Notes on SvelteKit adapter compatibility") lists at :30-31 under "Currently not supported" — "Non-Node.js server runtimes, such as Vercel's edge runtime, are not yet supported" — which reads as excluding Deno, while :28 lists Adapter-node as fully supported; the run contradicts the exclusion (the adapter-node production build ran under Deno with errors, route names, isolation, incoming trace, db spans and logs all working). The current docs/platforms/javascript/guides/sveltekit/manual-setup.mdx has no such expandable at all (its body is only `sentry-init/manual-setup-callout` + `getting-started-complete`, :1-9), so the v11 line now makes no runtime statement whatsoever; `grep -rni deno docs/platforms/javascript/guides/sveltekit/` returns 0 hits

What ran: SvelteKit 2 (@sveltejs/kit 2.x, adapter-node 5.x, svelte 5, vite 6) + @sentry/sveltekit 10.67.0 (develop) on Deno 2.9.0 (aarch64-apple-darwin), running the adapter-node production build. Cell record.
