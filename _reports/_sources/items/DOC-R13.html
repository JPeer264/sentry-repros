Proposed issue docs-change

Correct the Agents SDK span attribute and conversation ID claims

Description

docs/platforms/javascript/guides/cloudflare/features/agents-sdk.mdx:10 says callable RPC spans carry "the agent class and instance name as attributes". :39 says "The automatic conversation ID defaults to the agent instance name", and :41 builds override guidance on that premise, warning about per-user instances and singletons named "default".

Neither claim holds on develop. packages/cloudflare/src/instrumentations/agents/types.ts:61-70 builds the span attributes from instance._ParentClass?.name alone, setting gen_ai.agent.name to the base agent class; no instance name is attached. The conversation id is a uuid4() minted per instance and persisted to Durable Object storage (types.ts:173, :180), rotated to a fresh uuid4() when message:clear fires (instrumentChatAgentConversation.ts:34-36). types.ts:104 says the instance name is deliberately not used.

What to change

  • Fix :10 to name only the agent class attribute.
  • Rewrite the Conversation IDs section around a generated uuid4 per instance that rotates on chat clear.
  • Replace the "default" / per-user override rationale, which rests on the false premise.

Source: runtime docs audit, item DOC-R13

Status quo. docs/platforms/javascript/guides/cloudflare/features/agents-sdk.mdx:10 says callable RPC spans carry "the agent class and instance name as attributes". Line 39 says "The automatic conversation ID defaults to the **agent instance name**, which is correct when one agent instance is one chat session", and :41 advises overriding it when instances are per-user or a shared singleton like `"default"`.

On develop. packages/cloudflare/src/instrumentations/agents/types.ts:61-70 builds the span attributes from `instance._ParentClass?.name` only, setting `gen_ai.agent.name` to the base agent class; no instance name is attached. The conversation id is a `uuid4()` minted per instance and persisted to DO storage (types.ts:173, :180), rotated to a fresh `uuid4()` on the `message:clear` event (instrumentChatAgentConversation.ts:34-36). types.ts:104 states the instance `name` is deliberately not used.

Work item. Correct :10 to say the span carries the agent class name only. Rewrite the Conversation IDs section: the automatic ID is a generated uuid4 per agent instance that rotates when the chat is cleared, and replace the per-user / `"default"` override rationale, which rests on the false name-based premise.
