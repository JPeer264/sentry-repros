DOC-R13Agents SDK page claims instance-name span attributes and instance-name conversation IDs; neither is trueP0verified in source

Proposed issue docs-change

Correct the Agents SDK span attribute and conversation ID claims

Description

docs/platforms/javascript/guides/cloudflare/agent-tracing/agents-sdk.mdx:11 says callable RPC spans carry "the agent class and instance name as attributes". :43 says "The automatic conversation ID defaults to the agent instance name", and :45 builds override guidance on that premise, warning about per-user instances and singletons named "default".

Neither claim holds on develop. packages/cloudflare/src/instrumentations/agents/types.ts:61-70 builds the span attributes from instance._ParentClass?.name alone, setting gen_ai.agent.name to the base agent class; no instance name is attached. The conversation id is a uuid4() minted per instance and persisted to Durable Object storage (types.ts:173, :180), rotated to a fresh uuid4() when message:clear fires (instrumentChatAgentConversation.ts:34-36). types.ts:104 says the instance name is deliberately not used. Recorded telemetry matches: callable RPC spans arrive with gen_ai.agent.name set to the base class, and conversation ids are hex uuid4 values that change after the chat is cleared.

What to change

  • Fix :11 to name only the agent class attribute.
  • Rewrite the Conversation IDs section around a generated uuid4 per instance that rotates on chat clear.
  • Replace the "default" / per-user override rationale, which rests on the false premise.
  • Check the link into this page from docs/platforms/javascript/guides/cloudflare/features/durableobject.mdx:31; the page moved to agent-tracing/ and nothing else needs moving.
