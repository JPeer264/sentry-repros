Proposed issue docs-change

Show deno add and an import map in the Deno guide's install step

Description

guides/deno/index.mdx:38-46 says to "Import the Sentry Deno SDK directly from the npm registry", and every snippet on the page renders npm:@sentry/deno from the ___SDK_PACKAGE___ placeholder (the literal specifier is not in the file). guides/hono/index.mdx:88-89 is the only page showing deno add npm:@sentry/deno. The Deno featureflags and enable-stream-mode includes hardcode @sentry/deno and npm:@sentry/deno instead of the ___SDK_PACKAGE___ placeholder.

What was observed: every Deno e2e app uses a deno.json import map and the bare @sentry/deno specifier, which is also the form the @sentry/deno/import hook requires. Events reported by the SDK carry sdk.packages[0].name = "denoland:sentry".

What to change:

  • In the install step at guides/deno/index.mdx:38-46, add deno add npm:@sentry/deno and show the resulting deno.json import map entry.
  • Use the bare @sentry/deno specifier in the snippets that follow, since that is the form the hook import needs, and keep npm:@sentry/deno documented as the no-import-map alternative.
  • Replace the hardcoded package names in the Deno featureflags (:2) and enable-stream-mode (:11) includes with ___SDK_PACKAGE___.
  • While in enable-stream-mode/javascript.deno.mdx, note that :24 calls traceLifecycle: 'static' "the default", which holds for the released line only; DOC-Q1 tracks that sentence across all ten runtime variants of the include.
