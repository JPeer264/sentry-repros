Proposed issue docs-change

Correct the Nuxt Nitro preset page for Deno: keep the node-server preset

Description

docs/platforms/javascript/guides/nuxt/features/nitro-deployment-presets.mdx:7 claims that the SDK supports different Nitro deployment presets, "most of which work out of the box", and the 11-line file then documents only Cloudflare Pages at :9-11. The Nuxt guide has no Deno mention anywhere, so a reader picking the deno_server preset gets no warning.

Verified on Nuxt 4 with @sentry/nuxt 10.67.0 and Deno 2.9.0: do not set a Nitro preset. Build the default node-server output with npx nuxt build, keep sentry: { autoInjectServerSentry: 'top-level-import' } in nuxt.config.ts and a root sentry.server.config.ts that calls Sentry.init(), then run the output under Deno with cd .output/server && PORT=<port> deno run --allow-net --allow-read --allow-write --allow-env --allow-sys --allow-ffi --unstable-byonm ./index.mjs. Nitro's node-server entry uses node:http, which the SDK instruments on Deno. For outgoing requests, add winterCGFetchIntegration() from @sentry/vercel-edge to Sentry.init.

Works today:

  • Errors from nitro route handlers, with request data and source context.
  • Parameterized GET /api/users/:id with source route.
  • Per-request isolation and incoming trace continuation.
  • http.client spans and sentry-trace/baggage on fetch and nitro's $fetch, with the integration above.
  • Logs.

Known limits:

  • With nitro: { preset: 'deno_server' } there is no request instrumentation at all: no http.server spans, getActiveSpan() is undefined in handlers, every request shares one isolation scope and one trace id so tags and users leak, and incoming trace headers are ignored.
  • Outgoing fetch is not instrumented on Deno without the integration above.

What to change:

  • guides/nuxt/features/nitro-deployment-presets.mdx:7: qualify the "work out of the box" claim; add a Deno section next to Cloudflare Pages at :9 with the run command and the deno_server warning.
  • Cross-link a Deno framework page for Nuxt.

The presets page must stop implying that every non-Cloudflare preset works out of the box and must add a Deno section saying the opposite for `deno_server`: with `nitro: { preset: 'deno_server' }` there is no request instrumentation — route names are not parameterized, every request shares one isolation scope and one trace id (so tags, users and breadcrumbs leak between requests), and incoming `sentry-trace`/`baggage` headers are not continued. The verified guidance is: do not set a Nitro preset on Deno. Keep the default `node-server` preset (`npx nuxt build`) and run the produced Node output under Deno with `cd .output/server && PORT=<port> deno run --allow-net --allow-read --allow-write --allow-env --allow-sys --allow-ffi --unstable-byonm ./index.mjs`, with `sentry: { autoInjectServerSentry: 'top-level-import' }`; that restores route names, incoming trace continuation, per-request isolation and route-level errors with request data. The page must also cover the two remaining Deno gaps: (a) outgoing requests made with `fetch` or nitro's `$fetch` get no `http.client` span and no `sentry-trace`/`baggage` headers because Deno's fetch is not backed by `node:http`/undici — add `winterCGFetchIntegration()` from `@sentry/vercel-edge` in `sentry.server.config.ts` (and `traceLifecycle: 'stream'` in the verified configuration); (b) if `deno_server` is used anyway, database drivers must stay bundled — the verified config is `nitro: { preset: 'deno_server', externals: { inline: ['generate-function', 'named-placeholders'], external: ['mysql'] } }`, because externalizing a driver routes it through Deno's module hook where `require()` of a JSON file fails. Errors and logs work in all cases.

Where the docs stand: docs/platforms/javascript/guides/nuxt/features/nitro-deployment-presets.mdx:7 claims "The Sentry Nuxt SDK provides support for different Nitro deployment presets, most of which **work out of the box**" and the 11-line file then documents only Cloudflare Pages (:9-11) — the run contradicts this for the `deno_server` preset, which produced no request instrumentation at all; docs/platforms/javascript/guides/nuxt/install/cli-import.mdx:33 prescribes `node --import ./.output/server/sentry.server.config.mjs .output/server/index.mjs`, a Node-only start command; `grep -rni deno docs/platforms/javascript/guides/nuxt/` returns 0 hits and `grep -rniE "nuxt|nitro" docs/platforms/javascript/guides/deno/` returns 0 hits
