DOC-Q68The Mastra agent-tracing page lists attributes the exporter does not emit, and neither page names the defaults or the trace shapeP2proven

Proposed issue docs-change

Correct the attribute list, the defaults and the trace shape on the Mastra pages

Description

common/agent-tracing/mastra.mdx:140-172 lists gen_ai.system, gen_ai.request.messages, gen_ai.request.temperature, gen_ai.tool.type function, gen_ai.tool.input, gen_ai.tool.output and gen_ai.agent.instructions. The build sends gen_ai.provider.name, gen_ai.input.messages and gen_ai.output.messages, gen_ai.tool.type tool, gen_ai.tool.call.arguments and gen_ai.tool.call.result, and gen_ai.system_instructions; no temperature; and gen_ai.request.stream is true for non-streaming calls. guides/mastra/index.mdx:83 and agent-tracing/mastra.mdx:61 say the exporter reads SENTRY_ENVIRONMENT and SENTRY_RELEASE; when unset it passes environment production and release '', and the empty release makes the SDK discard every session with a warning.

Two things about the trace neither page says: the model's HTTP calls arrive as separate http.client root segments (auto.http.node_fetch) in the same trace, not as children of gen_ai.chat; and on the built-in route each tool call yields two gen_ai.execute_tool spans (one under the agent span from client_tool_call, one under the chat span), so tool counts double.

What to change:

  • Replace the attribute list with the names the exporter emits, name the defaults and tell users to set SENTRY_RELEASE, and describe the trace shape.

Source: runtime docs audit, item DOC-Q68, quick start QS-mastra, variants guide, explicit, env-only and sdk-only

What ran: Mastra getting-started reproduction on 2026-09-09, develop 03aaf42455 (@sentry/node 10.67.0, 46 integrations including Mastra), @mastra/core with @mastra/sentry 1.2.16 and a local mock model endpoint, Node 26.5.0: quickstarts/mastra, results-*.json per variant.

SDK-side note. The built-in integration maps client_tool_call to gen_ai.execute_tool as well, and the exporter reports gen_ai.request.stream: true for non-streaming calls; both are SDK-side.
