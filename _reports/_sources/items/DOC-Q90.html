Replace the --import instructions on the Nuxt manual-setup and cli-import pages with the bundled server config

Description

platform-includes/getting-started-complete/javascript.nuxt.mdx:237-247 and :510-514 say server-side monitoring only works after building and starting with node --import ./.output/server/sentry.server.config.mjs .output/server/index.mjs, and guides/nuxt/install/cli-import.mdx:1-68 with install/index.mdx:7-12 present the flag as the default and crucial method. On develop a plain node .output/server/index.mjs initializes the server SDK: the build log prints Bundled sentry.server.config.ts into the Nitro server build ... no node --import preload needed, and the run delivered 46 integrations, seven server events with auto.function.nuxt.nitro and sixteen route-named span envelopes. The file the docs preload is a four-line shim whose only effect is the console line The --import flag for the Sentry server config is no longer needed and should be removed. The SDK team confirmed on 2026-09-09 that Nuxt no longer emits the server config into the build (DOC-Q85).

What to change:

  • Replace the --import instructions with: build, then start normally, the server config is bundled and initializes at startup; rewrite cli-import.mdx and install/index.mdx as a legacy note that says the shim only warns.
