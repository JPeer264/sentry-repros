DOC-F51SolidStart on Cloudflare: documented noP1proven

Proposed issue new-page

Add a SolidStart on Cloudflare Workers page wiring the Nitro output with withSentry

Description

Nothing documents this combination in either direction. grep -rn -i cloudflare docs/platforms/javascript/guides/solidstart/ returns zero hits across index.mdx, install/, features/ and profiling/. docs/platforms/javascript/guides/cloudflare/frameworks/ has no solidstart.mdx and the framework list at docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 omits SolidStart. The generic Workers entry pattern the run relied on is documented only at guides/cloudflare/index.mdx:111, with no SolidStart context.

Verified on the develop line: SolidStart 1.3 with the cloudflare-module Nitro preset, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"]. @sentry/solidstart itself does not run on Workers, so keep it for the browser and wire the server side by hand: set server: { preset: 'cloudflare-module', rollupConfig: { external: ['@sentry/cloudflare'] } } in app.config.ts so Nitro does not inline a second SDK copy, then write a worker.mjs that wraps the built Nitro handler with Sentry.withSentry() from @sentry/cloudflare and point wrangler's main at that wrapper. Add a Nitro server plugin registered through server.plugins that forwards Nitro's error hook to Sentry.captureException, otherwise thrown server errors never become events.

Works today:

  • Server errors through the Nitro error hook, per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, Sentry.logger logs, and browser errors with Sentry.init from @sentry/solidstart in src/entry-client.tsx.

Known limits:

  • Server transactions are named from the request URL with source url, never the file-route pattern; there is no Sentry SolidStart router integration on this runtime.
  • There is no server-to-client trace continuation: nothing injects a sentry-trace meta tag into the SSR HTML.
  • Database spans were not exercised, and no Sentry database instrumentation path exists for this vinxi/Nitro/rollup build shape.

What to change:

  • Add docs/platforms/javascript/guides/cloudflare/frameworks/solidstart.mdx with the wiring above and the limits.
  • Link it from guides/cloudflare/index.mdx:16-23 and from guides/solidstart/index.mdx.

Page: docs/platforms/javascript/guides/cloudflare/frameworks/solidstart.mdx (new), linked from docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 and from docs/platforms/javascript/guides/solidstart/index.mdx

A page must exist and must open by stating that `@sentry/solidstart` itself does not run on Workers — its server entry initializes the Node SDK, and there is no `@sentry/solidstart/cloudflare` export or Cloudflare code path — so the runtime is wired by hand: keep `@sentry/solidstart` for the browser and wrap the built Nitro handler with `Sentry.withSentry` from `@sentry/cloudflare` in your own `worker.mjs`, keeping `@sentry/cloudflare` external via `server.rollupConfig` so Nitro does not inline a second copy. It must then document the two capabilities that need extra work beyond that wrapper. (1) Server errors are not captured by the wrapper alone: add a Nitro server plugin that forwards Nitro's `error` hook to `Sentry.captureException` and register it with `server.plugins: ['./src/server-plugin.ts']` in `app.config.ts`. (2) Route names are wrong: add `src/middleware.ts` (registered via `middleware: './src/middleware.ts'` in `app.config.ts`) that builds a radix3 router from vinxi's route manifest and renames the Cloudflare root span per request using `getActiveSpan`/`getRootSpan`/`spanToJSON` and the segment-name-source attribute. With those in place isolation, incoming trace continuation, outgoing fetch, logs and client-side errors all work; database spans were not exercised.

Where the docs stand: No page mentions this combination in either direction. `grep -rn -i cloudflare docs/platforms/javascript/guides/solidstart/` returns zero hits across index.mdx, install/, features/ and profiling/. `ls docs/platforms/javascript/guides/cloudflare/frameworks/` contains astro, hono, hydrogen-react-router, hydrogen-remix, nextjs, nuxt, remix, sveltekit and tanstack-start — there is no solidstart.mdx — and the framework list at docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 omits SolidStart. SolidStart appears in the docs only inside PlatformSection exclusion lists, for example docs/platforms/javascript/common/tracing/streamed-spans/index.mdx:76 and docs/platforms/javascript/common/index.mdx:31. The generic Cloudflare `withSentry` entry pattern the run relied on is documented only at docs/platforms/javascript/guides/cloudflare/index.mdx:111 ("Setup for Cloudflare Workers"), with no SolidStart context.

What ran: SolidStart 1.3 (vinxi 0.5 + Nitro, `cloudflare-module` preset) on Cloudflare Workers (workerd via wrangler 4.129.0 dev, compatibility_date 2026-05-01, nodejs_compat). Cell record.
