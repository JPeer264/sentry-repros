Description

Neither guide covers the pair: grep -rn -i hapi docs/platforms/javascript/guides/deno/ and grep -rn -i deno docs/platforms/javascript/guides/hapi/ both return nothing. docs/platforms/javascript/guides/hapi/index.mdx:4-5 declares sdk: sentry.javascript.node with fallbackGuide: javascript.node and :12 is a bare getting-started-node include. docs/platforms/javascript/guides/deno/index.mdx:1-232 covers error monitoring and tracing only, and never mentions node_modules, nodeModulesDir or the import hook.

Verified on @hapi/hapi and Deno 2.9.0: npm install @hapi/hapi plus @sentry/deno into a real on-disk node_modules, deno.json with {"nodeModulesDir": "manual"} and an imports map, and Sentry.init() from @sentry/deno before the server is created. Two shapes were verified. Bundle the app with esbuild and sentryOrchestrionPlugin() from @sentry/server-utils/orchestrion/esbuild (bundle: true, platform: 'node', format: 'esm', external: ['@sentry/deno','@sentry/server-utils'], createRequire banner) and run deno run --allow-net --allow-env --allow-read --allow-sys dist/main.js, which also yields parameterized route names and Hapi and database spans. Or keep deno run main.ts and call attachHapiErrorHandler(server) from @sentry/server-utils after creating the server.

Works today:

  • Route errors, mechanism auto.function.hapi, in both shapes above.
  • GET /users/{id} with source route, from the bundled build.
  • Per-request isolation and incoming trace continuation, with or without a build step.
  • Database spans for mysql, and logs.

Known limits:

  • Running the entry directly with Sentry.init() alone loses Hapi errors, because Hapi turns the throw into a Boom 500, and names transactions GET /users/42 with source url.
  • Outgoing fetch() is not instrumented; node:http/node:https requests are.

What to change:

  • Add docs/platforms/javascript/guides/deno/frameworks/hapi.mdx with both setups side by side and the limits.

Page: guides/deno/frameworks/hapi.mdx (new), covering the esbuild/orchestrion route and the import-hook + JSON-load-hook route side by side

A Hapi-on-Deno page must exist and must distinguish what needs the import hook from what does not. It must say: setup is `npm install @hapi/hapi` plus `@sentry/deno` into a real on-disk `node_modules` with `deno.json` `{"nodeModulesDir": "manual"}`. Error capture does NOT require the `@sentry/deno/import` runtime hook — either bundle the app with esbuild and `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild` (`bundle: true, platform: 'node', format: 'esm', external: ['@sentry/deno','@sentry/server-utils']`, plus a `createRequire` banner), which additionally yields parameterized route names and Hapi/database spans, or run the entry directly with plain `Sentry.init`. Parameterized transaction names (`GET /users/{id}` with `sentry.segment.name.source: 'route'` and a nested `router` span) do require `import "@sentry/deno/import"` as the first line of the entry file (or `--import=./node_modules/@sentry/deno/build/import.mjs`), and until the SDK tags JSON modules itself, they also require a JSON load hook registered before Hapi is imported: `Module.registerHooks({ load(url, ctx, next) { const r = next(url, ctx); return url.endsWith('.json') ? { ...r, format: 'json' } : r; } })`. Isolation, incoming trace continuation, database spans and logs work with no caveat. Outgoing `fetch` is not instrumented: no `http.client` span and no `sentry-trace`/`baggage` headers, independent of framework and of `traceLifecycle`; the page must ship a userland fetch integration (`addFetchInstrumentationHandler`, `defineIntegration`, `getClient`, `instrumentFetchRequest`, `isSentryRequestUrl`, `LRUMap`, `shouldPropagateTraceForUrl` from `@sentry/core`) which was verified to restore both spans and headers with the hook on and off, and note that `node:http` requests are traced normally.

Where the docs stand: `grep -rn -i hapi docs/platforms/javascript/guides/deno/` returns nothing (that directory holds only index.mdx and configuration/integrations/{breadcrumbs,contextlines}.mdx) and `grep -rn -i deno docs/platforms/javascript/guides/hapi/` returns nothing; docs/platforms/javascript/guides/hapi/index.mdx:4-5 declares `sdk: sentry.javascript.node` / `fallbackGuide: javascript.node` with a bare `getting-started-node` body at :12; docs/platforms/javascript/guides/deno/index.mdx:1-232 covers error monitoring and tracing only and never mentions `node_modules`, `nodeModulesDir`, or the `@sentry/deno/import` hook
