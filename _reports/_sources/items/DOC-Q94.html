Description

sentryHandle() (getting-started-complete/javascript.sveltekit.mdx:283) defaults handleUnknownRoutes to false to reduce noise, yet with the page's tracing.server: true every unrouted request (/nope, /favicon.ico) still produced a streamed segment named sveltekit.handle.root with a 404 child. The server segment of the throwing route (:530-540) has status ok and no status code although the response was 500; only the sveltekit.resolve child carries the 500. configuration/build/index.mdx:69-71 says the SDK auto-instruments load functions with a Vite plugin because Kit offers no hook; on Kit 2.70 with server tracing the server load span is Kit's own (sveltekit.load, origin auto.function.sveltekit.load) and only the universal client load span comes from the plugin. :134-135 and :250-251 say 100% of transactions; no transaction item was sent. :7-8 require Vite 4.2 or newer, while the current Kit 2 peers Vite 5 through 8. :357-372 say the plugin uploads source maps; without a token every build prints the telemetry notice and two will-not-upload warnings, and still injects the git HEAD sha as the release on every envelope.

What to change:

  • Note the unknown-route root span, the segment status on throwing routes, rewrite the load rationale for Kit 2.31 and later, say spans instead of transactions, state the Vite majors the current Kit accepts, and mention the warnings and the injected release in the Configure Vite step.
