Description

guides/nuxt/install/limited-server-tracing.mdx:27-38 and install/dynamic-import.mdx:9-13, :55-77, :86-95 document autoInjectServerSentry (top-level-import, experimental_dynamic-import) and experimental_entrypointWrappedFunctions as current options and say the dynamic import does not work with recent Nuxt or Nitro; both options are @deprecated in the shipped types, every build with them prints a deprecation warning, and both still work on Nuxt 4.5.2 with nitropack 2.13.4. platform-includes/getting-started-prerequisites/javascript.nuxt.mdx:7 says Nuxt 3.7.0 or above; the peer range covers 3.7, 4.x and 5.x, and the registry gives a new user 4.5.2. getting-started-complete/javascript.nuxt.mdx:118-119 and :188-189 say 100% of transactions; every span arrives as a span item. The option buttons (:12-19) offer no logs option, so the logs verify block at :497-501 never renders although the logger lines produced log envelopes on both sides. The Throw Server Error button (:459-489) also creates a client-side FetchError: [GET] "/api/sentry-example": 500 issue, because the awaited $fetch has no catch, and ofetch retries the GET once, so two server events arrive per click. Server segments for static routes are named GET with the path in url.path; only parameterized routes and requests with a query string get a route name.

What to change:

  • Mark both inject pages as deprecated legacy modes and drop the stale alert, name Nuxt 4 and 5 in the prerequisites, say spans instead of transactions, add the logs option, catch the $fetch rejection in the verify snippet or mention the extra issue and the retry, and document the static-route naming.
