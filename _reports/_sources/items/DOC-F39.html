Add a Koa on Cloudflare Workers page covering the Vite build and module-scope rule

Description

Nothing documents Koa on Workers. docs/platforms/javascript/guides/koa/index.mdx:1-12 is a 12-line stub declaring sdk: sentry.javascript.node with fallbackGuide: javascript.node, and grepping it for "cloudflare" or "workerd" returns nothing. grep -rin koa docs/platforms/javascript/guides/cloudflare/ returns nothing, guides/cloudflare/frameworks/ has no koa.mdx, the framework list at guides/cloudflare/index.mdx:16-23 omits Koa, and httpServerHandler and enable_nodejs_http_server_modules appear nowhere in the docs.

Verified on the develop line: npm install @sentry/cloudflare koa @koa/router plus vite and @cloudflare/vite-plugin for the build. Koa 3 with @koa/router on workerd, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat", "enable_nodejs_http_server_modules"], served through httpServerHandler from cloudflare:node and wrapped with Sentry.withSentry() from @sentry/cloudflare. Build with Vite: plugins: [cloudflare(), sentryCloudflareVitePlugin()] from @sentry/cloudflare/vite at its defaults, then vite build and run wrangler against the emitted config. httpServerHandler({ port: 8080 }) stays at module scope; new Koa(), every app.use(), the router wiring and app.listen() must run inside fetch, behind a memoized promise. The plugin registers the Koa error listener itself, so no hand-written app.on('error') is needed on this build.

On a plain wrangler build, where none of that instrumentation exists, two app-side lines keep the Worker from being silent: app.on('error', err => Sentry.captureException(err)), Koa's own idiom, and inside a handler Sentry.updateSpanName(Sentry.getRootSpan(Sentry.getActiveSpan()), `${ctx.method} ${ctx._matchedRoute}`), all four exports from @sentry/cloudflare. That yields a captured error and a route-shaped name with source custom rather than route.

Works today:

  • Vite build: unhandled errors captured automatically (mechanism auto.middleware.koa, handled: false, from the error listener the Koa integration attaches), parameterized route names with http.route, per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, db spans from mysql2 or mysql 2.x, Sentry.logger logs.
  • Plain wrangler build: isolation, incoming trace continuation, outgoing fetch spans and logs unaided; errors and a custom-source route name with the two app-side lines above.

Known limits:

  • Without the Vite build there is no Koa instrumentation at all: unless you add the two lines above, errors are swallowed with no event and the transaction is named from the raw URL (GET /users/42, source url).
  • The manual rename gives source custom, not route, and no database spans exist on a plain wrangler build.
  • Creating the Koa app at module scope makes the Worker fail to start with "Disallowed operation called within global scope".
  • mysql2 on workerd needs disableEval: true in the connection options.

What to change:

  • Add docs/platforms/javascript/guides/cloudflare/frameworks/koa.mdx with the wiring above and link it from guides/cloudflare/index.mdx:16-23.
  • Add the module-scope rule as a shared note on guides/cloudflare/features/vite-plugin.mdx.
  • Include the plain-wrangler fallback on the new page, so readers who cannot build with Vite still get errors and a usable transaction name.

A page must say that Koa 3 with @koa/router runs unchanged on workerd once the Node HTTP server flag is set and the server is served through httpServerHandler. Error capture and route names come for free only when the Worker is built with Vite and the Sentry Cloudflare plugin, which injects Koa's diagnostics channels at build time and attaches the app error listener for you (mechanism auto.middleware.koa, handled: false); on a plain wrangler build nothing of Koa is instrumented, and the page must give the fallback: app.on('error', err => Sentry.captureException(err)) plus Sentry.updateSpanName(Sentry.getRootSpan(Sentry.getActiveSpan()), `${ctx.method} ${ctx._matchedRoute}`) from @sentry/cloudflare, which names the root span with source custom rather than route and still leaves database spans out. It must state the module-scope rule that follows: the Koa app, every use call and listen must run inside the fetch handler, because the instrumented use starts a span at worker startup and workerd rejects it; the httpServerHandler call may stay at module scope. Database spans need the same lazy construction plus the plugin, with mysql2 or mysql 2.x. Isolation, incoming trace, outgoing fetch and logs work unaided on either build. The page should also give the install line: @sentry/cloudflare, koa and @koa/router, plus vite and @cloudflare/vite-plugin.

Where the docs stand: guides/koa/index.mdx:1-12 (12-line stub, Node fallback, body is one include); guides/cloudflare/index.mdx:16-23 (no Koa) and no koa.mdx under guides/cloudflare/frameworks/; grep for httpServerHandler and enable_nodejs_http_server_modules returns zero; guides/cloudflare/features/vite-plugin.mdx:40-44 versus packages/cloudflare/src/vite/index.ts:37,87.
