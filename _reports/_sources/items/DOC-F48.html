DOC-F48React Router on Cloudflare: documented noP1proven

Proposed issue new-page

Add a React Router 7 on Cloudflare Workers page

Description

No page documents React Router framework mode on Workers. docs/platforms/javascript/guides/react-router/ holds only index.mdx, manual-setup.mdx and profiling/, and a case-insensitive grep for "cloudflare" across it returns zero hits. In the other direction, docs/platforms/javascript/guides/cloudflare/frameworks/ has no react-router.mdx and the framework list at docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 omits React Router. The nearest page, guides/cloudflare/frameworks/hydrogen-react-router.mdx:186-215, is Shopify Oxygen-specific and prescribes different wiring.

Verified on the develop line: React Router 7.18 in framework mode with SSR, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"]. Install @sentry/react-router and @sentry/cloudflare (a separate install), and pin @react-router/node to ^7 next to react-router 7: nothing on Workers uses it, but @sentry/react-router's peer range otherwise makes npm hoist 8.3.1 and the install aborts with ERESOLVE. react-router.config.ts needs ssr: true and future: { v8_viteEnvironmentApi: true }, without which the build dies in [commonjs--resolver] with id.endsWith is not a function, a message that names neither plugin. vite.config.ts combines cloudflare({ viteEnvironment: { name: 'ssr' } }), reactRouter() and sentryCloudflareVitePlugin() from @sentry/cloudflare/vite. app/entry.server.tsx exports a handleError that calls Sentry.captureException, written by hand because createSentryHandleError lives only on the node entry: @sentry/react-router/cloudflare re-exports ../client, wrapSentryHandleRequest and injectTraceMetaTags and nothing else. wrapSentryHandleRequest supplies the route names, and injectTraceMetaTags is what hands the browser its trace.

Works today:

  • Loader errors, parameterized route names (GET /users/:id, source route), per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, db spans from mysql through the Vite plugin's build-time instrumentation, Sentry.logger logs.

Known limits:

  • Without the hand-written handleError export, React Router routes the throw into the ErrorBoundary and no event is sent; createSentryHandleError is not available on the Cloudflare entry.
  • Building with sentryCloudflareVitePlugin({ buildTimeInstrumentation: false }) removes all database spans.
  • mysql 2.x is the driver this ran on; mysql2 queries fail on workerd unless you pass disableEval: true in the connection options, which this cell did not exercise.
  • Only the server runtime was exercised; the client half of @sentry/react-router was not part of this run.

What to change:

  • Add docs/platforms/javascript/guides/cloudflare/frameworks/react-router.mdx with the package set, wrangler config, Vite configuration and worker entry above.
  • Add React Router to the framework list at guides/cloudflare/index.mdx:16-23 and a Cloudflare pointer to guides/react-router/index.mdx.

Source: runtime docs audit, item DOC-F48, cell M-reactrouter-cf

Page: docs/platforms/javascript/guides/cloudflare/frameworks/react-router.mdx (new), linked from docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 and from docs/platforms/javascript/guides/react-router/index.mdx

A page must exist for React Router 7 framework mode (SSR) on Cloudflare Workers built with `@cloudflare/vite-plugin`, and it must state that all seven exercised capabilities work — errors, route names, request isolation, incoming trace continuation, outgoing fetch spans, database spans and logs — once the entry exports a hand-written `handleError`, because `createSentryHandleError` exists only on the node entry and `@sentry/react-router/cloudflare` does not re-export it. It must give the package set (`@sentry/react-router` plus `@sentry/cloudflare`, a separate install, plus a `@react-router/node@^7` pin, or npm hoists 8.3.1 and the install aborts with ERESOLVE), the `wrangler` config (`nodejs_compat`, compatibility_date `2026-05-01`), the worker entry wiring, and the Vite configuration combining `@cloudflare/vite-plugin` with the React Router dev plugin plus `future: { v8_viteEnvironmentApi: true }`, without which the build fails with `[commonjs--resolver] id.endsWith is not a function`. Only the server runtime was exercised, so the client half is unclaimed. It must also be reachable: add React Router to the framework list on the Cloudflare index and add a Cloudflare pointer to the React Router guide, which currently never mentions the runtime.

Where the docs stand: No page covers this combination. `ls docs/platforms/javascript/guides/react-router/` yields only index.mdx, manual-setup.mdx and profiling/, and `grep -rn -i cloudflare docs/platforms/javascript/guides/react-router/` returns zero hits — the guide is Node-only. In the other direction, docs/platforms/javascript/guides/cloudflare/frameworks/ contains astro.mdx, hono.mdx, hydrogen-react-router.mdx, hydrogen-remix.mdx, nextjs.mdx, nuxt.mdx, remix.mdx, sveltekit.mdx and tanstack-start.mdx — there is no react-router.mdx, and the framework list at docs/platforms/javascript/guides/cloudflare/index.mdx:16-23 omits React Router entirely. The nearest page, docs/platforms/javascript/guides/cloudflare/frameworks/hydrogen-react-router.mdx:186-215, is Shopify Oxygen-specific and prescribes `wrapRequestHandler` from `@sentry/cloudflare/request` at :187, which is not the wiring that worked here.

What ran: React Router 7.18.3 (framework mode, SSR) with @react-router/dev 7.18.3, vite 7.3.6, @cloudflare/vite-plugin 1.54.4 on Cloudflare Workers (wrangler 4.129.0 / workerd 1.20260903.1, local `wrangler dev`), compatibility_date 2026-05-01, nodejs_compat. Cell record: M-reactrouter-cf.
