DOC-Q11The verify flow discards the session replay when the error fires within the first five secondsP2proven

Proposed issue docs-change

Tell browser readers to wait before triggering the verify error if they expect a replay

Description

platform-includes/getting-started-config/javascript.mdx:50-55 sets replaysOnErrorSampleRate: 1.0 and says that the replay is captured for every session with an error; the verify step tells the reader to click the button.

Observed on develop, clicking the button right after load: the error event carries a replayId tag, and the replay is dropped with [Replay] Session duration (0s) is too short, not sending replay. An error thrown later in the same session produced the replay_event with replay_type: buffer.

What to change:

  • Add one sentence to the verify step: a replay is sent only when the session is at least five seconds old (minReplayDuration), so wait before clicking, and the issue will still show a replay id before the replay exists.
