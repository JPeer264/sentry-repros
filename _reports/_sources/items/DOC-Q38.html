Move shouldHandleError to fastifyIntegration on the Fastify error handler page

Description

guides/fastify/features/error-handler.mdx:29-48 passes { shouldHandleError(error, request, reply) } to setupFastifyErrorHandler(app, ...). On develop the function is a deprecated one-parameter no-op: the options object is ignored, the callback never ran and /error-404 stayed uncaptured. fastifyIntegration({ shouldHandleError }) works, ran the callback four times with the final status codes on Fastify 5, and captured the 404.

What to change:

  • Document shouldHandleError on fastifyIntegration({ ... }) and mark setupFastifyErrorHandler(app) as a deprecated no-op.
