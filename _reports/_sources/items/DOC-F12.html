DOC-F12SvelteKit on Bun: documented noP1proven

Proposed issue new-page

Add a SvelteKit on Bun page for the adapter-node output

Description

The SvelteKit guide states that Bun is unsupported: docs/platforms/javascript/guides/sveltekit/index.mdx:5-9 categorises it as server-node, and the adapter box at platform-includes/getting-started-complete/javascript.sveltekit.mdx:36-48 heads its list "Fully supported Node.js runtimes" (:39), lists adapter-node at :42, and then says at :45-46 "Currently not supported - Non-Node.js server runtimes ... are not yet supported".

Verified on SvelteKit 2.70.3 with @sveltejs/adapter-node and @sentry/sveltekit 10.67.0 (develop, 6f2da7483d) on Bun 1.4.0 and re-run on 1.4.2: sentrySvelteKit() first in the Vite plugin list, imported from @sentry/sveltekit/vite — the bare @sentry/sveltekit import fails hard with "does not provide an export named sentrySvelteKit". The sveltekit() plugin needs experimental: { instrumentation: { server: true }, tracing: { server: true } }; without those options no transaction or span envelope is emitted at all, on Node as well as Bun, while errors still arrive. In src/hooks.server.ts export both handleErrorWithSentry and export const handle = Sentry.sentryHandle();, the latter being what renames and re-attributes the root span. Put Sentry.init in src/instrumentation.server.ts, run vite build, then bun build/index.js. Install @sentry/bun alongside @sentry/sveltekit and pass its fetchIntegration() into Sentry.init, gated with typeof globalThis.Bun !== 'undefined' so Node builds do not get a duplicate span. Database spans need one more line in the same file, a workaround for a Bun bug: import 'mysql2/promise'; next to the Sentry.init call. Bun drops a node:diagnostics_channel subscription once the channel object becomes unreachable, so a driver that first loads after Sentry.init() publishes to fresh, unsubscribed channels; importing it in the same file keeps the channels reachable.

Works today:

  • Unhandled server-route errors with source context lines
  • Route names GET /api/users/[id] with source route and http.route
  • Per-request isolation across concurrent requests
  • Incoming sentry-trace/baggage continuation, plus the SSR meta tags for the browser
  • Outgoing fetch spans and propagation headers, with fetchIntegration() added
  • mysql2 database spans, with the driver imported in src/instrumentation.server.ts
  • Sentry.logger log envelopes

Known limits:

  • A route that answers 500 still reports status: "ok" on its http.server span once kit tracing is on.
  • contexts.runtime.name is node on Bun, so Bun events cannot be told apart from Node ones in Sentry.
  • SvelteKit 2.70 has no svelte.config.js; the kit config, including the adapter swap, lives inside the sveltekit() Vite plugin.
  • Browser-side capture was not exercised; this run drove the server through curl only.

What to change:

  • New page docs/platforms/javascript/guides/bun/frameworks/sveltekit.mdx: the adapter-node build, bun build/index.js, the runtime-gated fetchIntegration(), the driver import, the config-location note and the capability list.
  • platform-includes/getting-started-complete/javascript.sveltekit.mdx:36-48: name Bun in the adapter and runtime compatibility box, and correct :45-46, which currently rules out non-Node server runtimes outright.
  • platform-includes/getting-started-complete/javascript.sveltekit.mdx:365, :403, :458: the plugin import path is @sentry/sveltekit/vite, not the package root. This is runtime-independent and breaks the documented setup on Node too.
  • platform-includes/getting-started-complete/javascript.sveltekit.mdx:219-225: the "SvelteKit 3" tab writes sveltekit({ tracing: { server: true } }) at :223 where kit 2.70.3 needs the experimental wrapper and the instrumentation option beside it.

Source: runtime docs audit, item DOC-F12, cell M-sveltekit-bun

Page: docs/platforms/javascript/guides/bun/frameworks/sveltekit.mdx (new); and correct the adapter/runtime compatibility box at platform-includes/getting-started-complete/javascript.sveltekit.mdx:36-48

A page must say the `@sveltejs/adapter-node` build output runs on Bun as `bun build/index.js`, that errors, route names, request isolation, incoming trace continuation and logs work there unchanged, and name the two capabilities that need an extra line. Outgoing `fetch()` from server routes gets no `http.client` span and carries no `sentry-trace`/`baggage` headers, because `@sentry/sveltekit`'s server side is `@sentry/node` and its fetch instrumentation relies on Node's undici diagnostics channel, which Bun does not emit; install `@sentry/bun` alongside `@sentry/sveltekit` and pass its `fetchIntegration()` into `Sentry.init` in `src/instrumentation.server.ts`, gated on the runtime so Node builds do not get a duplicate span. Database spans are absent because Bun drops a `node:diagnostics_channel` subscription once the channel object is garbage collected, so a driver first imported inside a lazily loaded route chunk is never instrumented; the recorded workaround for that Bun bug is to import the driver in the same file as `Sentry.init()` (`import 'mysql2/promise';`), or to hold the channels on `globalThis`. The page must also carry the two setup elements the guide gets wrong for every runtime, since a reader who copies them gets no spans at all: `sentrySvelteKit` is exported from `@sentry/sveltekit/vite`, not from the package root, and the `sveltekit()` plugin needs `experimental: { instrumentation: { server: true }, tracing: { server: true } }`. Finally it should note that SvelteKit 2.70 has no `svelte.config.js` — kit config lives inside the `sveltekit()` Vite plugin — since the adapter swap is part of the setup.

Where the docs stand: docs/platforms/javascript/guides/sveltekit/index.mdx:5-9 (`categories: [javascript, browser, server, server-node]`); platform-includes/getting-started-complete/javascript.sveltekit.mdx:36 ("designed to work out of the box with several SvelteKit adapters and their underlying server runtimes"), :39 ("**Fully supported Node.js runtimes**"), :42 (Adapter-node), :45-46 ("Currently not supported - Non-Node.js server runtimes ... are not yet supported"); javascript.sveltekit.mdx:219-225 (the "SvelteKit 3" tab) and :365, :403, :458 (the plugin import). `grep -i bun` across guides/sveltekit/ and that include returns nothing.

What ran: SvelteKit 2.70.3 (svelte 5, `sv create` minimal template, `@sveltejs/adapter-node` 5.x, vite 8 / rolldown) with `@sentry/sveltekit` 10.67.0 (develop, 6f2da7483d) on Bun 1.4.0 and re-run on 1.4.2, running the adapter-node server output (`bun build/index.js`); node v26.5.0 used only as a control on the identical build. `@sentry/bun` is not in the cell's package.json and enters through verify4-M-sveltekit-bun-outgoingfetch (works-after-all); verify4-M-sveltekit-bun-dbspans (works-after-all) supplied the driver import. The SDK-side fix for the channel bug sits in `bindTracingChannelToSpan()` in packages/server-utils/src/tracing-channel.ts. Cell record M-sveltekit-bun.
