DOC-F12SvelteKit on Bun: documented noP1proven

Proposed issue new-page

Add a SvelteKit on Bun page for the adapter-node output

Description

The SvelteKit guide implies Node only: docs/platforms/javascript/guides/sveltekit/index.mdx:5-9 categorises it as server-node, and the adapter box at platform-includes/getting-started-complete/javascript.sveltekit.mdx:36 says the SDK works out of the box with several adapters and their underlying runtimes, listing adapter-node at javascript.sveltekit.mdx:42 with the runtime unqualified. Neither mentions Bun.

Verified on SvelteKit 2.70.3 with @sveltejs/adapter-node and @sentry/sveltekit 10.67.0 on Bun 1.4.0: sentrySvelteKit() first in the Vite plugin list, handleErrorWithSentry in the server hooks, Sentry.init in src/instrumentation.server.ts, vite build, then bun build/index.js. Install @sentry/bun alongside @sentry/sveltekit and pass its fetchIntegration() into Sentry.init, gated with typeof globalThis.Bun !== 'undefined' so Node builds do not get a duplicate span.

Works today:

  • Unhandled server-route errors with source context lines
  • Route names GET /api/users/[id] with source route and http.route
  • Per-request isolation across concurrent requests
  • Incoming sentry-trace/baggage continuation, plus the SSR meta tags for the browser
  • Outgoing fetch spans and propagation headers, with fetchIntegration() added
  • Sentry.logger log envelopes

Known limits:

  • Database spans are not recorded on Bun in this setup.
  • SvelteKit 2.70 has no svelte.config.js; the kit config, including the adapter swap, lives inside the sveltekit() Vite plugin.

What to change:

  • New page docs/platforms/javascript/guides/bun/frameworks/sveltekit.mdx: the adapter-node build, bun build/index.js, the runtime-gated fetchIntegration(), the config-location note and the capability list.
  • platform-includes/getting-started-complete/javascript.sveltekit.mdx:36-48: name Bun in the adapter and runtime compatibility box.

Source: runtime docs audit, item DOC-F12, cell M-sveltekit-bun

Page: docs/platforms/javascript/guides/bun/frameworks/sveltekit.mdx (new); and add Bun to the adapter/runtime compatibility box at platform-includes/getting-started-complete/javascript.sveltekit.mdx:36-48

A page must say the `@sveltejs/adapter-node` build output runs on Bun 1.4.0 as `bun build/index.js`, that errors, route names, request isolation, incoming trace continuation and logs work there unchanged, and name the two capabilities that do not. Outgoing `fetch()` from server routes gets no `http.client` span and carries no `sentry-trace`/`baggage` headers, because `@sentry/sveltekit`'s server side is `@sentry/node` and its fetch instrumentation relies on Node's undici diagnostics channel, which Bun does not emit; install `@sentry/bun` alongside `@sentry/sveltekit` and pass its `fetchIntegration()` into `Sentry.init` in `src/instrumentation.server.ts`, gated on the runtime so Node builds do not get a duplicate span. Database spans are absent because on Bun `node:diagnostics_channel` drops a channel's subscribers as soon as the channel object is garbage collected, so a driver first imported inside a lazily loaded route chunk is never instrumented; until this is fixed in the SDK, pin the mysql2 tracing channels in `src/instrumentation.server.ts` immediately after `Sentry.init()`. The page should also note that SvelteKit 2.70 has no `svelte.config.js` — kit config lives inside the `sveltekit()` Vite plugin — since the adapter swap is part of the setup.

Where the docs stand: ~/dev/sentry-docs/docs/platforms/javascript/guides/sveltekit/index.mdx:5-9 (`categories: [javascript, browser, server, server-node]`); ~/dev/sentry-docs/platform-includes/getting-started-complete/javascript.sveltekit.mdx:36 ("designed to work out of the box with several SvelteKit adapters and their underlying server runtimes"); javascript.sveltekit.mdx:42 (Adapter-node listed as supported, runtime unqualified). `grep -rin bun` across guides/sveltekit/ and that include returns nothing.

What ran: SvelteKit 2.70.3 (svelte 5, `sv create` minimal template, `@sveltejs/adapter-node` 5.x, vite 8 / rolldown) with `@sentry/sveltekit` 10.67.0 from `develop` on bun 1.4.0 running the adapter-node server output (`bun build/index.js`); node v26.5.0 used only as a control on the identical build.
