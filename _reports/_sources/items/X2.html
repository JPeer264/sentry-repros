Add the per-runtime channel-instrumentation setup to the v10-to-v11 page

Description

common/migration/v10-to-v11/index.mdx covers the Cloudflare changes in detail (:948-993) and has a "Deno Changes" section at :933-939, but it names none of @sentry/bun/plugin, sentryBunPlugin or @sentry/deno/import, and it has no Bun section at all. Its :689 tells the reader "Most setups need no changes.", the same framing as the channel-instrumentation section of the SDK's MIGRATION.md:282-288.

What was observed: on Bun, library and framework spans require a Bun.build with sentryBunPlugin from @sentry/bun/plugin, and are not produced under bun run. On Deno, they require a first-line import '@sentry/deno/import';. On Cloudflare, they require the Vite plugin from @sentry/cloudflare/vite with buildTimeInstrumentation left at its default. Each of these subpaths exists on develop and is exercised by the corresponding e2e apps and integration suites.

What to change:

  • Add a Bun section to common/migration/v10-to-v11/index.mdx with the Bun.build({ plugins: [sentryBunPlugin()] }) step and a sentence that bun run on unbundled source records no library or framework spans.
  • Add the hook paragraph to the Deno section at :933-939: a first-line import '@sentry/deno/import'; before Sentry.init, with the package resolvable from node_modules.
  • Reword :689 so "Most setups need no changes." does not stand for Bun and Deno, and say which runtime needs a build step and which needs an import.
