Add the missing details to the Hono guide: catch-all naming, middleware options, error filter semantics and the node-server dependency

Description

Four things a Node reader hits that the guide does not say. Requests that match no route are named GET /* with http.route: /* and source route, because the sentry() middleware itself matches /*, so every 404 lands in one route-labelled segment. guides/hono/index.mdx:235 says the Node middleware takes no options, while sentry(app, { shouldHandleError }) is accepted on Node and features/error-handler.mdx:52-77 works (a 401 became captured). :362 says exceptions are captured from Hono's onError; capture reads the thrown error's status after next() regardless of onError, so a user onError that rewrites a 401 into a 500 does not make it captured, and Hono's default onError keeps printing every captured error to stderr. @sentry/hono/node imports @hono/node-server/conninfo, so @hono/node-server is required on Node although no install step names it; and :214 runs node --import ./instrument.mjs app.js while the app tab at :264 is named app.ts.

What to change:

  • Mention the GET /* grouping, say "no init options" instead of "no options", state that filtering reads the thrown error's status, name @hono/node-server in the install step, and align the file names.
