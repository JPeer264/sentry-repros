DOC-F13Astro on Bun: documented wrongP0proven

Proposed issue docs-change

Name Bun in the Astro runtime alert and add a Running on Bun section

Description

The runtime alert at docs/platforms/javascript/guides/astro/index.mdx:21-28 says the SDK "currently only works on Node runtimes, such as Node adapter or Vercel with Lambda functions" and that other non-Node runtimes are not supported, which reads as excluding Bun. Nothing under guides/astro/ mentions Bun, and nothing under guides/bun/ mentions Astro.

Verified on Astro 7.3.1 with the @astrojs/node standalone adapter and @sentry/astro 10.67.0 on Bun 1.4.0: the sentry() integration in astro.config.mjs, a root sentry.server.config.mjs guarded with Sentry.isInitialized(), astro build, then bun --preload ./sentry.server.config.mjs dist/server/entry.mjs. The preload is required, because the integration injects the init only into .astro page chunks. Install @sentry/bun and add its fetchIntegration() to the server init, guarded on typeof globalThis.Bun !== 'undefined' so Node deployments of the same build do not double-count.

Works today:

  • Unhandled page and endpoint errors via the Astro request middleware
  • Route names GET /users/[id] with source route and http.route
  • Per-request isolation across concurrent requests
  • Incoming sentry-trace/baggage continuation
  • Outgoing fetch spans and propagation headers, with fetchIntegration() added
  • Sentry.logger log envelopes

Known limits:

  • Database spans are not recorded on Bun in this setup.

What to change:

  • guides/astro/index.mdx:21-28: amend the alert to name Bun as working on the Node adapter output.
  • Add a "Running on Bun" section to that page with the bun --preload ... dist/server/entry.mjs start command, the runtime-gated fetchIntegration(), and the capability list.

Source: runtime docs audit, item DOC-F13, cell M-astro-bun

Page: docs/platforms/javascript/guides/astro/index.mdx:21-28 — amend the runtime alert to name Bun, and add a "Running on Bun" section covering the fetch integration and the diagnostics-channel pinning

The runtime alert tells a reader that a non-Node runtime is unsupported, but Astro 7.3.1's `@astrojs/node` standalone build (`dist/server/entry.mjs`) runs on Bun 1.4.0 with `@sentry/astro` and delivers working errors, route names, request isolation, incoming trace continuation and logs. The alert must be amended to name Bun explicitly as working on the Node adapter output, and the page must state the two caveats observed. Outgoing `fetch` is not instrumented under Bun, because `@sentry/node`'s HTTP integration listens on undici's `undici:request:*` diagnostics channels and Bun's native fetch does not publish them — install `@sentry/bun` and add its `fetchIntegration()` to `sentry.server.config.mjs`, guarded on `typeof globalThis.Bun !== 'undefined'` so Node deployments of the same build do not double-span. Database spans are dropped because Bun holds diagnostics channels weakly and a channel with subscribers is not kept alive, so every subscription made at `Sentry.init()` is lost on the next tick — until this is fixed in the SDK, keep the channels reachable by storing them on `globalThis` after `Sentry.init()` (`orchestrion:mysql2:query`, `orchestrion:mysql2:execute`, `orchestrion:mysql:query`, `mysql2:query`, `mysql2:execute`, ...).

Where the docs stand: ~/dev/sentry-docs/docs/platforms/javascript/guides/astro/index.mdx:21-28 ("This SDK currently only works on Node runtimes, such as Node adapter or Vercel with Lambda functions... Other non-Node runtimes, like Vercel's Edge runtime, are currently **not supported**."); astro/index.mdx:4 (`sdk: sentry.javascript.astro`). `grep -rni bun` over guides/astro/ and `grep -rni astro` over guides/bun/ both return nothing.
