Proposed issue docs-change

Fix the extensionless instrument import on the Express, Fastify, Koa, Hapi and Connect guides and the esm-without-import page

Description

platform-includes/getting-started-use/javascript.express.mdx:22 starts the ESM app with import "./instrument";, while the config step creates instrument.mjs. Node ESM does not probe extensions: the app never starts, Error [ERR_MODULE_NOT_FOUND]: Cannot find module .../instrument ... Did you mean to import "./instrument.js"?. With import "./instrument.mjs" the same app produces exactly the --import output. The same extensionless import sits at common/install/esm-without-import.mdx:55, and the orphaned platform-includes/getting-started-add-top-level-import/javascript.express.mdx imports ./instrument.js. The Fastify tab has the same defect at platform-includes/getting-started-use/javascript.fastify.mdx:20, with the same ERR_MODULE_NOT_FOUND (QS-fastify, variant esm-tab), and so does the Koa tab at getting-started-use/javascript.koa.mdx:20; on Koa the corrected first-line import starts the app but loses every router and middleware span and the route names, so the Koa tab should rely on the node --import command instead (QS-koa, variants esm-tab and self-import). The Hapi tab at getting-started-use/javascript.hapi.mdx:28 fails the same way, and its corrected first-line import loses nothing (QS-hapi, variants esm-tab and self-import), and so does the Connect tab at getting-started-use/javascript.connect.mdx:20 (QS-connect, variant esm-tab).

What to change:

  • Import ./instrument.mjs in the Express, Fastify, Hapi and Connect ESM tabs, drop the import from the Koa tab in favour of --import, matching the file the config step creates, and fix esm-without-import.mdx:55 the same way.
