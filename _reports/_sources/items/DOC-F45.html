Document server route naming for Nuxt on Cloudflare Workers

Description

The combination is documented. docs/platforms/javascript/guides/cloudflare/frameworks/nuxt.mdx:1-11 is a "Nuxt on Cloudflare" page that names Nitro's cloudflare_module preset at :6 and pulls in the shared include at :8-11. The Cloudflare branch of that include is platform-includes/getting-started-complete/javascript.nuxt.mdx:261-322: the wrangler config at :263-268, the warning to delete an existing sentry.server.config.ts at :276-279, and the sentryCloudflareNitroPlugin server plugin at :286-293. What no page describes is how the request span is named on Cloudflare: grep -rn -i "route name|segment name" guides/cloudflare/ platform-includes/getting-started-complete/javascript.nuxt.mdx returns zero hits.

Verified on the develop line: Nuxt 4.2 with the cloudflare_module preset, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"], and server/plugins/sentry.ts registering sentryCloudflareNitroPlugin from @sentry/nuxt/module/plugins. Six of seven capabilities worked with that documented wiring verbatim, with no bundler plugin and no extra instrumentation step.

Works today:

  • Unhandled server route errors through Nitro's error hook, parameterized route names for routes such as server/api/users/[id].ts (GET /api/users/:id, source route, with http.route), per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, db spans with no manual bundler step, Sentry.logger logs.

Known limits:

  • A server route with no parameters gets no route attribute, so its span is named by HTTP method alone under the default traceLifecycle: 'stream' and from the request URL under 'static'.

What to change on docs/platforms/javascript/guides/cloudflare/frameworks/nuxt.mdx:

  • Replace the bare include passthrough with a page that keeps the include and adds a "Server Route Names" section stating the parameterless-route limit above, in both trace lifecycles.
  • Note that database spans need no extra configuration on the Cloudflare presets.

Source: runtime docs audit, item DOC-F45, cell M-nuxt-cf

Page: docs/platforms/javascript/guides/cloudflare/frameworks/nuxt.mdx — replace the bare include passthrough with a page that keeps the include and adds a "Server Route Names" section documenting the `GET`/URL naming on Workers and the route-naming Nitro plugin workaround

The documented wiring is correct and six of seven capabilities worked with it verbatim. The missing piece is server route naming: only routes carrying parameters, such as `/api/users/[id]`, are reported under their route pattern. A parameterless server route such as `/api/health` is reported as bare `GET` under the default `traceLifecycle: 'stream'`, and as the full request URL under `traceLifecycle: 'static'` — in both cases with a URL-derived name rather than the Nitro route pattern. The page must state this limitation and show the ship-today fix that was verified to produce identical output to a patched SDK: a second Nitro server plugin registered next to the Sentry one that uses only public `@sentry/cloudflare` exports (`getActiveSpan`, `getRootSpan`, `spanToJSON`) to rename the root span to the matched Nitro route and set the segment-name source accordingly.
