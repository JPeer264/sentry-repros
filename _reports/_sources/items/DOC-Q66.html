Description

platform-includes/performance/what-instrumentation-provides/javascript.elysia.mdx:1 is a BrowserTracing paragraph; :5-7 name the ops request_handler.elysia and middleware.elysia, say transactions use parameterized names, and say named handlers show their function name. Observed on Node: ops handler and middleware, no transaction under the default lifecycle, route-named segments, and no code.function.name on any span although the handler is a named function; common/migration/v10-to-v11/index.mdx:392 makes the same function-name claim for Elysia. The SDK also emits middleware spans for its own hooks (sentryOnRequest, sentryOnAfterHandle, sentryOnError), 11 to 12 spans per request, and children that end before route resolution carry sentry.segment.name: GET.

guides/elysia/index.mdx:105-127 presents index.ts as the Node setup and never says how to start it; node index.ts runs it but prints MODULE_TYPELESS_PACKAGE_JSON unless package.json has "type": "module". The Bun tab is the default expanded tab; run under Node it dies at .listen() with WebStandard does not support listen.

What to change:

  • Drop the browser paragraph, use the handler and middleware ops, say spans and segments, remove the function-name sentence until Node emits the attribute (and qualify migration :392), document the span count, and add the run command with the "type": "module" note.
