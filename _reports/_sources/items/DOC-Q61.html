Say what SentryModule does on the NestJS guide, fix the transactions wording and describe the span sets

Description

guides/nestjs/index.mdx:97-117 presents SentryModule.forRoot() as a required step; the run without it was identical in every check (event transaction name, route-named segments, spans), because the module only registers an interceptor that sets a transaction name the HTTP instrumentation already set. guides/nestjs/tracing/instrumentation/automatic-instrumentation.mdx:3 promises transactions; no transaction envelope was sent, every request is a span envelope, and the included node-automatic-instrumentation.mdx never mentions Nest. common/migration/v10-to-v11/index.mdx:392 and :436-441 describe the Nest handler spans correctly, but each request also carries the Express instrumentation's spans (urlencodedParser, jsonParser, two identical handler spans with origin auto.http.express) and a Create Nest App segment at start-up, which no page mentions.

What to change:

  • Say what the module does or mark it optional, reword transactions to spans and list the Nest spans, and mention that Nest-on-Express apps get both span sets and a start-up segment.
