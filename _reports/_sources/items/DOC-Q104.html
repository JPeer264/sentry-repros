DOC-Q104The SolidStart Vite plugin deletes every source map below the project root, node_modules includedP1proven

Proposed issue docs-change

Warn on the SolidStart guide that the plugin deletes every *.map below the project root unless told otherwise

Description

guides/solidstart/index.mdx:324-352 says adding org, project and authToken uploads source maps, and says nothing about deletion. Without an auth token the plugin logs Will not upload source maps and then deletes 3,543 *.map files, 3,519 of them under node_modules/, because the automatic sourcemaps.filesToDeleteAfterUpload is ["./**/*.map"]; seven maps remained in node_modules after one build.

What to change:

  • State that the plugin deletes every *.map below the project root unless sourcemaps.filesToDeleteAfterUpload is narrowed, and recommend sourcemaps: { disable: true } when no auth token is configured.

Source: runtime docs audit, item DOC-Q104, quick start QS-solidstart, variant import-src (build.log)

What ran: SolidStart getting-started reproduction on 2026-09-09, develop 03aaf42455 (@sentry/solidstart 10.67.0, 14 client and 46 server integrations), @solidjs/start 2.0.4 with nitro 3.0.260903-beta, server on Node 26.5.0 and the client in Chrome 153 headless: quickstarts/solidstart, results-*.json per variant. The guide is guides/solidstart/index.mdx with its install and feature pages; SolidStart 1 with vinxi was not run.

SDK-side note. The default delete glob reaches into node_modules and runs even when nothing was uploaded; worth an SDK ticket, the Astro plugin has a narrower default.
