Proposed issue docs-change

Document Hono on Cloudflare Workers: compatibility_date and build-time database spans

Description

The Hono guide already treats Cloudflare Workers as a first-class tab: docs/platforms/javascript/guides/hono/index.mdx:12 names Cloudflare Workers as a supported runtime, :65-78 tells Workers users to install @sentry/cloudflare as a peer dependency they never import, :129-144 is the "Cloudflare Workers: Enable Node.js Compatibility" Expandable, and :240-262 (the Cloudflare Workers tab of "Add the Sentry Middleware") shows the sentry(app, {...}) wiring. Two gaps: the Expandable sets compatibility_flags: ["nodejs_compat"] but never compatibility_date, and the guide's only database sentence, :162, is Node.js-only.

Verified on the develop line: npm install @sentry/hono @sentry/cloudflare hono, a wrangler.jsonc with compatibility_date: "2026-05-01" and compatibility_flags: ["nodejs_compat"], app.use(sentry(app, { dsn, tracesSampleRate: 1.0 })) as the first middleware, export default app, run with npx wrangler dev. For database spans the same app is built through Vite instead, which needs three more packages, npm install vite @cloudflare/vite-plugin mysql@2, and a vite.config.ts with plugins: [cloudflare(), sentryCloudflareVitePlugin({ autoInstrumentation: false })] from @sentry/cloudflare/vite, with autoInstrumentation: false because the Hono middleware already applies withSentry.

Works today:

  • Unhandled route errors, parameterized route names (GET /users/:id, source route), per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, Sentry.logger logs.
  • db spans from a mysql query, through the Vite build only.

Known limits:

  • A Worker bundled by wrangler dev/wrangler deploy alone emits no database spans and logs no warning.
  • No middleware.hono spans on Workers: the transaction's spans[] holds only the db and http.client children.

What to change on docs/platforms/javascript/guides/hono/index.mdx:

  • Extend the Expandable at :129-144 to set compatibility_date alongside nodejs_compat, matching platform-includes/getting-started-config/javascript.cloudflare.mdx:5.
  • Add a "Database spans on Cloudflare Workers" subsection after the "Add the Sentry Middleware" section (:227-359), before "### Report Unhandled Exceptions" at :360, stating that database instrumentation on Workers is build-time only, showing the Vite config above, and linking to /platforms/javascript/guides/cloudflare/features/vite-plugin/.
  • Say in the same subsection that a Workers transaction carries no middleware.hono spans, so readers do not go looking for them.
  • Link that subsection from docs/platforms/javascript/guides/cloudflare/frameworks/hono.mdx, the 8-line stub that today only redirects to the Hono guide, so a reader who starts on the Cloudflare side reaches the database note too.

The Hono guide documents the middleware wiring correctly, but two things the run needed are absent. (1) Database spans: the probe only got `db` spans after adding `vite`, `@cloudflare/vite-plugin` and the Sentry Cloudflare Vite plugin to the build (the query itself used `mysql@2`); the Hono guide's only database sentence (:162) is Node.js-specific and the Cloudflare tab says nothing, so a Workers user following this page gets errors, routes, isolation, trace continuation, fetch and logs but silently no db spans. The Cloudflare Workers section must say that database instrumentation on Workers is build-time only and link to /platforms/javascript/guides/cloudflare/features/vite-plugin/, and the same note should be reachable from the Cloudflare-side stub at guides/cloudflare/frameworks/hono.mdx:6-8. (2) The `nodejs_compat` Expandable at :129-144 sets the flag but never sets `compatibility_date`; the run used `2026-05-01` and the Cloudflare include (getting-started-config/javascript.cloudflare.mdx:5) states a date of `2024-09-23` or later is required, so the Hono Cloudflare tab must state the compatibility_date requirement alongside the flag. One more observed fact belongs in the same section: on Workers the transaction's `spans[]` contains no `middleware.hono` entries, only the db and http.client children.

Where the docs stand: docs/platforms/javascript/guides/hono/index.mdx:12 ("supports Hono 4+ across multiple runtimes: Cloudflare Workers, Node.js, Bun, and Deno"); :65-78 (Cloudflare Workers tab: `npm install @sentry/cloudflare` as the peer dependency, "You won't import it directly, but it must be present"); :129-144 (Expandable "Cloudflare Workers: Enable Node.js Compatibility", `compatibility_flags: ["nodejs_compat"]` for AsyncLocalStorage); :240-262 (the Cloudflare Workers tab of "Add the Sentry Middleware" at :227-359, carrying the exact `sentry(app, {...})` wiring from `@sentry/hono/cloudflare` that the run used); docs/platforms/javascript/guides/cloudflare/frameworks/hono.mdx:6-8 (stub that redirects to the Hono guide); docs/platforms/javascript/guides/cloudflare/index.mdx:17 (framework list entry). Missing: `grep -rn -i "vite|mysql|database" docs/platforms/javascript/guides/hono/` returns only index.mdx:162, which is about Node.js, so nothing in the Hono guide covers database spans on Workers. `compatibility_date` is never mentioned in the Cloudflare Expandable (only the flag, at :140-144), unlike platform-includes/getting-started-config/javascript.cloudflare.mdx:5-21 which the Hono guide does not include.
