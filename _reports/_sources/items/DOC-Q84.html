DOC-Q84Cloudflare Pages details: the nodejs_compat requirement depends on the date, request spans are method-named, waitUntil on PagesP2proven

Proposed issue docs-change

Add the missing Pages details to the Cloudflare guide and its config include

Description

platform-includes/getting-started-config/javascript.cloudflare.mdx:5 says the SDK needs the nodejs_compat flag and a compatibility date of 2024-09-23 or later. With no flags at all the same bundle runs at compatibility date 2026-09-01 (identical items) and fails at 2024-09-23 (No such module "node:async_hooks"); the requirement depends on the date, which the include does not say. Every Pages function-route segment is named GET with source url and no http.route; the parameterized functions/api/users/[id].js is GET with url.path /api/users/42, so Pages file routes are not visible as routes. The waitUntil section at guides/cloudflare/index.mdx:376-401 shows Worker code only; context.waitUntil(Promise.reject(...)) in a Pages function is not captured either, workerd logs the rejection and only the request segment arrives.

What to change:

  • Say the flag is required for compatibility dates before Node.js compatibility became the default, state that Pages request spans are named by method with the path in url.path, and add a Pages line with the .catch(Sentry.captureException) pattern to the waitUntil section.
