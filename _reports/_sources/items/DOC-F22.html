Add a Koa on Deno page covering error capture and instrumentation limits

Description

No page covers Koa on Deno. docs/platforms/javascript/guides/koa/index.mdx:4 declares sdk: sentry.javascript.node, :5 fallbackGuide: javascript.node, and :12 is only <PlatformContent includePath="getting-started-node" />; grep -rni deno docs/platforms/javascript/guides/koa/ returns nothing, and docs/platforms/javascript/guides/deno/index.mdx:1-232 mentions no framework and no import hook.

Verified on Koa with @koa/router on Deno 2.9.0: npm install the app dependencies and @sentry/deno into a real node_modules, deno.json with {"nodeModulesDir": "manual"} and an imports map, an instrument.ts calling Sentry.init() from @sentry/deno that is evaluated before the Koa app module, and deno run --allow-net --allow-env --allow-read --allow-sys main.ts. For automatic Koa error capture, bundle the server with esbuild and sentryOrchestrionPlugin() from @sentry/server-utils/orchestrion/esbuild (format: 'esm', external: ['@sentry/deno', '@sentry/server-utils'], plus a createRequire banner) and run the bundle; without that build step, register app.on('error', err => Sentry.captureException(err)) yourself. For database spans, keep @sentry/deno/import out of the static imports and register it in the entry body with await import("@sentry/deno/import") after Koa is imported, then load the driver with a dynamic import.

Works today:

  • Error capture, through the bundled build or the app.on('error') handler.
  • Per-request isolation and incoming trace continuation.
  • Database spans for mysql, with the deferred hook registration.
  • Logs, carrying the request trace id.

Known limits:

  • Parameterized route names are not available: transactions are GET /users/42 with source url, and the streamed server span is GET with no http.route.
  • import "@sentry/deno/import" must not be the first static import: Koa's statuses dependency does require('*.json'), and Deno compiles JSON as JavaScript while any module load hook is registered (denoland/deno#36240), so the process dies at import.
  • Outgoing fetch() is not instrumented; node:http requests are.

What to change:

  • Add docs/platforms/javascript/guides/deno/frameworks/koa.mdx with the setup, both error-capture options and the limits.

Page: guides/deno/frameworks/koa.mdx (new), with an "Instrumentation timing on Deno" section covering `--import` vs static import and the JSON load-hook workaround

A Koa-on-Deno page must exist and must document instrumentation timing, which is where every Koa capability succeeded or failed. It must say: (1) A static `import "@sentry/deno/import"` as the first import of the entry file does not work for Koa — Deno instantiates the whole module graph, including `koa`, before any module body executes, so the hook is registered too late; load it with the CLI flag instead (`deno run --import=./preload.ts main.ts`). (2) On Deno 2.9.0, registering any `Module.registerHooks` load hook breaks CJS `require('*.json')` (denoland/deno#36240), and Koa's `statuses` dependency does exactly that, so the app must also register a JSON-restoring load hook (`registerHooks({ load(url, ctx, next) { const r = next(url, ctx); return url.endsWith('.json') ? { ...r, format: 'json' } : r; } })` or the `readFileSync` equivalent); with the flag plus that hook, route names work. (3) An alternative that avoids the runtime hook entirely and was verified for both error capture and library spans: bundle the Koa app with esbuild and `sentryOrchestrionPlugin()` from `@sentry/server-utils/orchestrion/esbuild` (`format: 'esm'`, `external: ['@sentry/deno', '@sentry/server-utils']`, plus a `createRequire` banner) and run the bundle with Deno — no import hook and no manual `app.on('error')` handler needed. (4) For database spans without bundling, keep `import "@sentry/deno/import"` out of the static import list and register it in the entry body after Koa is imported (`await import('@sentry/deno/import')`), then dynamically import the driver. Isolation, incoming trace continuation and logs need no caveat. Outgoing `fetch` is not instrumented — no `http.client` span, no `sentry-trace`/`baggage` — in both `static` and `stream` lifecycles; the page must ship the userland fetch integration built from `addFetchInstrumentationHandler` / `defineIntegration` / `getClient` / `instrumentFetchRequest`, and note `node:http`/`node:https` are traced normally.

Where the docs stand: docs/platforms/javascript/guides/koa/index.mdx:4 `sdk: sentry.javascript.node`, :5 `fallbackGuide: javascript.node`, :12 body is only `<PlatformContent includePath="getting-started-node" />`; `grep -rni deno docs/platforms/javascript/guides/koa/` returns nothing; docs/platforms/javascript/guides/deno/index.mdx:1-232 never mentions Koa or any framework, and no page in the repo mentions `@sentry/deno/import` or `Module.registerHooks`
