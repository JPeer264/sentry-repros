Correct the Nitro error-capture and span claims

Description

guides/nitro/index.mdx:273 says the error hook captures unhandled errors and skips 3xx and 4xx HTTPErrors: true on nitro 3.0.260415-beta; on 3.0.260903-beta every handler error is captured twice (auto.http.nitro.onTraceError plus auto.function.nitro.captureErrorHook) and the 404 HTTPError is reported. :203-214 and :228-249 say the verify route's Error("My first Sentry error!") creates the issue; the event's outermost exception is HTTPError: My first Sentry error!, Nitro's 500 wrapper, with the thrown Error as a chained cause, so the issue is titled HTTPError. :289 says middleware spans use op: 'middleware.nitro'; the h3 spans have op middleware and are named after the route (middleware GET /api/users/:id), never after the middleware. :286 says the SDK creates transactions for incoming requests; only span items arrive. :291 says 4xx HTTPErrors do not mark the span errored; the /error-404 segment arrives with status error and status code 404.

What to change:

  • Scope the error-hook claim to the verified Nitro versions and note the newer betas' duplicates, tell the reader the issue is titled HTTPError with the original error chained, change the op to middleware with route naming, say request spans instead of transactions, and drop or restrict the 4xx claim.
