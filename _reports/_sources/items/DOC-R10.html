DOC-R10ExtraErrorData page says the data lands in extra; it is written to contexts.<ErrorName>P1verified in source

Proposed issue docs-change

Correct where ExtraErrorData writes on the integration page

Description

docs/platforms/javascript/common/configuration/integrations/extraerrordata.mdx:3 and :8 both describe the integration as one that "attaches them to the event as extra data". The page renders on the Bun, Deno and Cloudflare guides via platform-includes/configuration/extra-error-data/javascript.{bun,deno,cloudflare}.mdx, so readers on all three go looking for the values under Additional Data.

On develop the integration writes a context instead. packages/core/src/integrations/extraerrordata.ts:69 sets contexts[exceptionName] = normalizedErrorData and returns { ...event, contexts } at :72-75; event.extra is never touched. The key is the error's name, falling back to its constructor name (:54), so the payload shows up as contexts.<ErrorName> in the issue view.

What to change

  • Reword the description frontmatter and the body sentence to say the properties are attached as a context named after the error.
  • Name the location explicitly as contexts.<ErrorName> and drop the "extra data" phrasing.
