DOC-Q5Node guide: the --require flag prints an undocumented "no longer supported" banner, and the ordering warning is stricter than developP2proven

Proposed issue docs-change

Update the Node getting-started page for --require and for first-line ESM imports

Description

platform-includes/getting-started-node/javascript.mdx:93-96 shows node --import ./instrument.mjs app.mjs, and :55 warns that importing the instrument file later than first means auto-instrumentation and modules like database monitoring may not work. Nothing on the page mentions --require.

Observed on develop with Node v26.5.0: node --require ./instrument.cjs app.mjs still delivers the same errors, spans, headers and logs, but its first stderr line is [Sentry] Initializing the SDK via the Node --require flag is no longer supported, because Node re-runs --require preloads on its module loader thread. Use --import instead. A first-line import "./instrument.mjs" in the entry file gives the same telemetry as the flag, including Express route names and handler spans, because the injection hook is registered while @sentry/node evaluates. NODE_OPTIONS="--import ./instrument.mjs" is identical to the flag.

What to change:

  • Add one sentence that --require is no longer supported and prints a banner, with the --import replacement.
  • Soften the ordering warning at :55: a first-line ESM import of the instrument file is equivalent to --import; the warning applies to imports that are not first.
  • List NODE_OPTIONS as an equivalent form.
