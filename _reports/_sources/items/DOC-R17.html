DOC-R17Deno guide never mentions deno serve, which is instrumented like Deno.serveP2verified in source

Proposed issue docs-change

Add deno serve to the Deno guide run commands

Description

The Deno guide shows only two ways to start an app: deno run --allow-net=___ORG_INGEST_DOMAIN___ index.ts at docs/platforms/javascript/guides/deno/index.mdx:106 and deno run --allow-read=./src index.ts at :125. The string deno serve appears nowhere under docs/, platform-includes/ or includes/, so a reader using the default-export server form has no confirmation that the SDK covers it.

Verified: an export default { fetch } entrypoint started with deno serve is instrumented exactly like Deno.serve. The DenoServe integration proxies Deno.serve (packages/deno/src/integrations/deno-serve.ts:73-80), which is what deno serve calls internally. Running with --parallel performs one Sentry.init per worker and produces no duplicate telemetry.

What to change

  • Add a deno serve note to the Deno guide alongside the existing run commands.
  • State that a default-export fetch handler is instrumented the same way as Deno.serve.
  • Note that --parallel initializes once per worker without duplicate events.

Source: runtime docs audit, item DOC-R17

Status quo. The Deno guide's only run commands are `deno run --allow-net=___ORG_INGEST_DOMAIN___ index.ts` (docs/platforms/javascript/guides/deno/index.mdx:106) and `deno run --allow-read=./src index.ts` (:125). The string `deno serve` appears nowhere under docs/, platform-includes/ or includes/.

On develop. The audit verified that an `export default { fetch }` entrypoint started with `deno serve` is instrumented exactly like `Deno.serve`, because the DenoServe integration proxies `Deno.serve` (packages/deno/src/integrations/deno-serve.ts:73-80), which `deno serve` calls internally. Running with `--parallel` performs one `Sentry.init` per worker and produces no duplicate telemetry.

Work item. Add a `deno serve` note to the Deno guide stating that a default-export `fetch` handler is instrumented the same way and that `--parallel` initializes once per worker without duplicating events.
