Rewrite the Remix on Cloudflare page for Workers and fix the Vite plugin options

Description

docs/platforms/javascript/guides/cloudflare/frameworks/remix.mdx is 60 lines and does not describe a working Workers setup: :39-49 installs only @sentry/remix with no @sentry/cloudflare, and :55-58 embeds the shared include. In that include, the Cloudflare branch at platform-includes/getting-started-complete/javascript.remix.mdx:250-294 covers Cloudflare Pages only, and the "Capture Server-Side Errors" step at :296-329 sits outside any PlatformSection and tells every reader to import from bare @sentry/remix at :314. Separately, guides/cloudflare/features/vite-plugin.mdx:30 presents _experimental.useDiagnosticsChannelInjection as something you must enable.

Verified on the develop line: Remix v2 (2.17.5) with the Remix Vite plugin on workerd, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"]. Install @sentry/remix and @sentry/cloudflare; npm needs --legacy-peer-deps, because @remix-run/cloudflare pins @cloudflare/workers-types ^4 while wrangler 4 pins ^5. In app/entry.server.tsx, export const handleError = sentryHandleError imported from @sentry/remix/cloudflare. In the worker entry, Sentry.withSentry() from @sentry/cloudflare around a handler built with createRequestHandler(instrumentBuild(remixBuild)); do not reach for makeWrappedCreateRequestHandler from @sentry/remix/cloudflare as well, which on Cloudflare reports every request twice, as two http.server transactions in two different traces. In vite.config.ts, sentryCloudflareVitePlugin() from @sentry/cloudflare/vite at its defaults alongside the Remix plugin, with ssr: { target: 'webworker', noExternal: ['mysql', /^@sentry\//, '@opentelemetry/api'] } (noExternal: true is the blunt version of the same thing). Build with remix vite:build: a plain vite build under Vite 6 silently builds only the client and skips build/server.

This item prescribes sentryCloudflareVitePlugin() because that is what was run. The Remix Vite plugin's own Cloudflare behavior, sentryRemixVitePlugin from @sentry/remix/vite, which on the v11 line applies the build-time instrumentation transform itself, was not exercised in this audit.

Works today:

  • Loader, action and resource-route errors, parameterized route names with http.route, incoming trace continuation, outgoing fetch spans with propagation headers, db spans from mysql, Sentry.logger logs.
  • Per-request isolation, with the withSentry plus instrumentBuild entry above.

Known limits:

  • Importing from bare @sentry/remix in a webworker SSR build leaves handleError undefined and captures nothing.
  • wrapRequestHandler from @sentry/cloudflare/request establishes no request isolation on Workers: it is the one Cloudflare wrapper that never calls setAsyncLocalStorageAsyncContextStrategy, so under concurrency every setTag, setUser and request-data write is global to the isolate and bleeds into unrelated later requests, and no event carries request data at all. It exists for runtimes that cannot enable nodejs_compat, such as Shopify Oxygen.
  • A route with no loader or action stays method-only.
  • With instrumentBuild alone the event's transaction field is unset, because nothing calls isolationScope.setTransactionName, so error grouping loses the route.
  • Without sentryCloudflareVitePlugin() there are no database spans and no warning; mysql2 is unusable on workerd.

What to change:

  • Rewrite guides/cloudflare/frameworks/remix.mdx: add @sentry/cloudflare to the install at :39-49, add a Workers entry section, point handleError at @sentry/remix/cloudflare, and add a database-spans section.
  • Correct guides/cloudflare/features/vite-plugin.mdx to the shipped top-level options buildTimeInstrumentation and autoInstrumentation, both defaulting to true: the prose at :30, the snippets at :40-47 and the SdkOption blocks at :150-166, which still document _experimental.autoInstrumentation and _experimental.useDiagnosticsChannelInjection as defaulting to false.
  • Add the wrapRequestHandler isolation warning to the two Hydrogen pages that document exactly that shape, guides/cloudflare/frameworks/hydrogen-remix.mdx and guides/cloudflare/frameworks/hydrogen-react-router.mdx.

The page contradicts the run on three points and must be rewritten for Workers. (1) Error capture: on Cloudflare Workers and Pages the `handleError` import must come from `@sentry/remix/cloudflare`, never bare `@sentry/remix` — the bare specifier silently captures nothing in a `webworker` SSR build. Both `export const handleError = sentryHandleError` and `wrapHandleErrorWithSentry` work from that subpath, on both trace lifecycles, for loaders, actions, resource routes and thrown 5xx Responses. (2) Request isolation: the worker entry must be wrapped with `withSentry` from `@sentry/cloudflare` around a handler built with `instrumentBuild` from `@sentry/remix/cloudflare`, and `makeWrappedCreateRequestHandler` must not be added on top, because on Cloudflare it double-reports every request as two http.server transactions in two different traces. `wrapRequestHandler` from `@sentry/cloudflare/request` exists only for runtimes that cannot enable `nodejs_compat` (Shopify Oxygen); on Workers it is the one wrapper that never calls `setAsyncLocalStorageAsyncContextStrategy`, so tags, user and request data are written to a scope shared by the whole isolate and bleed across concurrent requests, and events carry no request data — a warning the two Hydrogen pages, which document exactly that shape, should carry. (3) Database spans require the build-time transform: add `sentryCloudflareVitePlugin()` to the Vite config alongside the Remix plugin — defaults are sufficient, `autoInstrumentation: false` is unnecessary, and the connection may sit at module scope or inside the loader — and set `ssr: { target: 'webworker', noExternal: ['mysql', /^@sentry\//, '@opentelemetry/api'] }`, with `noExternal: true` as the blunt equivalent. Without the plugin, queries run normally, no `db` span appears, and the SDK logs no warning. Two build details belong on the page as well: the build command is `remix vite:build`, since a plain `vite build` under Vite 6 skips the server build, and npm needs `--legacy-peer-deps` for the `@cloudflare/workers-types` conflict between `@remix-run/cloudflare` and wrangler 4. The `_experimental.useDiagnosticsChannelInjection: true` requirement stated on the Vite plugin page is no longer needed on the v11 line and must be corrected there too. Finally, the page must also install `@sentry/cloudflare`, not just `@sentry/remix`. One scope note: this item prescribes `sentryCloudflareVitePlugin()` because that is the plugin the run used; `sentryRemixVitePlugin` from `@sentry/remix/vite`, which on the v11 line applies the build-time transform itself, was not exercised on Cloudflare in this audit and may well be the shorter path.
