Rewrite features/d1.mdx around automatic D1 instrumentation

Description

guides/cloudflare/features/d1.mdx:6-16 is the whole body of the page and instructs the user to wrap their binding with instrumentD1WithSentry(env.DB) at :13.

What was observed: on develop that export is gone, and withSentry instruments every D1 binding found on env (packages/cloudflare/src/instrumentations/worker/instrumentEnv.ts:64-68 at 6f2da7483d, :61-65 at develop head, recorded in MIGRATION.md:1401-1416). The automatic path is what dev-packages/cloudflare-integration-tests/suites/d1 exercises. D1 spans use the db.query op, batches are named D1 batch, single queries are named by the sanitized query summary under the stream lifecycle and by the raw query under the static one (instrumentD1.ts:137), and the cloudflare.d1.* attributes are set in instrumentD1.ts:114-116,142-146,178. On the released line the wrapper already has no effect beyond the automatic instrumentation, and the page does not say so. The page will be wrong when v11 ships.

What to change:

  • Rewrite features/d1.mdx to state that D1 bindings on env are instrumented automatically by withSentry, with no per-binding call.
  • Document the span op db.query, the D1 batch span name, the query-summary naming for single queries, and the cloudflare.d1.* attributes listed above.
  • Replace the instrumentD1WithSentry snippet with a note that the function exists before 11.0 and is not needed.
