Proposed issue docs-change

Add a bindings table to the Cloudflare features/index.mdx

Description

No Cloudflare page lists which Worker bindings produce spans. guides/cloudflare/features/index.mdx is a 13-line PageGrid. agent-tracing/workers-ai.mdx covers Workers AI, D1 is described as a manual wrapper in features/d1.mdx, and common/tracing/instrumentation/caches-module.mdx and queues-module.mdx are shown for Cloudflare while describing Redis and manual spans only.

What was observed in instrumentEnv.ts at 6f2da7483d: D1 bindings are instrumented automatically with span op db.query; R2 is instrumented (instrumentR2.ts:26-48) with object.* ops; Queues producers are instrumented with the span name send <binding> (instrumentQueueProducer.ts:20) and the queue.publish op (:28); env.AI.run produces gen_ai.* spans; Durable Object namespaces and service bindings get trace-propagation headers and RPC metadata, with RPC instrumented and headers not; the rate limiter binding is not instrumented at that commit. Workers KV, Vectorize, Hyperdrive, Analytics Engine, the Cache API and Assets are not instrumented. The d1, r2, queue and ratelimit integration suites pin these.

What to change:

  • Add a bindings table to guides/cloudflare/features/index.mdx with columns: binding, instrumented, span op, where it is documented, using the rows above.
  • State plainly that Workers KV, Vectorize, Hyperdrive, Analytics Engine, the Cache API and Assets produce no spans.
  • Adjust the supported: lists so the caches and queues common pages are not shown as Cloudflare binding documentation.
