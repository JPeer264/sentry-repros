DOC-F17SolidStart on Bun: documented noP1proven

Proposed issue new-page

Add a SolidStart on Bun page with the @sentry/bun integrations

Description

Nothing under docs/platforms/javascript/guides/solidstart/ mentions Bun. solidstart/index.mdx:5-8 gives only categories: [browser, server], solidstart/index.mdx:289 tells you to add an --import flag to NODE_OPTIONS, and the single start command at solidstart/index.mdx:309-310 is node --import ./.output/server/instrument.server.mjs .output/server/index.mjs; solidstart/install/cli-import.mdx:33,45 repeats it.

Verified on SolidStart 2 (@solidjs/start 2.0.2, Nitro 3) with @sentry/solidstart 10.67.0 on Bun 1.4.0: sentrySolidStart() in vite.config.ts, Sentry.init inside the Nitro plugin server/plugins/sentry.ts, sentryBeforeResponseMiddleware() in src/middleware.ts, vite build, then bun .output/server/index.mjs. Install @sentry/bun alongside @sentry/solidstart and add bunHttpServerIntegration() and fetchIntegration() to integrations, guarding the fetch one on process.versions.bun so a Node deployment of the same build does not get two spans. Add import 'mysql2/promise'; as the first import of the Nitro plugin.

Works today:

  • Per-request isolation, one scope and one trace per request
  • Incoming sentry-trace/baggage continuation
  • Outgoing fetch spans with propagation headers
  • mysql2 3.20.0+ database spans, with the driver loaded at startup
  • Sentry.logger log envelopes
  • Errors from server functions wrapped in withServerActionInstrumentation

Known limits:

  • Errors thrown in a file API route or during page render are not reported, on Bun and on Node alike.
  • Server transactions are named from the raw URL (GET /users/456, source url), not the route pattern, on Bun and on Node alike.
  • Drivers Sentry instruments by build-time code injection produce no spans on Bun.

What to change:

  • New page docs/platforms/javascript/guides/bun/frameworks/solidstart.mdx with the bun .output/server/index.mjs start command, the two @sentry/bun integrations, the startup driver import and the capability list.
  • Add the route-naming and unreported-API-route-error notes to guides/solidstart/index.mdx.

Page: docs/platforms/javascript/guides/bun/frameworks/solidstart.mdx (new); plus route-naming and unreported-server-error notes on docs/platforms/javascript/guides/solidstart/index.mdx

A page must say the SolidStart 2 nitro node output runs on Bun 1.4.0 as `bun .output/server/index.mjs` and give the Bun equivalent of the `node --import ./.output/server/instrument.server.mjs` start command documented at index.mdx:309-310. It must state that on Bun, with the documented setup alone, requests are not isolated (every request shares one trace and one scope, so tags and user leak between concurrent requests), incoming `sentry-trace`/`baggage` is not continued, and outgoing `fetch()` produces no `http.client` span and sends no trace headers — because Bun does not emit the `http.server.request.start` diagnostics channel and its native fetch does not publish undici's channels. The fix: install `@sentry/bun` alongside `@sentry/solidstart` and add `bunHttpServerIntegration()` and `fetchIntegration()` to the `Sentry.init()` in `server/plugins/sentry.ts` (guard the fetch one on the runtime so a Node deployment of the same build does not get two spans). For database spans it must say only drivers publishing their own `node:diagnostics_channel` events (mysql2 3.20.0+) are recorded on Bun, and only if the driver is loaded at startup — add `import 'mysql2/promise';` as the first import of `server/plugins/sentry.ts` — because Bun's GC otherwise collects the SDK's subscriptions; drivers Sentry instruments by build-time code injection are not recorded at all. Two further observed facts hold on Node as well and belong on the SolidStart guide itself: server transactions are named from the raw request URL (`GET /users/456`, `source: "url"`) rather than the route pattern, because SolidStart mounts its whole app as a single Nitro catch-all so the SDK's Nitro route parameterization never fires; and errors thrown in a file API route (`src/routes/api/*.ts`) or during page render are turned into a 500 by SolidStart's internal h3 app before nitro's error hook, so no event is sent — only `withServerActionInstrumentation`, or a user-supplied h3 middleware via `createMiddleware`, captures them.

Where the docs stand: ~/dev/sentry-docs/docs/platforms/javascript/guides/solidstart/index.mdx:5-8 (`categories: [browser, server]`, no runtime named); solidstart/index.mdx:289 ("add an `--import` flag to the `NODE_OPTIONS` environment variable"); solidstart/index.mdx:309-310 (`start:node`: `node --import ./.output/server/instrument.server.mjs .output/server/index.mjs`); ~/dev/sentry-docs/docs/platforms/javascript/guides/solidstart/install/cli-import.mdx:33,45. `grep -rin bun` over guides/solidstart/ and `grep -rin solid` over guides/bun/ both return 0.
