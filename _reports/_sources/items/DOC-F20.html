Proposed issue new-page

Add an Express on Deno page describing what @sentry/deno instruments

Description

Nothing covers this combination: grep -rni express docs/platforms/javascript/guides/deno/ and grep -rni deno docs/platforms/javascript/guides/express/ both return zero hits. docs/platforms/javascript/guides/express/index.mdx:4-5 declares sdk: sentry.javascript.node with fallbackGuide: javascript.node, and :12 is a bare <PlatformContent includePath="getting-started-node" />, so the whole guide assumes @sentry/node on Node. docs/platforms/javascript/guides/deno/index.mdx:1-232 names no framework.

Verified on Express 5.2.1 and Deno 2.9.0: npm install express plus @sentry/deno into a real on-disk node_modules, deno.json with {"nodeModulesDir": "manual"}, an instrument.ts that calls Sentry.init({ dsn, tracesSampleRate: 1.0 }) from @sentry/deno and is the first import of the app file, then deno run --allow-net --allow-env --allow-read --allow-sys app.ts.

Works today:

  • Incoming requests produce http.server transactions.
  • Per-request isolation across concurrent requests, with distinct trace ids.
  • Incoming sentry-trace/baggage continuation.
  • Logs.

Known limits:

  • Transaction names stay unparameterized: GET /users/42 with source url, and no handler spans.
  • Errors thrown in route handlers are swallowed by Express and are not captured.
  • Database spans are not produced.
  • import "@sentry/deno/import", which is what would add route names, handler spans, error capture and database spans, cannot be used with Express on Deno 2.9: registering any module load hook makes require('*.json') compile as JavaScript (denoland/deno#36240) and Express fails at import.
  • Outgoing fetch() is not instrumented; node:http/node:https requests are.

What to change:

  • Add docs/platforms/javascript/guides/deno/frameworks/express.mdx with the install, deno.json, init placement, run command and the limits above.
  • Add a shared "Outgoing fetch requests" note to guides/deno/index.mdx.

Source: runtime docs audit, item DOC-F20, cell M-express-deno

Page: guides/deno/frameworks/express.mdx (new), plus a new "The Deno import hook" section in guides/deno/index.mdx (currently absent from :1-232) that the framework pages link to

An Express-on-Deno page must exist, and before it can describe any capability it must document the `@sentry/deno/import` hook, which is currently undocumented repo-wide even though every Express capability on Deno depends on it. It must say: Express 5 runs on Deno unmodified; route names, handler spans, Express error capture and database spans all require `import "@sentry/deno/import"`; and that hook currently needs a one-line user-land workaround for denoland/deno#36240 (registering any module load hook makes `require('*.json')` compile as JavaScript) or Express cannot even be imported. It must show the workaround (a `Module.registerHooks` load hook that returns JSON sources as JSON, either the `readFileSync` form or the delegating `nextLoad` form) and the `deno.json` with `"nodeModulesDir": "manual"` plus an on-disk `node_modules`. With that in place errors, route names, isolation, incoming trace continuation, database spans and logs all work. The one remaining gap is outgoing HTTP: `@sentry/deno` instruments only `node:http`/`node:https`, so a native `fetch()` gets no `http.client` span and no `sentry-trace`/`baggage` headers. The page must ship the copy-paste integration rather than telling readers to switch clients — the verified guidance is explicitly not to swap to `node:http`, but to define an integration from public `@sentry/core` exports (`addFetchInstrumentationHandler`, `defineIntegration`, `getClient`, `instrumentFetchRequest`, `isSentryRequestUrl`) after `import "@sentry/deno/import"` and pass it to `Sentry.init`, which restores both the span and the headers.

Where the docs stand: `grep -rni express docs/platforms/javascript/guides/deno/` returns nothing and `grep -rni deno docs/platforms/javascript/guides/express/` returns 0 hits; docs/platforms/javascript/guides/express/index.mdx:4-5 declares `sdk: sentry.javascript.node` / `fallbackGuide: javascript.node` and :12 is a bare `<PlatformContent includePath="getting-started-node" />`, i.e. the whole guide is @sentry/node on Node; `grep -rn "@sentry/deno/import\|registerHooks" docs/ platform-includes/` returns nothing anywhere in the repo
