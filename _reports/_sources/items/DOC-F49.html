Verified on the develop line: TanStack Start (React) v1.136 with file-based routing, React 19, compatibility_date: "2026-05-01", compatibility_flags: ["nodejs_compat"], wrangler 4.129.0. The page's wiring was exercised as shown, plus one step the page never mentions: sentryTanstackStart() from @sentry/tanstackstart-react/vite in vite.config.ts. Plugin order matters: cloudflare({ viteEnvironment: { name: 'ssr' } }) first, tanstackStart(), then sentryTanstackStart(). src/start.ts registers sentryGlobalRequestMiddleware and sentryGlobalFunctionMiddleware first in their arrays, and src/router.tsx must export getRouter, not createRouter, or the client build fails. Run vite build, then wrangler dev against the emitted config.

Works today:

  • Unhandled route handler errors, parameterized route names (GET /users/$id, source route, with http.route), per-request isolation, incoming trace continuation, outgoing fetch spans with propagation headers, db spans, Sentry.logger logs.

Known limits:

  • Without sentryTanstackStart() in vite.config.ts, two capabilities disappear at once: route names fall back to the raw URL (GET /users/123, source url), because that plugin defines __SENTRY_ROUTE_PATTERNS__, which wrapFetchWithSentry reads, and database spans vanish, because the same plugin runs sentryOrchestrionPlugin.
  • vite dev produces no database spans on this stack at all: the orchestrion plugin returns early when NODE_ENV is development. Use vite build plus wrangler dev.
  • Only the server runtime was exercised; the client half of the SDK was not part of this run.

What to change on docs/platforms/javascript/guides/cloudflare/frameworks/tanstack-start.mdx:

  • Add a "Configure Vite" step to the Configure section showing the full plugin chain in order, cloudflare({ viteEnvironment: { name: 'ssr' } }), then tanstackStart(), then sentryTanstackStart(), and stating that without the last one route names fall back to source url and database spans are not recorded.
  • Say in that step that sentryCloudflareVitePlugin() should not be added to a TanStack Start app, since the TanStack plugin chain plus the explicit withSentry in src/server.ts already covers it, and that database spans need vite build, not vite dev.
  • Add a tested-versions note near :10 recording the combination above.

The page cannot state the plugin order that matters either, because it has no Vite section at all — `grep sentryTanstackStart` on it returns nothing. Two further facts belong in that step: `sentryCloudflareVitePlugin()` must not be added to a TanStack Start app, and `vite dev` never produces database spans here because the orchestrion plugin skips itself when NODE_ENV is development. Everything else the run exercised passed with the documented wiring — errors, isolation, incoming trace continuation, outgoing fetch spans and logs — and the versions it passed on (TanStack Start / `@tanstack/react-start` v1.136 with file-based routing, React 19, wrangler 4.129.0, `nodejs_compat`, compatibility_date 2026-05-01) are worth recording, since the page names none.
