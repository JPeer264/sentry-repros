Proposed issue docs-change

Say on the Lambda wrapper page that v11 wraps the handler automatically with default options

Description

guides/aws-lambda/configuration/lambda-wrapper.mdx:13-37 says timeout warnings, flushTimeout and timeoutWarningLimit are set through the wrapHandler options. On develop awsLambdaIntegration rewrites _HANDLER to a shim that wraps the exported handler with default options: with captureTimeoutWarning: false on the user's wrapHandler a Possible function timeout warning event still arrived. wrapHandler in user code is redundant for both install options and only changes the mechanism to auto.function.aws_serverless.handler; on its own, without the runtime redirect, it yields an error event but no span.

What to change:

  • State that the automatic instrumentation applies default wrapper options, and document how to opt out of awsLambdaIntegration so the wrapHandler options take effect.

Source: runtime docs audit, item DOC-Q73, quick start QS-aws-lambda, variants manual-esm-wrap-options, auto-esm and wrap-only

What ran: AWS Lambda getting-started reproduction on 2026-09-09, develop 03aaf42455 (@sentry/aws-serverless 10.67.0, 25 integrations), invoked locally by a runtime stand-in with a fake API Gateway event, Node 26.5.0: quickstarts/aws-lambda, results-*.json per variant; the layer and container-image paths need AWS and were read only.

SDK-side note. The shim wraps the handler again even when the export is already a wrapHandler result, so wrapper options never apply; worth an SDK ticket in the Cloud milestone.
