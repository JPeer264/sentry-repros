Document Elysia on Deno: init from @sentry/deno, keep withElysia

Description

docs/platforms/javascript/guides/elysia/index.mdx:25 lists prerequisites as Bun or Node 18+ with the node adapter, and the install and configure snippets at :52-70 and :78-120 have only Bun and Node tabs, with Sentry.init imported from @sentry/elysia. platform-includes/performance/what-instrumentation-provides/javascript.elysia.mdx:9-12 enumerates exactly two runtimes and :6 claims parameterized route names unconditionally. A grep for deno over the Elysia guide returns nothing.

Verified on Elysia 1.4.30 and Deno 2.9.0: install the packages with npm into a real node_modules, set {"nodeModulesDir": "manual"} in deno.json, then call Sentry.init() from @sentry/deno before Deno.serve and import only withElysia (and fetchIntegration) from @sentry/elysia. Mount with Deno.serve({ port }, withElysia(new Elysia()).get(...).fetch). Add import "@sentry/deno/import"; as the first line for database spans, and pass integrations: [fetchIntegration()] for outgoing requests.

Works today:

  • Route errors, mechanism auto.http.elysia.on_error.
  • GET /users/:id with op http.server and source route.
  • Per-request isolation and incoming trace continuation.
  • Outgoing http.client spans plus sentry-trace/baggage, with fetchIntegration().
  • Database spans for mysql, and logs.

Known limits:

  • @sentry/elysia's own init() delegates to @sentry/bun and does not instrument Deno.serve: with it there is no http.server span, every request shares one process-wide trace, and incoming trace headers are ignored.
  • Events report sdk.name as sentry.javascript.deno.
  • mysql2 cannot be imported while the Deno import hook is active: Deno compiles require('*.json') as JavaScript and the import throws SyntaxError: Unexpected token ':'.

What to change:

  • guides/elysia/index.mdx:25 and the snippets at :52-70, :78-120: add Deno tabs with the split init described above.
  • platform-includes/performance/what-instrumentation-provides/javascript.elysia.mdx:6,9-12: add a Deno bullet and qualify the route-name claim.

A page must state that Elysia 1.4 runs unchanged on Deno 2.9, mounted with Deno.serve and app.fetch, with nodeModulesDir manual and deps installed with npm, and that the wiring the guide shows today is wrong for this runtime. With Sentry.init from @sentry/elysia, route names, isolation and incoming trace continuation are all broken on Deno, because that init delegates to @sentry/bun, which does not instrument Deno.serve; every Elysia lifecycle phase becomes its own root transaction. The correct wiring is the Deno import hook, Sentry.init from @sentry/deno before Deno.serve, and only withElysia imported from @sentry/elysia. Separately, the Deno SDK does not instrument global fetch; add a fetch integration for http.client spans and trace headers. With that wiring, errors, database spans and logs work. The parameterized-route-names claim and the two-runtime list must both be corrected.
