Proposed issue docs-change

Add a Bun section to the Nuxt Nitro deployment presets page

Description

docs/platforms/javascript/guides/nuxt/features/nitro-deployment-presets.mdx:7 says the presets "work out of the box" and nitro-deployment-presets.mdx:9-11 carves out only Cloudflare Pages, while the documented start command at guides/nuxt/index.mdx:68 is node --import ./.output/server/sentry.server.config.mjs .output/server/index.mjs. Nothing under guides/nuxt/ mentions Bun.

Verified on Nuxt 4.5.2 (Nitro 2.13.4) with @sentry/nuxt 10.67.0 on Bun 1.4.0, NITRO_PRESET=bun, run as bun .output/server/index.mjs: set sentry: { autoInjectServerSentry: 'top-level-import' } in nuxt.config.ts because Bun ignores NODE_OPTIONS and has no --import flag, install @sentry/bun alongside @sentry/nuxt, and pass integrations: [bunServerIntegration(), fetchIntegration()] from @sentry/bun to the existing Sentry.init in sentry.server.config.ts.

Works today:

  • Unhandled server-route errors via the Nitro error hook, with or without the extra integrations
  • http.server spans named GET /users/:id with source route and http.route
  • Per-request isolation and a fresh trace per request
  • Incoming sentry-trace/baggage continuation
  • Outgoing fetch spans with propagation headers
  • Sentry.logger log envelopes

Known limits:

  • Without bunServerIntegration() there is no request span at all, every event shares one process-wide trace, names are not route-based and incoming trace headers are ignored.
  • Database spans need nitro: { externals: { external: ['mysql2', 'mysql2/promise'] } } in nuxt.config.ts, otherwise every query fails with genFunc$1 is not a function regardless of Sentry.
  • Unparameterized routes stay method-only with source url.

What to change:

  • guides/nuxt/features/nitro-deployment-presets.mdx: add a Bun section next to the Cloudflare Pages one covering autoInjectServerSentry: 'top-level-import', the two @sentry/bun integrations and the Nitro externals.
  • guides/nuxt/index.mdx:68: add the Bun start command bun .output/server/index.mjs beside the Node one.

Source: runtime docs audit, item DOC-F11, cell M-nuxt-bun

Page: docs/platforms/javascript/guides/nuxt/features/nitro-deployment-presets.mdx — new "Bun" section alongside the Cloudflare Pages one (and a Bun start command next to docs/platforms/javascript/guides/nuxt/index.mdx:68)

The presets page's "work out of the box" claim, with only Cloudflare excepted, is contradicted by the `bun` Nitro preset run under `bun .output/server/index.mjs`: `@sentry/nuxt` uses the Node HTTP instrumentation, which never sees `Bun.serve`, so with the documented setup alone there is no request span — every event shares one trace and one scope across concurrent requests, transactions are not route-named, incoming `sentry-trace`/`baggage` is not continued, and outgoing `fetch()` from server routes gets no `http.client` span and sends no trace headers. The page must add a Bun section stating that you install `@sentry/bun` alongside `@sentry/nuxt` and add `bunServerIntegration()` and `fetchIntegration()` from it to `integrations` in `sentry.server.config.ts`, which restores `http.server` segment spans named `GET /users/:id` with `sentry.segment.name.source=route`, per-request trace ids and per-request isolation, and outgoing-fetch spans and headers. For database spans it must additionally say to stop Nitro from bundling `mysql2` in `nuxt.config.ts` — otherwise every query 500s with `genFunc$1 is not a function`, with or without Sentry. Finally, the start command at nuxt/index.mdx:68 cannot be followed on Bun and needs a documented Bun equivalent.

Where the docs stand: ~/dev/sentry-docs/docs/platforms/javascript/guides/nuxt/features/nitro-deployment-presets.mdx:7 ("provides support for different Nitro deployment presets, most of which **work out of the box**"); nitro-deployment-presets.mdx:9-11 (Cloudflare Pages is the only preset carved out); ~/dev/sentry-docs/docs/platforms/javascript/guides/nuxt/index.mdx:68 (`node --import ./.output/server/sentry.server.config.mjs .output/server/index.mjs` as the documented start command). `grep -rni bun` over guides/nuxt/ and `grep -rni nuxt` over guides/bun/ both return 0.

What ran: Nuxt 4.5.2 (Nitro 2.13.4, h3 v1) + @sentry/nuxt 10.67.0 (develop, worktree 6f2da7483d) on bun 1.4.0 (nitro `bun` preset, Bun.serve). Cell record.
