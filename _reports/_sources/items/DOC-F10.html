Proposed issue new-page

Add a Next.js on Bun page for bun --bun with @sentry/bun integrations

Description

No page describes Next.js on Bun. docs/platforms/javascript/guides/nextjs/index.mdx:4 is sdk: sentry.javascript.nextjs, nextjs/index.mdx:53 names only Client, Server and Edge, and the documented register() at nextjs/index.mdx:144-147 branches only on NEXT_RUNTIME === "nodejs" and "edge". The Bun guide never mentions Next.js.

Verified on Next.js 15.5.4 (app router) with @sentry/nextjs 10.67.0 on Bun 1.4.0: withSentryConfig imported from the @sentry/nextjs/config subpath in next.config.mjs, the standard instrumentation.ts with the nodejs branch and captureRequestError re-exported as onRequestError, then bun --bun next build and bun --bun next start. Install @sentry/bun alongside @sentry/nextjs and add fetchIntegration() and bunHttpServerIntegration({ spans: false }) from it to integrations in sentry.server.config.ts.

Works today:

  • Unhandled route-handler errors
  • Route names GET /api/users/[id] with source route
  • Per-request isolation across concurrent requests
  • Incoming sentry-trace/baggage continuation
  • Outgoing fetch spans and propagation headers, with fetchIntegration() added
  • Sentry.logger log envelopes

Known limits:

  • Database spans are not recorded on Bun in this setup.
  • Do not name the project root, or any ancestor of your app/ directory, app: an extra app path segment degrades transaction and span names to source url.
  • Edge-runtime routes, middleware and server actions were not exercised.

What to change:

  • New page docs/platforms/javascript/guides/bun/frameworks/nextjs.mdx with the install, the @sentry/nextjs/config import, the two @sentry/bun integrations, the bun --bun build and start commands, and which instrumentation.ts branch runs under bun --bun.
  • Add the project-directory naming note under docs/platforms/javascript/guides/nextjs/; it applies to Node too.

A page must say Next.js 15.5.4 (app router) builds and serves under `bun --bun next build` / `bun --bun next start` and that `@sentry/nextjs` initializes there, then name the three things the Node path does not need. (1) Install `@sentry/bun` alongside `@sentry/nextjs` and add `fetchIntegration()` and `bunHttpServerIntegration({ spans: false })` from it to `integrations` in `sentry.server.config.ts`; without them outgoing `fetch` produces no `http.client` span and no `sentry-trace`/`baggage` headers, because the Node SDK's HTTP instrumentation relies on undici diagnostics channels Bun never publishes. (2) After `Sentry.init()`, keep a strong reference to the tracing channels (`mysql2:query`, `mysql2:execute`, `mysql2:connect`, `mysql2:pool:connect`, `ioredis:command`, `ioredis:connect`) on `globalThis` — Bun collects channels that only Sentry's subscriber references, so the subscriptions made at init are gone a tick later and no db span is recorded. (3) State which `instrumentation.ts` branch runs under `bun --bun`, since the documented `register()` at :144-147 covers only `nodejs` and `edge`. A separate troubleshooting note applies to Node and Bun equally: do not name the project root, or any ancestor of your `app/` directory, `app` — Next.js derives the route on its OpenTelemetry spans by splitting the route file's absolute path on the first `/app/` segment, so an extra `app` segment degrades transaction names, span segment names and `event.transaction` to `transaction_info.source: "url"`; with the root renamed (e.g. `nextapp`) they read `GET /api/users/[id]` with `source: "route"`.
